# Адаптивное восстановление ECC-защищённой памяти

**Тема:** «Разработка методов адаптивного управления системами коррекции ошибок в цифровой памяти вычислительных систем». Специальность 2.3.2.

**Основная архитектура диссертации — путь A.** [Окончательное решение DEC-004](docs/decisions/DEC-004-dissertation-architecture-A.md), 2026-09-11, сохраняет объект ECC-памяти и собственные методы управления риском. Поиск нового объекта прекращён. FPGA с переключением вычислительных копий при постоянном SEM — сохранённая альтернатива смены предмета, не следующий этап. Практическая ветвь RES-004 остановлена.

Научная задача — установить, какая информация позволяет выбирать периоды последовательного восстановления с достаточным ограничением риска на всём заданном горизонте и когда усложнение управления меняет допустимое решение. Большая экономия полосы не обязательна. Прикладной выход — наименее сложный из рассматриваемых классов управления, для которого получен достаточный сертификат выполнения требований, с ответами **достаточно / недостаточно / не установлено** и конкретным недостающим входом в последнем случае.

**[Согласованная концепция работы](docs/dissertation_concept.md), 2026-09-15:**
когда адаптация необходима или полезна, когда достаточно Fixed/simple и когда
при данных ECC/организации требуется пересмотр архитектуры. Два направления
усиления — области применимости по физическим, информационным и ресурсным осям
и требования к данным радиационных испытаний. Реальное инженерное следствие
при учёте полной цены подсистемы обязательно. [Рабочая структура — четыре главы](thesis/README.md).

## Один текущий научный вопрос

**Как на доступных данных CY62167 и явно заданных W/ECC получить корректные границы риска, отделить неуправляемые события от накопления и определить, какое недостающее сведение действительно меняет решение?**

Порядок: **физический мост → отдельный SR → формальная методика выбора → аппаратное подтверждение**. Первая статья RES-003 пишется параллельно. [Backlog и условия завершения](docs/research_backlog.md). По [Issue №15](https://github.com/z3tm4n-x/phd-adaptive-memory-ecc/issues/15) локальный proof/executor этап закрыт после SR-03 для детерминированных окон. Затем отдельный Reviewer завершил [coverage-threshold SR-01 d29b95f2](https://github.com/z3tm4n-x/phd-adaptive-memory-ecc/blob/d29b95f2b913055cc54cd657b8f3f3d6195a02fc/docs/scientific_reviews/CY62167_COVERAGE_THRESHOLD_REVIEW_01.md) на exact target [a9d9b74b](https://github.com/z3tm4n-x/phd-adaptive-memory-ecc/blob/a9d9b74b9ac03a4eb20b209eb14552d5b914e21a/experiments/RE-CY62167-COVERAGE-THRESHOLD-01/HANDOFF.md): **PASS_WITH_MINOR**. [Disposition Orchestrator](docs/research_gates/CY62167-COVERAGE-THRESHOLD-SR-DISPOSITION-01.md) ограниченно принимает frozen-input DREG и достаточную огибающую `U(Delta)=min(1,a_upper+b_upper*Delta)` в объявленной registered data-only модели. При `epsilon_analysis=0.001` и нулевом coverage upper exact предел `Delta_star` составляет приблизительно 273.0047101324 ns; при условном `Delta=100 ns` допустимо не более `0.00043737385094840922` на отдельно доказанное нарушение физического переноса. Это требование, не измерение coverage. Полный raw-input rerun, full-device coverage, фактический WCET, clean-start и конкретная физическая Fixed остаются NOT_ESTABLISHED. Новый RES и общий PASS не присвоены; Issue открыт. [Входной аудит timing/start](experiments/RE-CY62167-EXECUTOR-TIMING-GATE-01/REPORT.md) получен в exact RE commit 003c2346c4135b3d2f24dac0981e60cb2f179384: **Stage 0 BLOCKED_INPUT / NOT_ESTABLISHED; Stage 1 не начат**. [Disposition Orchestrator](docs/research_gates/CY62167-EXECUTOR-TIMING-STAGE0-DISPOSITION-01.md) принимает аудит и определяет следующий проектный вход: один конкретный контракт подсистемы и её начала. Полная задержка, clean/no-pending start и сравнение с порогом не установлены; недостаточность исполнителя не доказана.

Fixed/Adaptive исследование выполнено: [ограниченное cold-start принятие a88d6a26](https://github.com/z3tm4n-x/phd-adaptive-memory-ecc/blob/a88d6a26c54c193e3d518fb16f43ffd19511202b/experiments/RE-FIXED-ADAPTIVE-FEASIBILITY-01/SCIENTIFIC_REVIEW_DISPOSITION.md). Общий SR поставки остаётся REVISE. Выбранный результат показывает условную область достаточности простого внешнего управления; необходимость RES-003/004 в ней не установлена.

## Границы и практический задел

E_cap не тождествен DUE/SDC или отказу системы. Непрохождение достаточного сертификата не доказывает невозможности защиты. Поглощающий direct-член CY62167 — верхняя оценка; положительный физический floor для любой политики ещё требует основания. Идеальный потенциал не равен причинному или системному выигрышу.

[chapter4-risk-limited-scrubber, cf7ab706](https://github.com/z3tm4n-x/chapter4-risk-limited-scrubber/tree/cf7ab706224f7872fdafcf34febda70e3f6c8dd1): аналитическая постановка главы 3, SEC-DED(39,32), conditional-write исполнитель, scheduler, simple и прежние проверки главы 4. Они используются в собственных областях. RTL подтверждает исполнение и затраты; самостоятельное положение требует отдельного архитектурного результата.

[Первая статья RES-003](docs/publication_plans/RES-003-PUBLICATION-HANDOFF.md) сохраняет состав. Четыре RES не означают четыре готовые статьи. Историческая независимость held-out RES-004 не установлена; подтверждающая выборка — отдельная будущая публикационная проверка.
