## 1. Какое решение требуется

Методика выбирает правило для **одного объявленного объекта и требования**.
Её результат — конкретное достаточное правило с областью гарантии,
условиями исполнения и установленным статусом цены либо точная причина,
почему такой выбор пока невозможен. Доказанную недопустимость правила
или класса она отличает от недостаточности имеющейся оценки.

Для готовых точек результат следующий. В c01 сохраняется допустимое
оконное M(26,208); преимущество полной цены перед всем допустимым
постоянным классом остаётся условным. В c03 и c00 выбираются уже проверенные
постоянные исполнения F(21) и F(3): выбранные N0, N+ и M совпадают с ними.
Это выбор достаточных правил расчётной модели, а не оптимизация всего
класса и не подтверждение их аппаратного исполнения. Конкретные условия
смены этих статусов приведены в §§5–6.

Проверка готового правила и разрешение его будущих действий — разные
задачи. В первой проверяется вся заранее заданная политика, включая
нештатные ветви. Во второй проверяется допустимость каждого следующего
выбора при сохранении общего бюджета и резервного продолжения. Методика
может использовать оба принятых результата, но не подменяет один другим.

## 2. От системного требования к допустимой вероятности памяти

Пусть для класса данных j событие

\[
 A_j=\{\exists t\in[0,T],\ w\in W_j:
              \operatorname{wt}E_w(t)>t_{\rm ECC}\},
 \qquad Q_j(T)=\Pr(A_j)                                      \tag{1}
\]

означает первое превышение способности кода за срок. Для рассматриваемого
(39,32) имеем t_ECC=1. Слова W_j, правильное содержимое и начало срока
должны быть определены; позднее исправление, погашение инверсий или
перезапись не отменяют уже наступившее A_j.

Дополнительно различаем S_j — потребление неверных данных без своевременного
сигнала; D_j — обнаруженную ошибку с восстановлением; F_sys — нарушение
заданной функции или срока реакции системы. Эти события не тождественны:
превышение способности кода может быть обнаружено и восстановлено до
использования данных; обычная исправленная одиночная ошибка может дать D_j
без A_j. Ошибка декодера, незащищённого пути или управления способна дать
SDC либо отказ без A_j. Даже успешное восстановление не исключает отказа
по времени. Поэтому ни Q=Pr(SDC), ни Q=Pr(F_sys) не принимаются по названию кода.

**Шаг назначения ε.** Владелец требования задаёт событие F_sys, горизонт T
и предел η_sys. Для принятой архитектуры требуется обосновать покрытие

\[
 F_{\rm sys}\subseteq B_{\rm sys}\cup\bigcup_j A_j,
 \qquad \Pr(B_{\rm sys})\le b_{\rm sys}.                      \tag{2}
\]

B_sys включает все не покрытые событиями A_j причины: например, сбой
управления, неверную адресацию, незащищённые пути и нарушение сроков
восстановления. Оно не объявляется пустым без основания. Тогда назначение

\[
 \varepsilon_j\ge0,\qquad
 b_{\rm sys}+\sum_j\varepsilon_j\le\eta_{\rm sys},\qquad
 Q_j(T)\le\varepsilon_j                                     \tag{3}
\]

достаточно для системного требования. Независимость причин не нужна.
При отдельном требовании η_SDC необходимо также обосновать
\(\bigcup_j S_j\subseteq B_{\rm SDC}\cup\bigcup_j A_j\) и обеспечить
\(b_{\rm SDC}+\sum_j\varepsilon_j\le\eta_{\rm SDC}\).
Это консервативные достаточные связи, а не необходимое распределение бюджета.
Более слабое требование к Q допустимо лишь при отдельно доказанном переходе
от превышения к последствиям; вероятность такого перехода здесь не выдумывается.

Классы данных задают последствия, срок жизни, доступное восстановление
и его дедлайн: исполняемый код/таблицы/состояние управления, долгоживущие
данные и заменяемый буфер нельзя автоматически считать равноценными.
Однако одно название класса не определяет ε. После архитектурного
распределения, например, заданные заранее веса w_j≥0 с суммой ≤1 дают
\(\varepsilon_j=w_j(\eta_{\rm sys}-b_{\rm sys})\), если остаток неотрицателен.
Веса выбирают по требованию и последствиям до сравнения режимов; это не
подбор допуска ради экономии. Если остаток отрицателен, непригодно именно
это распределение; оно не доказывает невозможности системы.

Разбиение данных должно соответствовать физическим кодовым словам.
Для смешанного слова нужны совместное назначение бюджета и более строгое
из относящихся к нему ограничений, а не независимые допуски его битам.
Бюджет не возобновляется в каждом окне, после записи или восстановления.
Общие исполнительные исключения, уже включённые в Q_j, повторно внутрь
того же сертификата не добавляются. При суммировании разных Q_j повторный
учёт общей причины консервативен; чтобы оплатить её один раз, нужно явное
совместное покрытие с общим плохим событием и оценками на его дополнении.
Статистический уровень доверия к параметрам среды также не равен ε:
нужна либо условная на подтверждённые параметры гарантия, либо обоснованный
учёт вероятности их ошибочного принятия.

Так конкретизируется принятый шаг [главы 2, §2.5](../thesis/ch2/chapter2.md).
Для c01/c03/c00 ε=10⁻³ уже назначено как исследовательское требование.
Системные η, покрытие (2) и доли по данным для реального изделия в этих
входах не заданы. Поэтому ε сохраняется; его системное происхождение
для конкретного изделия остаётся незакрытым входом, не новым расчётом.

## 3. Вход и последовательность выбора

### 3.1. Один договор сравнения

Вход содержит объект (полное слово, упаковку, объём, T, начальное состояние,
полезные записи/чтения), назначенное ε, закон среды либо класс Θ, сведения
контроллера, сервис и допустимые исполнения e∈E, ресурсные ограничения,
объявленное семейство кандидатов Π и класс соперника F. Для каждого
кандидата зафиксированы запуск, конец срока, invalid, loss/restore,
запоздалое решение, pending и продолжение после первого превышения.

Известный закон θ₀ и принадлежность классу различаются кванторами:

\[
 Q_{\theta_0,e}^{\pi}(T)\le\varepsilon
 \quad\hbox{либо}\quad
 \sup_{\theta\in\Theta,\ e\in\mathcal E}Q_{\theta,e}^{\pi}(T)
       \le\varepsilon.                                    \tag{4}
\]

В первом случае также явно задаётся, известен ли закон исполнения или
гарантия требуется для всех e. Во втором **одно** причинное правило
работает при всех θ,e; ему нельзя после выбора скрытой среды назначить
другие действия. Известная функция p, известный закон r и наблюдение
истинного r — разные сведения. Собственные наблюдения должны быть
порождены собственными действиями и скрытым остатком данного правила.
Скрытый остаток и скрытый признак выживания контроллеру не выдаются.
Сопернику предоставляются те же исходные сведения в рамках определения F.

До цены объявляются её координаты и смысл. Здесь это ожидаемая занятость
шины и отдельно последовательного обслуживания памяти за весь срок;
CPU, энергия и ёмкость имеют собственные единицы. Для известного закона
можно сравнивать его ожидания, для класса — заранее выбранную равномерную
или наихудшую ожидаемую цену. Менять этот критерий между соперниками нельзя.

### 3.2. Последовательность и остановки

1. **Проверить совместимость.** Нормировка интенсивности, полное слово,
   метки попаданий, начальное состояние, конечная запись, фазы, часы,
   наблюдения и исключения должны входить в область используемого результата.
   Для будущих действий дополнительно проверяются доступность публичного
   бюджета, резервная политика и её начальное условие. Несовместимость
   с теоремой останавливает её применение; она ещё не исключает само правило.
   При недостатке сведения выход называет его и нарушенный переход.
   Формальный договор исполнения можно проверить как условие модели;
   отсутствие подтверждения фактического исполнителя отмечается отдельно.

2. **Проверить Q за T.** Для каждой π использовать применимый достаточный
   верх U_Q(π). Если U_Q≤ε, допустимость в объявленной модели доказана.
   Если имеется строгий нижний свидетель L_Q>ε при допустимых θ,e,
   правило исключается из равномерно допустимых; это не нарушение при
   каждом θ,e. Для известного закона нужен низ именно при этом законе.
   Если ни один вывод не получен, статус — «допустимость не установлена»;
   выход содержит конкретный незакрытый верх/низ или предпосылку.
   U_Q>ε не является нижним нарушением. При конфликте U_Q≤ε<L_Q
   проверку останавливают как несогласованность оснований.

   Для исключения всего класса требуется
   \(\forall\pi\in F\ \exists(\theta,e):Q_{\theta,e}^{\pi}>\varepsilon\)
   в исходной области либо необходимое ресурсное ограничение,
   несовместимое со всем классом. Разные правила могут иметь разных
   допустимых свидетелей. Отсутствие прошедшей точки конечного меню не
   исключает ни непросмотренные периоды, ни другие правила класса.

3. **Проверить исполнение и ресурсы.** Использовать пределы занятости
   в требуемом временном окне, сроки реакции, размеры/защиту состояния,
   очереди, ограниченные приходы и стоимость незавершённой работы.
   Среднее за T не заменяет пик или WCET. Если фактическое исполнение
   не соответствует сервису, использованному в шаге 2, перенос Q на него
   прекращается. Если исполнение нарушает обязательный ресурсный предел,
   исключается эта пара «правило — исполнение», а не все возможные
   реализации правила. Непрохождение достаточного ресурсного верха
   также не заменяет доказанного нарушения.

   В необходимой границе класса из доступного ресурса вычитается
   обязательная **нижняя** работа приложения, а не её достаточный верх.
   В достаточном тесте кандидата, напротив, оплачивается верх всей работы.

   При неизвестном существенном условии сохраняется «допустимо в модели,
   исполнение не подтверждено». Практическое применение разрешается
   только после обеспечения всех предпосылок гарантии и обязательных
   ресурсов. Неизвестный необязательный для гарантии коэффициент цены
   может оставаться неизвестным и после этого: он блокирует сравнение,
   а не уже обеспеченную допустимость.

4. **Сопоставить полную цену.** Обозначим выбранную ожидаемую меру через
   J_x(π), x — одна координата, а F_adm — часть F, допустимую по Q и
   ресурсам в рассматриваемом договоре. Для вывода
   о преимуществе перед классом нужны применимые границы

   \[
   J_x(\pi)\le U_x(\pi)<L_{F,x}\le
                \inf_{f\in F_{\rm adm}}J_x(f).              \tag{5}
   \]

   F_adm должен быть непустым для содержательного сравнения; иначе
   сообщается исключение класса по допустимости/ресурсам. Если границы
   равномерны по θ,e, (5) действует при каждом разрешённом законе;
   границы только на supremum ожидаемой цены дают только сравнение
   такого supremum. Сравнение двух верхов само по себе (5) не даёт.

   Если π само входит в F_adm, строгий тест (5) против **всего** F_adm
   невозможен: класс содержит самого кандидата. Для доказательства
   минимальности достаточно U_x(π)≤L_F,x; тогда эти границы и J_x(π)
   совпадают. Сравнение только с остальными кандидатами требует явно
   другого множества соперников. Совпадение выбранных исполнений не
   даёт ни одного из этих доказательств.

   Полный счёт включает чтения, исправления, приложение, инициализацию,
   наблюдения/передачу, управление, фон состояния, старт, хвост и работу
   после первого превышения. Остановка доказательного функционала не
   останавливает этот счёт. Общую часть сокращают лишь при доказанном
   тождестве; иначе используют нижний конец соперника и верх кандидата.
   Неизвестная цена остаётся параметром. Нулевой низ неотрицательной
   цены допустим; нулевой верх неизвестной цены — нет. Проверка (5)
   проводится отдельно по координатам или по заранее обоснованному
   системному критерию, без произвольного сложения секунд, памяти и энергии.

5. **Выдать решение.** Если доказано (5), выбирается π с указанием
   координаты, соперника и области преимущества. Если полная цена
   неизвестна, но допустимость и обязательные ресурсы обеспечены,
   можно выбрать конкретный достаточный режим по заранее объявленному
   приоритету проекта, сохранив статус «сравнение цены не завершено».
   Первый прошедший кандидат или минимум достаточного верха внутри
   меню не называется оптимальным либо минимально сложным.

   Совпадающие на всех разрешённых историях исполнения сводятся к
   одному кандидату; одинаковы должны быть также периферийные ветви
   и учитываемая работа. Одного совпадения названий периодов недостаточно.
   Для одинакового постоянного исполнения естественный представитель —
   его постоянное правило. Нулева разность цены тождественных исполнений,
   а не неизвестная базовая цена контроллера. При нескольких несравнённых
   кандидатах без приоритета возвращается их конкретный перечень и
   недостающий коэффициент/приоритет. При отсутствии достаточного
   кандидата возвращается исключённое множество и точный остаток,
   без автоматического запуска новой сетки или изменения ε.

Это конечная последовательность решений по предъявленному пакету
границ, а не обещание построить сертификат или найти оптимум для любого π.

## 4. Почему эти решения корректны

**Утверждение.** Если покрытия системных событий и все используемые
верхние/нижние границы верны в одном договоре, процедура не объявляет
правило практически допустимым без обеспечения его предпосылок,
не исключает правило только по неудаче достаточной оценки и не
объявляет ценового преимущества только по сравнению верхов.

**Обоснование.** Из (2) и неравенства для объединения событий следует (3).
Применимый верх даёт Q≤U_Q≤ε. Для фиксированного закона это утверждение
при этом законе; для класса одинаковое правило удовлетворяет ему для
всех θ,e. Один допустимый нижний свидетель Q≥L_Q>ε опровергает такой
универсальный квантор. Исключение всех правил требует отдельного
квантора по F. Условия шага 3 обеспечивают именно тот сервис и доступные
сведения, для которых доказан верх, а ресурсные ограничения проверяются
самостоятельно. Наконец, цепочка (5) даёт строгий знак относительно
каждого допустимого соперника. При неизвестном звене процедура сохраняет
условие, а не достраивает его предположением. □

Содержательные основания шага 2 уже приняты. Для фиксированных
периодов/окон используются оценки физического первого превышения,
сохраняющие конечный сервис, фазы и остаток через границы. Теорема 3.1
для полностью заданного правила в A_E использует **совместный** переход
собственного наблюдения и остатка, причинное сопряжение и остановленный
функционал: достаточно проверенного мажоранта и начального условия
δ+sup v≤ε в заявленной области. Для разрешения будущих действий её
вариант в A_reg требует публичного бюджета, оплаченной резервной β и
собственного начального теста; непустота обеспечивается β, а не
обязательным разрешением удлинения периода. Ни один из этих вариантов
не разрешает обнулять остаток или квоты среды на новой границе.

Прямой физический сертификат c01 PR323/326 — отдельное принятое
приложение для заданного M, не буквальное включение в A_E/A_reg и не
разрешение будущей перестройки M. RES-003 и T36 используются только
в собственных доказанных областях; их наблюдатель/малую модель или
атомарный сервис нельзя подставить в эти три точки. Доверительный
уровень, известный закон и равномерная гарантия не отождествляются.

Объединение событий, мажорирующая функция и логика сравнения верх/низ —
известные общие приёмы. Здесь результат для положения 3 — процедура их
согласованного использования с принятыми специальными переходами для
памяти и полной ценой; новым общим вероятностным принципом она не объявляется.
Граница собственного вклада соответствует [#336, §7](t336-method-comparison-20261030.md).

### 5.2. Что именно остаётся в c01

PR320 исключает все постоянные P≥14 с, включая OFF, строгим нижним
свидетелем Q_F>0,00100717187649. Используются прежние p₀, ξ=ξ₊,
нулевой джиттер и произвольные фазы; входной остаток не очищается.
Это исключение части F при **равномерном** требовании, а не исключение
всего F: допустимый F(52) существует. Из P<14 получен использованный
в таблице необходимый низ цены всего F_adm. Свидетель не переносится

исполнителя. Это **недостаток основания цены и переноса на исполнение**,

## 6. Результат для положения 3 и точный следующий вход

Получена процедура, связывающая требование, сведения, доказательства
допустимости и полный состав ресурсов/цены с конкретным исходом.
Для §4.1 она уже показывает: M c01 можно сохранить как достаточный
кандидат с положительным условным запасом цены; в c03/c00 достаточно
выбрать совпавшие постоянные исполнения. Выигрыш адаптации не является
условием применимости методики. Переход от нижней границы всего класса
к достаточному верхнему кандидату полезен именно тем, что отделяет
возможную экономию от ещё неизвестной цены её реализации.

Незакрытые входы имеют разные назначения; их не следует объединять
в общий запрос «нужно больше данных»:

- **Для системного применения:** событие/предел η за T, отображение
  классов данных на слова, покрытие (2), бюджет остальных причин и
  назначение ε. Без них ε=10⁻³ остаётся исследовательским входом.
- **Для переноса каждого выбранного правила на исполнение:** соответствие
  именно его календарю и слабому E, размещение 6 МиБ данных и состояния,
  сохранность часов/управления, границы исключений, задержек и очередей.
  Для M дополнительно существенны loss/restore, hold, поздние команды и
  post-A. Нужны ровно относящиеся к принятому договору свидетельства,
  не новая лётная квалификация. Свободный слот не заменяет этих сведений.
- **Для полного ценового преимущества M c01:** совместимый верх суммы
  PR322 с (7), включая selector и подтверждённый ERR-off либо ограниченный
  тракт ERR. Если он получен, решение по соответствующей координате
  сразу меняется на «преимущество перед всем F доказано». Если верх выше
  предела, остаётся неизвестность; вывод о проигрыше из этого не следует.
- **Для оптимальности или нового ценового предпочтения c03/c00:** границы
  полной цены должны обеспечить нестрогое U_F(k),x≤L_F,x из шага 4 либо
  прямое доказательство минимальности. Конкретный незакрытый переход —
  от наибольшей **достаточной опоры меню** к цене всех допустимых периодов
  и фаз: принятый необходимый порог исключения P≥P₀ равен 7,618701832 с
  для c03 и 0,750551288 с для c00 на часах допустимого свидетеля, тогда как
  достаточные фактические верхи
  выбранных периодов — 4,31598197588816 и 0,61656885412688 с. Эти границы
  не совпадают; необходимые нижние цены в таблице также существенно ниже
  верхов кандидатов. Неизвестная полная цена добавляет отдельный пробел.
  Нужен применимый переход к минимальности, а не ещё один малый верх Q
  для уже выбранного периода. Для нынешнего достаточного выбора этот
  переход не требуется. Данные о более выгодном сопоставимом кандидате
  могут сменить выбор, но его поиск настоящей задачей не назначается.

Рекомендация — передать эту связку на адресную рецензию как основание
положения 3 и §4.1. На контроль 06.11 остаются приёмка формулировки и
перечисленные внешние входы; нового расчёта для трёх данных решений нет.
Следующий содержательный вход для усиления **экономического** результата
— применимая ведомость исполнения c01, если автор отдельно назначит
такую работу. Новые сетки, физическая α, новый контроллер и переоценка
статьи 1 для завершения #358 не требуются.

import json
from pathlib import Path
from fractions import Fraction as F
from decimal import Decimal, localcontext

def read(path):
    return json.loads(Path(path).read_text(encoding="utf-8"))

def decimal(value):
    v = F(value)
    with localcontext() as c:
        c.prec = 32
        return Decimal(v.numerator) / Decimal(v.denominator)

root = "experiments/regime-map-methodology-20261019/predictability-volume-20261028/"
cells = read(root + "map-14/result.json")["cells"]
direct = read("theory/t196-c01-direct-certificate-20261029/result.json")

ledger = read("experiments/t186-c01-control-price-20261029/result.json")
for cid in ("c01", "c03", "c00"):
    cell = cells[cid]
    method = cell["methods"]["M"]
    q = F(direct["Q_upper"] if cid == "c01" else method["Q_upper"])
    print(cid, method["execution"], "Q_upper", decimal(q),
          "risk_margin", decimal(F(1, 1000) - q))
    execution = cell["executions"][method["execution"]]
    cutoff = (strong["fixed_class_cutoff_s"] if cid == "c01" else
              cell["fixed_class_lower_for_price"]["P0_s"])
    print("period upper", decimal(execution["period_high_s"]["upper"]),
          "fixed-class cutoff", decimal(cutoff))
    if cid != "c01":
        print("same execution:", {
            k: cell["methods"][k]["execution"]
            for k in ("N0", "Nplus_box", "M", "F_max")})
        print("Nplus_refined", cell["methods"]["Nplus_refined"])
    price = cell["price_bounds"][method["price"]]["price"]["coordinates"]
    for x in ("bus", "serial"):
        lower = (strong["costs"][x]["fixed_class_new_protection_lower_s"]
                 if cid == "c01" else
                 cell["fixed_class_lower_for_price"]["cost"][x]["lower_s"])
        print(x, "protection U/L", decimal(price[x]["protection_upper_s"]),
              decimal(lower), "known all upper", decimal(price[x]["all_known_upper_s"]))
for x in ("bus", "serial"):
    c = ledger["coordinates"][x]
    gap = F(c["fixed_class_known_lower_s"]) - F(c["accepted_M_known_upper_s"])
    print(x, "full known gap", decimal(gap), "strict budget us/s",
          decimal(c["conservative_strict_budget_us_per_s"]),
          "actual control upper", c["actual_control_upper_s"])
