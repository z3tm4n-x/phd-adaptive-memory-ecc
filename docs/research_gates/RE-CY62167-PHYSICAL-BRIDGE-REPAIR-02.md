## 3. Необходимое доказательство

Взять маршрут SR §§4.2–4.4, сохранив происхождение аргумента; инженерное оформление и проверки принадлежат RE.

1. Задать чистое начало без pending write; фактические заранее заданные проверки каждого слова; начальный, полные и конечный интервалы длиной не более tau. Clean read не пишет. Singleton read фиксирует исправленный образ; его запись заканчивается до следующей проверки слова. Прочих записей, отказов декодера/контроллера и одновременных многобитовых родительских событий в этой подмодели нет. First passage сохраняется после последующей коррекции. Указать порядок операций при совпадении времён либо исключить совпадения.
2. Доказать включение **`E_CW ⊆ P ∪ B`** по интервалу первого превышения, включая конец горизонта с незавершённой записью. Не подменять P отказом ideal-at-read. Если вводится иной исполнитель, его отличие требует явного локального доказательства, не изменения исходных условий молча.
3. При независимых простых NHPP по битам внутри слова с общей детерминированной интенсивностью r(t) вывести
   `Pr(P) ≤ C(32,2)*sum_w sum_{I in partition_w}(integral_I r)^2 ≤ W*C(32,2)*tau*integral_H r²`.
   Первая сумма записывается отдельно для каждого слова при различных фазах. Независимость слов не нужна для union bound. Партиции, зависящие от событий, не получают эту формулу автоматически. Это 32 data bits, не полный внутренний код (32,38).
4. Для детерминированных потенциальных проверок c_wk, измеримых к проверке singleton-индикаторов J_wk и заданных заранее/по прошлому верхних пределов D_wk записать корректное ожидание:
   `Pr(B) ≤ 31*E[sum J_wk*integral_[c_wk,min(c_wk+D_wk,H)] r]`.
   Затем получить детерминированную all-check огибающую при соответствующих детерминированных окнах. Указать использование независимых будущих приращений; реализованная случайная сумма не является безусловной вероятностью, будущая фактическая задержка не становится заранее заданным окном.
5. Основной вариант — явная огибающая `31*integral_H K_D(t)*r(t)dt`, где K_D считает перекрывающиеся окна всех потенциальных записей. Упрощение `31*W*(D/tau)*integral_H r` допускается при доказанном периодическом расписании `c_wk=phi_w+k*tau`, общем D<tau и блоках постоянной r, содержащих целое число периодов; начальные/конечные окна учесть как в SR. Для 300-секундных блоков и tau=1 с нулевая дополнительная граничная поправка может быть обоснована — не требовать её положительности без причины. При произвольной r средняя duty сама по себе недостаточна; при одном max-gap ограничении частота дополнительных проверок не ограничена.
6. Свести результат к `U_CW = min(1, U_P + U_B)` в объявленном зарегистрированном классе. Full-device расширение требует собственного delta_cov. Минимальный datasheet tWC не подставлять вместо максимальной D.

Если в выбранных условиях локальный вывод не удаётся, предъявить точное препятствие/контрпример. Не возвращаться к сильному неверному сопряжению ради меньшего upper.

## 4. Исполняемая проверка

Нужен переход состояния по упорядоченным событиям, а не заранее присвоенные итоговые множества. Состояния physical и ideal-at-read вести по одним toggle; отдельно хранить latch, исходный singleton pending write, момент commit, P, B и sticky first passage.

Обязательная отрицательная регрессия — SR §4.1:

| Время | Событие |
|---|---|
| 0.5 | toggle b |
| 1.0 | singleton read; latch clean; ideal reset |
| 1.1 | toggle b в RMW |
| 1.2 | commit latched clean |
| 1.3 | toggle b |
| 1.4 | toggle c |

Требуемый исход: `physical_failure=true`, `ideal_failure=false`, `B=false`, `P=true`. Исправление не должно заставлять эту трассу удовлетворять старому включению.

Сохранить проверки clean/no-write и ошибки после него, distinct-hit внутри RMW, same-bit cancellation, незавершённой записи на H, начального/конечного интервалов и сохранения first passage после writeback. Проверить новый инвариант ограниченным перебором коротких потоков; масштаб 4096 трасс SR достаточен как ориентир, расширение без конкретного риска не требуется. Перебор дополняет доказательство, а не заменяет его.

Сохранить входные трассы, полный журнал контрпримера и компактные результаты перебора. Указать разделяемые реализации с SR и собственный независимый контроль; не называть копирование checker новым независимым подтверждением. Проверка должна различать неверное старое и исправленное включения.
