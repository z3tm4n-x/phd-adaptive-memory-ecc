## Принятый результат и область

`E_CW ⊆ P ∪ B`: физическое первое превышение покрывается событием двух различных меток поступлений в одном межпроверочном интервале либо попаданием в отличный от обнаруженного singleton разряд во время незавершённой исправляющей записи. P не является точным отказом идеального исполнителя.

Область: registered data-only SEC, чистое начало без pending write, заранее заданные детерминированные проверки каждого слова; чистое чтение не вызывает запись, singleton вызывает запись защёлкнутого исправленного образа до следующей проверки. Атомарные однобитовые инверсии; нет конкурирующих записей и ошибок декодера/контроллера. Начальный и конечный интервалы учтены; позднее исправление не отменяет first passage. Совпадения arrival/check/commit исключены в трассовом контракте и имеют нулевую вероятность для указанной непрерывной NHPP модели с фиксированными моментами.

При независимых простых побитовых NHPP внутри слова с общей детерминированной интенсивностью r(t), длине всех интервалов не более tau и детерминированных верхних окнах исправляющей записи принимается достаточная оценка

`U_CW = min(1, W*C(32,2)*tau*integral_H r(t)^2 dt + 31*integral_H K_D(t)*r(t) dt)`.

Здесь W — число слов в этой подмодели, K_D — число перекрывающихся потенциальных окон записи от всех заранее заданных проверок. Фазы учитываются по словам; межсловная независимость для объединяющей оценки не нужна. Формула не охватывает полный внутренний код (32,38), прямые многобитовые родители или зависящие от наблюдения разбиения времени. Duty-упрощение допускается только при дополнительных условиях §5 SR: периодические проверки, фиксированные фазы, общий детерминированный D<tau и горизонт из полных согласованных блоков постоянной r, длины которых кратны tau. Для произвольной r или частичного последнего блока требуется исходный интеграл или отдельная обоснованная огибающая.

## MINOR-01: действующая корректировка области

Известная по прошлому задержка может быть случайной. Для таких окон действует запись SR §4:

`Pr(B) <= 31*E[sum_wk J_wk*integral_[c_wk,min(c_wk+D_wk,H)] r(t)dt] <= 31*E[integral_H K_D(t)*r(t)dt]`.

Ожидание снимается только для детерминированных окон либо заменяется интегралом по доказанной детерминированной потраекторной огибающей Kbar >= K_D. Реализовавшееся случайное K_D не является безусловным верхним сертификатом. Будущее фактическое время завершения не подменяет заранее известную верхнюю задержку.

Эта формулировка определяет принятие и заменяет расширенное прочтение строки без ожидания в REPORT §4.2, CONTRACT и B-EXPECTATION исходной поставки. Исторические RE-файлы сохранены без переписывания; их неоднозначная формулировка не принимается. MINOR учтён в действующей области принятия. Новое общее доказательство для случайных задержек, расчётный repair и ещё один общий SR для закрытия детерминированного случая не требуются.

## Проверки, авторство и сохранность

Постоянный RE выполнил пакет в отдельной сессии. Отдельный Scientific Reviewer воспроизвёл 4096 потоков / 60 нарушений старого включения / 0 нового и сопоставил полные состояния с независимым восстановлением по чётности на 4105 случаях. Старый контрпример остаётся отрицательной регрессией. Это конечная проверка заданного семейства, не универсальная валидация Python API или физические данные.

Опубликованные результаты сопоставлены по правилам экспорта: counterexample JSON совпадает по значениям, но не форматированию. Неудачный frozen run, два test-fix commits, ретроспективная публикация и отсутствие независимой временной аттестации локального pre-execution сохранены. Аналитический enlarged-pair маршрут атрибутирован SR-02; его реализация и вывод в repair — RE; независимая проверка — SR-03. Orchestrator прочитал отчёт и канонический контекст, исследовательские команды не запускал.

## Что остаётся открытым

MAJOR SR-02 закрыт в указанной локальной области. **Issue №15 остаётся открытым; физический мост не завершён.** Численный CY bound=null; реальный WCET, full-device coverage, ненулевая физическая D3 lower и полный actual-CY m0/m1-свидетель не установлены. E_cap не отождествляется с DUE/SDC/отказом системы. Принятые RES-001…004 и прежние ограниченные D3/coverage результаты не расширяются.

Следующий научный вопрос первого приоритета: позволяют ли имеющиеся физические и структурные сведения ограничить ненаблюдаемые пути ошибки настолько, чтобы получить хотя бы одно обоснованное решение о защите в явно ограниченной области? Проверяются границы полноты регистрации/parent identity/parity/post-W исходов и абсолютной нормировки. Восстановление rate-артефакта и квалификация задержки нужны для численной верхней оценки, но сами по себе не квалифицируют физическую полноту.

Конечный выход первого приоритета остаётся заданным DEC-004: проверяемый контракт «данные → модель → границы → решение» и точно ограниченная область «не установлено» с разделяющим недостающим сведением. Полная топология не обязательна. При невозможности получить содержательную область на доступных данных фиксируется критерий пересмотра A, а не запускается очередное усложнение контроллера.

После этого — адресный SR новых существенных выводов, формализация методики выбора и аппаратное подтверждение. Первая статья RES-003 продолжается параллельно. Настоящее решение закрывает локальный этап и актуализирует состояние; новую техническую задачу, регенерацию, литературный цикл или аппаратный эксперимент не запускает.
