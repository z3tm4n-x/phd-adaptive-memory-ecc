# CY62167: один опорный исполнитель и продолжение timing/start

2026-09-15. **Проектное решение Orchestrator и явное дополнение к заданию RE.**
База: `ca8643c26ef773d6f29ba10bb0c9fc3b8c6c0450` (main, PR #27).
Статус: **DESIGN SELECTED / RE CONTINUATION PREPARED; исполнение не подтверждено.**

Выбран **AC701 Rev. 2.0 + три CY62167GE30-45ZXI на одном параллельном интерфейсе**,
внешний SEC-DED(39,32), 2 MiB полезной памяти. Задача продолжения — получить
проверяемое условие осуществимости этого проекта, включая подготовку и реальную
хронологию обслуживания. Готовое доказательство WCET от пользователя не требуется.

Это проект расширения AC701, **не уже существующая SRAM-плата, не заказ её
изготовления и не выбранное лётное изделие**. AC701 задаёт документированные
FPGA, тактирование и выводы; SRAM-модуль задаётся соединениями ниже. Квалификация
реальной разводки, источника часов и physical transfer остаётся отдельной от
проверки проекта. Нового RES, Scientific PASS или принятия физической Fixed нет.

## 1. Зачем и что изменено

[Stage 0, RE 003c2346](../../experiments/RE-CY62167-EXECUTOR-TIMING-GATE-01/REPORT.md)
и [его disposition](CY62167-EXECUTOR-TIMING-STAGE0-DISPOSITION-01.md) сохраняются:
входной аудит принят, прежний Stage 1 не выполнен, недостаточность исполнителя
не доказана. Настоящий документ разрешает **конструктивное продолжение**,
а не повтор аудита тех же 27 источников.

Разрешено локально дополнить постановку: последовательное начало по словам,
конечное окно считывания, допуск часов и запись по ERR встроенной ECC.
Запрет исходного handoff на реализацию при неизвестном готовом WCET заменяется
для этого продолжения разработкой и проверкой явно условного проекта. Неизвестные
физические величины нельзя превращать в подтверждённые параметры.

**Крупное утверждение:** положения 1 и 4 должны связать достаточные сведения
о памяти с выполнимым режимом восстановления. Этот этап — поддерживающая проверка
одного примера, не самостоятельное положение. Инженерное решение: имеет ли смысл
строить joint physical-transfer contract для выбранной организации, и какие
конкретные ограничения времени/начала он должен поддерживать.

Прикладной профиль проекта — неизменяемый в течение защищаемой эпохи образ
программы/таблиц/параметров с продолжающимися чтениями. Это **назначенный профиль
использования**, не измеренная нагрузка конкретного заказчика. Пользовательские
записи в эту эпоху запрещены; произвольная рабочая RAM данным примером не покрыта.
Цена трёх SRAM, лишней ёмкости, внешней ECC, чтений, резервирования шины и старта
учитывается полностью. Процент экономии и миссионное назначение не приписываются.

## 3. Физическая организация проекта

**SOURCE:** SRAM имеет x16-режим, встроенное исправление и ERR; автоматической
исправляющей записи после чтения нет (datasheet p. 1, note 2). Диапазон SRAM
2.2–3.6 V, industrial −40…+85 °C. AC701 — коммерческая отладочная платформа,
не устройство для радиационной среды; её диапазон платы 0…+45 °C ограничивает
этот проект. Пределы температуры кристалла FPGA проверяются отдельно.

**DESIGN:** питание SRAM от VADJ 2.5 V; I/O LVCMOS25, общий GND, без преобразователей
уровня. Совместимость DC, нагрузки, фронтов и питания проверяется RE во всех
выбранных углах, а не выводится из совпадения номинальных напряжений.

| Сигналы / область | Соединение проекта |
|---|---|
| SRAM M0, M1, M2 | Три одинаковые CY62167GE30-45ZXI, x16; общие A[18:0], CE1#, OE#, WE# |
| Адрес | Для внешнего слова w: A[18:0]=w, A19=0; BYTE=VCC, CE2=VCC, BHE#=BLE#=0 |
| P[15:0] | M0 I/O[15:0] = data[15:0] |
| P[31:16] | M1 I/O[15:0] = data[31:16] |
| P[38:32] | M2 I/O[6:0] = parity позиций 1,2,4,8,16,32,39 соответственно |
| P[47:39] | M2 I/O[15:7], девять padding bits; при записи нули, не дополнительные data bits |
| J30 LA00…LA23 | P[2i] на LAi_P, P[2i+1] на LAi_N, i=0…23; суффикс _CC сохраняется по Table 1-26 |
| J30 LA24…LA33 | j=0…9: A[2j] на LA(24+j)_P; A[2j+1] на _N при j<9; LA33_N = CE1# |
| J30 HA00_CC_P / HA00_CC_N | OE# / WE# |
| J30 HA01_CC_P / HA01_CC_N / HA02_P | ERR M0 / M1 / M2, раздельно, не объединять выходы электрически |

Это однозначное назначение на существующие FMC nets, не свободный выбор RE.
RE разворачивает его через Table 1-26 в FPGA package pins/XDC и Figure 5 datasheet
в номера выводов SRAM, проверяет уникальность, банки, питание и отсутствие конфликтов.
Неиспользованные сигналы FMC оформляются по требованиям платы; power-good/наличие
модуля должны разрешать работу до первого обращения, JTAG/I2C не входят в RAM datapath.

Обратная перестановка P→codeword обязательна: data bits заполняют непроверочные
позиции 1…38 прежнего кодека. **P[38:0] нельзя напрямую подать в старый decoder.**
524288 внешних слов дают 2 MiB данных. Занято 3 MiB внешне адресуемых разрядов
в трёх компонентах общей ёмкостью 6 MiB; верхние половины не выделены приложению.
Их возможное влияние через скрытую внутреннюю ECC не объявляется отсутствующим.

Внешний W задан проектом. Внутреннее W, скрытые parity и соответствие зарегистрированных
ошибок этому трёхкомпонентному слову **не восстановлены**. Совпадение номера SRAM
с испытательной линией не доказывает совместимость ревизии кристалла, режима испытаний,
отклика трёх компонентов и внешнего data-only r. Это остаётся physical bridge.

## 4. Расписание и проектный временной тракт

U51: 200 MHz, SiT9102AI-243N25E200.00000, ±50 ppm по UG952 p. 26. Проект использует
один домен 200 MHz; FSM продвигается по clock-enable через каждые два такта.
Один service tick номинально 10 ns. Не создавать новый домен произвольным logic clock.
50 ppm — не нулевой jitter и не доказательство абсолютного времени каждого фронта.

Пусть P_ticks=100000000, N=524288, w=0…N−1. Начала scrub reservations:
`s(w,k)=epoch_tick + k*P_ticks + floor(w*P_ticks/N)`. Длина каждого слота — **24 ticks**,
одинакова для clean, corrected и ERR. Read latch — всегда tick 8 относительно s.
Следующее слово и период не сдвигаются из-за исхода проверки. При физическом
допуске часов это не буквальное `c_wk=phi_w+k*1 s` в UTC; поправка — §6.

| Tick от s | Назначенное действие, ещё не измеренная длительность |
|---|---|
| 0 | Параллельный read: адрес/CE1#/OE# активны, WE# неактивен, FPGA DQ в high-Z |
| 8 | Одновременно защёлкнуть все 48 DQ и три ERR; поднять OE# |
| 10 | Зарегистрировать результат внешней ECC и неизменяемый образ будущей записи |
| 12 | При выбранной записи включить FPGA DQ на исправленный образ; padding=0 |
| 13 | Опустить WE#, сохраняя адрес/данные/CE и выключенный SRAM output |
| 19 | Поднять WE#; не выдавать completion раньше завершения всех setup/hold условий |
| 21 | Разрешить отключение FPGA DQ после доказанного hold; адрес ещё удерживается |
| 24 | Освободить слот; внутренний completion допустим только после квалифицированного завершения |

Запись выбирается при `outer_corrected OR any(latched_ERR)` и отсутствии
`outer_detected_uncorrectable`. При clean и ERR=0 записи нет. При обнаруженном
неисправимом слове — latched fault, без записи/успешного ответа; поведение после
E_cap не используется для доказательства отсутствия уже состоявшегося события.
ERR может вызвать запись внешне чистого слова: это **явное отличие** от старого
singleton-only исполнителя, а не скрытое применение прежней формулы.

Приложение читает только между reservations, через тот же единственный backend.
Принимается не более одного чтения за 48 ticks и не более одного outstanding;
read transaction резервирует 24 ticks. Арбитр не принимает чтение, если оно
пересечёт следующий scrub slot. Эти чтения не делают write-back, не меняют
период/фазу и не используются для адаптации; ERR/outer fault могут сообщаться отдельно.
Очередь/CDC front-end не задерживает уже начатый scrub. Внутри его слота нет
bus backpressure, retry, DMA или программного обработчика.

Назначенные **проверяемые ограничения проекта**, не SOURCE-факты: односторонний
board+FMC+module flight ≤2 ns, clock-to-package output ≤8 ns, package-input до
latch с setup ≤5 ns. Для любых q базовых 200-MHz периодов назначается огибающая
`5*q/(1+50e-6)-0.5 <= duration_ns <= 5*q/(1-50e-6)+0.5`;
добавочные 0.5 ns — требование к jitter, не характеристика из UG952.
Проверка включает быстрый угол для minimum pulse/hold, медленный
для read/decode, OE high-Z и межкомпонентный skew. Нельзя объявлять эти числа
подтверждёнными до соответствующего evidence. Если хотя бы одно не подтверждено,
выходом остаётся условное требование к реализации, а не фактический WCET платы.

В datasheet p. 10 различать max `tAA/tACE=45 ns`, `tDOE=22 ns`, `tHZOE=18 ns`
и min `tWC=45 ns`, `tPWE=35 ns`, `tSD=25 ns`. Учитываются все строки и notes,
DC/AC load и фронты, а не только эти ориентиры. Тракт не равен сумме minima.
Tick 24 — назначенный срок; в нём ещё надо доказать завершение, а не создать
самоподтверждающий ACK счётчиком. Внешнего ACK у асинхронной SRAM нет.

## 5. Подготовка и начало без фиктивного global clean

До H начинается фиксированная, не зависящая от ошибок последовательная загрузка
из доверенного неизменяемого образа. Образ/хэш фиксирует RE; нулевой образ допустим
для функционального теста, но не как доказательство физической независимости от данных.
Начало подготовки — `epoch_tick-20000000 service ticks`. Одна полная параллельная
запись на w, 24 ticks; адреса 0…N−1, без пользовательских обращений. Используются
write-фазы 12/13/19/21/24 из §4 без read/decode неинициализированной памяти.
Доверенный источник обязан подать очередное слово до его слота; отсутствие данных
не удлиняет скрыто подготовку, а запрещает epoch_valid. Подготовка источника до
этого момента не включается в RAM WCET; её доступность не считается доказанной
одним тестом нулевого образа. Для каждого w фиксируются окно и момент `sigma_w`.
Эпоха начинается в заранее заданном t0 после верхнего срока всех этих операций
и fence; раннее окончание ждёт t0, опоздание не разрешает `epoch_valid`.

`epoch_valid` требует power/clock ready, завершённую загрузку всех адресов,
нулевой pending count и безопасное состояние выводов. Soft reset — запрос
quiesce: запретить новые обращения, завершить принятое, выполнить fence.
Жёсткий reset, потеря питания/часов или неподтверждённый commit аннулируют эпоху;
никакого ACK или сохранённого clean-start свидетельства после них нет.
Вероятность таких нарушений не объявляется нулевой для физического устройства.

**В t0 ранее записанные слова уже имеют ненулевой возраст.** В модель входит
история от `sigma_w` до t0 и дальше; риск первого превышения после t0 включает
возможное небезопасное состояние уже в t0. При необходимости upper может учитывать
также превышения после sigma_w до t0. Не требовать отсутствия всех одиночных ошибок
во всём массиве как единственного способа получить полезное основание.

Фиксированный 24-h H, 288 строк r, DREG, shielding, W32_seq и epsilon_analysis
сохраняются для численного сравнения. Для короткой подготовки **до H** вводится
явный модельный параметр `r_pre_upper`: общая per-data-bit NHPP rate upper
на всём интервале подготовки. Предлагаемый именованный численный случай —
`r_pre_upper=max(r_j)` из frozen среза. Это **добавленная модельная предпосылка**,
не измеренный pre-H поток и не вывод из максимума последующего ряда. RE выводит
зависимость от r_pre_upper / допустимую границу, а физическое основание этого
параметра относится к будущему joint contract. Новый transport/GOES не запускается.

## 6. Ровно одно новое основание, которое требуется получить

Нужен достаточный **исполнительный upper `U_exec`** для явно объявленной модели,
связывающий последовательную подготовку, read aperture, выбранную запись и
расписание с реальными допусками. Это целевой результат RE, **не готовая теорема**
данного документа. Предпочтительный конструктивный путь:

1. Начинать историю каждого слова с его собственной квалифицированной записи;
   учитывать пары, пересекающие t0, включая уже небезопасное начало. Не объявлять
   весь массив чистым после последнего адреса.
2. Вместо выдуманного мгновенного физического snapshot задать консервативную
   read/repair service tube: от самого раннего влияющего момента считывания
   до завершения записи. Если для событий внутри неё нужно отдельное плохое
   событие — дать включение и количественный upper, учесть его ровно один раз.
   Внутренняя ECC и три независимых физических latch не становятся атомарными
   от одновременной команды FPGA.
3. Учесть возможную ERR-triggered запись в каждом заранее зарезервированном
   слоте. Для её исполнения нужен корректный latched образ вне явно названных
   нарушений переноса; ERR не равен числу всех физических ошибок.
4. Вывести экспозицию service tubes и pair bound при допуске часов и на краях
   300-s блоков/всего H. Старое равенство duty=Delta/tau не переносить без
   доказательства; при случайных окнах сохранять expectation или доказанный
   детерминированный upper. RMS jitter не превращать в абсолютную границу.

В чистом идеальном контрольном случае восстановить принятую область
[U(Delta) и exact Delta_star](CY62167-COVERAGE-THRESHOLD-SR-DISPOSITION-01.md).
Но сравнение одного назначенного 240-ns слота с 273 ns **не является прохождением**
нового gate. Если применена новая более грубая оценка, объяснить отношение к старой,
а не требовать искусственного численного совпадения.

Раздельно показать `Delta_pending`, всю длительность tube, цену начальной истории,
поправку часов, `U_exec` и подписанный остаток `0.001-U_exec`.
Будущий физический вывод требует на одном пространстве событий
`E_cap,physical ∩ V^c ⊆ E_exec,model` и `Pr(V) ≤ delta_joint`, совместно с
`U_exec + delta_joint ≤ 0.001`. Это **требование к будущему переносу**, не полученная
оценка coverage. Смешанные пути, скрытая ECC/parity, controller/clock violations,
доверенность подготовки и r_pre нельзя бесплатно выбросить или оплатить дважды.

## 7. Known / assumed / unknown; альтернативы

**Известно:** точные входы предыдущих RE/SR, завершённый входной аудит,
первичная документация выбранных компонентов и прежний кодек.
**Выбрано как проект:** топология, packing, профиль чтений, неизменяемые слоты,
условие записи, подготовка/fence и проверяемые временные ограничения.
**Предполагается в новом численном случае:** указанный r_pre_upper и прежний
registered NHPP/data-only контракт. **Не установлено:** реализованный новый тракт,
реальная разводка и jitter bound, full-device transfer, происхождение миссионного
epsilon, завершённая практическая значимость и полезность адаптации на этой подсистеме.

Отклонены: замена GE на EV/другую память с молчаливым переносом отклика; объявление
45 ns полным WCET; global clean после последовательного прохода; игнорирование
ERR при скрытом отсутствии write-back; немедленная сборка стенда. Сохранение
старого FBG484 без платы не закрывает source-to-pin binding; выбран документированный
