## 1. Один выбранный пробел и проверяемая цель

В RES-003 контроллер знает генератор среды. Выбираем одну неизвестную величину:
среднее время пребывания D, задающее обе интенсивности переключения 1/D.
D постоянно в одной миссии, неизвестно контроллеру, принадлежит [30,3000] с.
Уровни b_L/b_H, начальная смесь (1/2,1/2), канал счётчика, физика памяти и
прочие параметры остаются известными и неизменными.

Проверяемая цель: построить вычислимое продолжение счётчикового метода,
удовлетворяющее F_A^pi(D)<=0.1 для **каждого** D∈[30,3000], и установить,
позволяет ли информация из собственных счётчиков уменьшать консерватизм
управления, вызванный незнанием D. Результат должен быть гарантией при неполном
знании закона среды и измеримым следствием безопасного использования этой
информации; одна sensitivity curve исходного контроллера его не заменяет.

PI уточнение: цель — использование информации о временной структуре среды для
менее консервативных действий при сохранении общего риска, а не точность
восстановления D сама по себе. Узкое множество без управляющего следствия не
является главным успехом; широкое множество, уже улучшающее решение, не
является неудачей идентификации.

Почему D: он задаёт, как долго наблюдённое состояние среды полезно для будущих
решений. В RES-003 различались ресурсные эффекты при трёх D, но одинаковые
стационарные вероятности и средняя интенсивность не устанавливают одинаковый
риск/решение. Это мотивация выбора неизвестного параметра, не уже доказанный
новый эффект. Неизвестные уровни, асимметрия генератора, дрейф D внутри миссии
и несовершенство регистрации counts не добавляются.

## 2. Минимальная задача

Сохранить RES-003: W=524288, n=32, rho=0, равномерные word/bit marks,
условный пуассоновский поток, одиночные toggle, clean start только в 0,
H=3600 с, последовательный R2-U P=0.18874368 с, прежнее U и моменты решений
после проходов, терминальный exposure, счётчик собственных исправлений,
resource stop/survival semantics. b_L=2.8886786e-5, b_H=6.1249308 s^-1.
Контроллеру сообщается диапазон D, но не реализованное D или Z.

Основной epsilon=0.1 — уже сертифицированный режим RES-003.
Строгие 0.001/0.01 остаются исторически неразрешёнными для общего adaptive
класса; новая оптимизация этих шести точек не входит в задачу.

Вероятность для каждого D берётся по объявленному закону режима, инверсий и
собственных наблюдений. Не усреднять D по произвольному prior. Не требовать
безотказности для каждого пути Z. Вся миссия имеет один D: допущение нового
наихудшего D на каждом шаге является дополнительным консерватизмом
(rectangular relaxation), а не исходной физической моделью.

## 3. Центральная трудность, которую нельзя вынести за границу

Нужно связать безопасное сужение неопределённости D с likelihood наблюдений,
зависящей от предыдущих действий. Если используются множества D_i(history),
покрытие истинного D должно действовать на всей адаптивной последовательности,
а не отдельно с одинаковым 95%-интервалом на каждом проходе.

Предпочтительный путь для derivation: likelihood/тестовое исключение D с
одновременным контролем ошибки по временам. Не фиксировать конкретный estimator
до вывода. Допустим другой доказанный механизм, сохраняющий тот же uniform-in-D
risk contract. Подстановка posterior mean/MAP D без защитного аргумента не подходит.

Если выделяется вероятность ошибочного исключения beta, заранее использовать
beta=0.005 как внутреннюю настройку алгоритма (5% от epsilon), не требование
проекта и не настройку по найденной экономии. Она вместе с ошибками численного
сокращения должна войти в общий бюджет, без сброса или повторного выделения beta
при новых наблюдениях. Гарантия обязана быть выведена, а не постулирована как
механическая сумма.

Вспомогательные counts совпадают с физическими только до разрыва сопряжения.
Нельзя приписать auxiliary likelihood безусловное покрытие параметра в реальной
памяти. Требуется единый аргумент, связывающий ошибочное исключение, разрыв
сопряжения, численную ошибку и первое превышение, без потери/двойного учёта массы.

Если D_i пусто или сужение не сертифицировано, объявить исполнимое продолжение,
покрытое исходной гарантией. Автоматическое возвращение полного диапазона с
обнулением уже потраченного риска не допускается.

## 4. Последовательность внутри одного задания

1. До большого поиска доказать/проверить существование общего сертифицированного
   резерва на исходном диапазоне, начиная с прежнего периода 1 с. Если его
   сертификат не проходит, разрешены другие периоды прежнего U или более
   точная проверка достаточности; это не доказательство невозможности.
   Не сужать диапазон post hoc для успеха.
2. Вывести расширенное рабочее состояние, обновление по своему count,
   управление общим риском и обработку ошибочного сужения. Разделить:
   оценивание текущего Z при данном D; получение информации о D; её влияние
   на состояние/будущую экспозицию/выбор действия.
3. Обеспечить непрерывный диапазон D: interval bounds, доказанные аналитические
   свойства либо иная проверяемая аппроксимация с оплаченным остатком.
   Конечная сетка проверки не доказывает гарантию на всём [30,3000].
   Не предполагать заранее достижение worst case только на концах.
4. Реализовать метод на целевом массиве; малая точная модель остаётся
   независимым эталоном. Указать память, offline costs, update/choice time,
   зависимость от представления D и отличие от RES-003.
5. После вывода выполнить одно заранее зафиксированное сравнение. Для
   held-out численного сравнения D={30,100,300,1000,3000} с; внутренние точки
   не заменяют continuous-domain guarantee. 20000 миссий на точку с общими
   внешними streams для парных сравнений и собственными counts каждой политики.
   Seeds/численные настройки фиксируются до оценки итоговой экономии.
   Новая настройка по held-out запрещена.

## 5. Сравнения, отделяющие новый вклад

- **Fixed / двухблочный Precomputed:** те же 12/144 классы, но допустимость
  требуется для всех D диапазона. Иначе baseline получает более сильное знание.
- **Frozen-uncertainty controller:** тот же механизм с тем же диапазоном D
  навсегда. Он продолжает использовать свои counts для скрытого Z/остатка
  внутри каждого допустимого D; выключается только уменьшение неопределённости
  D. Это основной тест нового эффекта, не повтор count-disabled RES-003.
  Формально определить, что фиксируется: admissible D-set и его robust
  requirement; скрытая posterior переоценка D, обходящая запрет, недопустима.
- **Предлагаемый метод:** тот же канал, но доказанно разрешённое уточнение D.
- **Known-D RES-003:** диагностическая опора с дополнительной информацией,
  не равноправный competitor и не доказанная верхняя граница всех методов.
- **PA-DOM:** принятая target adaptation, с одним набором настроек на весь
  неизвестный-D диапазон, выбранным на отдельном пилоте. Не настраивать её
  отдельно на истинный D при сравнении неизвестного параметра. Статистическая
  проверка конечных точек не выдаётся за uniform-in-D гарантию аналога.

Общий первичный constraint uniform-in-D, затраты покомпонентно по истинному D.
Не усреднять ресурс по D без физического распределения.
Основной ресурс прежний E[N|survival]; дополнительно common-survivor пары и
безусловные stop-cost. Отдельно память/вычисления/стоимость модели наблюдения,
без искусственного net-energy показателя или обещания equal-risk dominance.
Сообщить fixed/precomputed baseline, frozen-D-set vs learning effect,
и потери относительно диагностического known-D без смешения этих объектов.

В отчёте и сохранённых трассах связать собственный count, допустимое множество
D до/после обновления, выбранный период, остаток общего риска и ресурсное
следствие. На той же наблюдательной истории можно диагностически сравнить
выбор с полным и уточнённым D-set при одинаковом остальном рабочем состоянии;
это локальное объяснение действия, не подмена основного сравнения политик,
каждая из которых получает собственные counts при собственных действиях.
При отсутствии дополнительной экономии различать подтверждённые причины:
недостаточную различимость D по доступной истории; нечувствительность
реализуемого действия к уже полученной информации; консерватизм сертификата,
аппроксимации или конкретного правила метода. Если причины не разделены
доказательством/диагностикой, оставить их неразрешёнными, не выдавая одну за
установленную. Оптимальное активное планирование наблюдений не добавляется.

## 6. Независимая проверка и завершение

Независимый малый killed physical model проверяет риск/собственные counts без
auxiliary observation helper; новый proof проверяет uniform coverage и общий
бюджет. Для численного continuum-сертификата — независимые bounds или
интервальные witnesses, а не совпадение двух сеток.
Равномерность по времени/D не заменяется Monte Carlo.

Завершённый положительный результат: вычислимый метод с uniform whole-horizon
гарантией и установленным следствием знания D — ресурсным эффектом,
сохранением гарантии при менее сильном знании или доказанной границей
полезности уточнения. Выигрыш во всех режимах не требуется.

Отрицательный: если выбранное сужение не даёт экономии, сообщить это как
результат данного метода. Сильный вывод о бесполезности канала требует
идентифицируемости/различимости или policy-class bound. Если доказана
невозможность безопасно различать необходимые D в данном канале/горизонте,
это завершённый информационный предел, не повод подбирать другие D.

Если guarantee работает только с неизменным множеством, сохранить законченный
robust baseline, но явно указать, что центральная learning-цель не решена.
Выявленный барьер должен привести к конкретному выбору, а не автоматическому
новому sweep. Не исключать ошибочное сужение/реальную count coupling из цели.
