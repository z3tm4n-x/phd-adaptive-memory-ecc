# Требование к определению группировки x16-адресов CY62167 по ERR

Решение автора 12.10.2026; дополнение к требованиям T89 и условному
примеру R0-A. Это протокол будущей адресной проверки, не отчёт об опыте
и не назначение облучений. Принятый METHOD T89 не изменён.

## Проверяемое условие

Задать функцию p(a), сопоставляющую двум разным x16-адресам одно
внутреннее слово 32+6: p(p(a))=a. Проверяется прежде всего используемая
RTL-пара по A0; условные X/Y из AN88889 её не устанавливают.
Известная пара позволяет выбрать по одному представителю 2^19 полных слов.
При неизвестной/несовместимой паре безопасный полный обход требует 2^20
x16-обращений: при прежней сетке число операций и длительность удваиваются.
Действующий сертификат с запасом около 1,695% ε это не покрывает;
верх выше ε не доказывает фактическое нарушение требования. Иная, но известная
функция p может допускать перестановку адресов без удвоения; это нужно проверить.

## Короткий опыт после получения изолированной исправимой ошибки

1. Зафиксировать полный артикул, корпус, партию/date code, режим x16,
   напряжение, температуру и схему регистрации ERR. Записать известный фон
   данных, убедиться в ERR=0; при измерении остановить автоматический scrub
   и записи приложения. ERR измерять только в паспортном окне чтения,
   поскольку при записи/отключении он может быть высокоимпедансным.
2. Использовать одну подтверждённую исправимую ошибку в выбранном образце.
   Способ её получения должен быть отдельно описан и разрешён; обычная запись
   другого значения через штатную шину заново кодирует ECC и не является
   инжекцией ошибки. Наличие доступного тестового режима не предполагается.
   Без ошибки результат опыта — «группировка не определена».
3. Без каких-либо записей считать адрес a с ERR=1, предполагаемый p(a)
   и контрольные адреса, меняющие отдельные адресные биты. Если пара не найдена,
   один проход чтения по всем адресам локализует второй адрес с тем же
   устойчивым ERR. Повторить чтения в обратном порядке: сама выдача
   исправленных данных не должна устранять сохранённую ошибку.
4. Перезаписать исправленное значение только по одному адресу предполагаемой
   пары и повторить чтение обоих. Ожидаемый различающий признак общего слова:
   до записи ERR=1 на обоих, после записи ERR=0 на обоих; данные сохранены,
   контрольные адреса не изменились. Повторить для нескольких адресных областей
   и направлений пары, исключая новые события во время серии.
5. Сохранить таблицу «адрес → ERR до записи → ERR после записи → данные»,
   временные трассы и обнаруженную функцию p. Одна пара не квалифицирует весь
   массив/другую партию; отдельно указать проверенный охват и основание обобщения.
   Неустойчивые или множественные ошибки дают неопределённый результат.

## Основание и граница вывода

[AN88889, §4.4, с.7–8](https://community.infineon.com/gfawx74859/attachments/gfawx74859/NonVolatileRAM/1914/1/Infineon-AN88889_Mitigating_Single-Event_Upsets_Using_Infineon_65-nm_Asynchronous_SRAM-ApplicationNotes-v04_00-EN%201.pdf)
описывает ERR и обновление полного внутреннего слова при доступе к одной
половине; точные номера адресов там условны. Протокол выше — наше предложение
для различения группировок, а не готовый эксперимент производителя.
[Паспорт CY62167G30/GE30, 002-20054 Rev.*F, с.10–12](https://www.infineon.com/assets/row/public/documents/10/49/infineon-cy62167g30-cy62167ge30-16-mbit-1m-words-x-16-bit-2m-words-x-8-bit-static-ram-with-error-correcting-code-ecc-datasheet-en.pdf)
задаёт окна валидности ERR/DQ. Перенос к конкретной партии остаётся условием
применимости; Б может быть завершён без выполнения этого опыта.
