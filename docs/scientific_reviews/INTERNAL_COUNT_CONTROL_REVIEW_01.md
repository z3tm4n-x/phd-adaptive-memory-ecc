## 2. Реальная память и вспомогательный счётчик

**Независимый вывод.** Пусть B — первое повторное попадание в ещё не очищенное слово, независимо от совпадения номера разряда. Свяжем реальные инверсии и вспомогательные поступления одними временами, режимом, словесными/битовыми метками и индивидуальными проверками. До B каждое неочищенное слово содержит ровно одно поступление: его реальная проверка даёт один count, как и вспомогательная. После ранней проверки новое поступление не исчезает в конце прохода. Оно входит в K и будет учтено при следующей проверке этого слова.

Индукция по завершённым проходам даёт одинаковые доступные истории и действия до B. Реальный E_cap не может наступить раньше B. Safe same-bit toggle тоже разрывает сопряжение, но **сам по себе не является E_cap**. Следовательно, это консервативное сопряжение, а не утверждение физического равенства двух счётчиков после повторных попаданий.

В момент решения T_i, определённый собственной прошлой историей, условно на текущий Z=z будущее среды имеет исходный марковский закон: применяется strong Markov property, а не безусловная независимость после смешения Z. Для любых позиций k старых поступлений условное ожидаемое число совпадающих пар ограничено

\[
r_h(z,k)=\{k\,\mathbb E_z B_h+\tfrac12\mathbb E_z B_h^2\}/W,
\qquad B_h=\int_0^h b_{Z(s)}\,ds.
\]

Новые метки слов равномерны и независимы от старых позиций. Проверки внутри действия только удаляют часть потенциальных пар; игнорирование этих удалений безопасно. Поэтому неизвестные позиции не требуют предположения об их равномерном posterior. Частичный последний интервал оплачивается тем же r_h без бесплатного завершающего сброса.

K_old целиком попадает в следующий вспомогательный count. Новые скановые потоки для count и K_new независимы **при заданной траектории Z**, поскольку это непересекающиеся категории пуассоновских меток. После смешения по Z они вообще зависимы друг от друга и от конечного Z. `scan_kernel` и `combine` сохраняют эту совместность; произведения маргинальных смешанных распределений вместо joint law не обнаружено.

Важно для переноса к физической вероятности: на каждом шаге закон ещё связанных состояний — подмера полного вспомогательного закона. Для неотрицательного r_h её интеграл не больше полного. Суммируются вероятности *первого* разрыва, а не условные риски при скрытом survival. Отдельное сопряжение точного и сокращённого каналов оплачивает вероятность их первого расхождения суммой равномерных ошибок строк. Здесь нет недопустимой оценки неограниченной суммы rewards как TV×1.

## 3. Общий бюджет, резерв и исполняемый закон

Для вспомогательного стохастического ядра P_a и его ветвей K_a[y] положим \(\ell_y=qK_a[y]\mathbf1\), \(q_y=qK_a[y]/\ell_y\). При нулевой вероятности ветвь не участвует. Тогда \(\sum_y\ell_yq_y=qP_a\).

Пусть V_R — ожидаемая будущая сумма r при резервном периоде 1 с. Воспроизводится рекурсия

\[
V_0=0,\quad V_R=r_R\ (0<R<1),\quad
V_R=r_1+P_1V_{R-1}\ (R\ge1).
\]

На полном действии \(D_a=q(r_a+P_aV_{R-a})-qV_R\), на последнем неполном — \(D_a=qr_R-qV_R\). При \(s'=s-D_a\) непосредственно получаем

\[
qr_h+\sum_y\ell_y(q_yV_{R-h}+s')=qV_R+s.
\]

Условие \(D_a\le sh/R\) сохраняет \(s'\ge0\); при отрицательном D запас может увеличиваться — это ожидаемое уменьшение будущего потенциала, не создание отрицательного риска. Для резерва D=0, в том числе при R<1 с терминальным r_R. Поэтому резерв не теряется в точной арифметике. Суммирование по дереву и неотрицательный терминальный s дают \(\mathbb E_{aux}\sum_i r_i\le\epsilon-\delta\). Вместе с §2 это даёт заявленный first-passage bound. Большой conditional budget на отдельной редкой истории не противоречит этому доказательству.

`Model.choose` выбирает наибольший admissible период; полный перебор всех 12 действий в независимом выражении D подтвердил этот порядок. `simulate._choose` использует ту же величину через аффинность V по k, а не новую оптимизационную цель. Независимость K_new от K_old при заданном исходном z делает будущий член не зависящим от k. Для проверки аффинности не нужно предполагать независимость K_new и Z_new.

Производственный симулятор не передаёт Z, фактическое число грязных слов или флаг survival контроллеру. Диагностический `active_n` только экспортируется. Каждая `_run` инициализирует собственные q, slack, count и расписание; общий marked stream служит common random numbers, не общим наблюдением. В count-disabled ветви используется qP_a; значение count не читается при выборе матрицы обновления. Резерв, бюджет, U и гибкость правила сохранены.

## 4. Сокращение модели: направление и величина ошибки

1. **C=32** — точная агрегация наблюдения `min(C,32)`, а не отброшенная масса. **K=12** — приближение, и оплачивается строго K>12. Доминирующая средняя Pois — b_H P/2; истинная дискретная средняя под all-H равна b_H P(W−1)/(2W), не больше используемой.
2. Число переключений за P имеет Pois(P/D), поскольку обе интенсивности выхода равны 1/D. Полная масса N_sw≥3 заменена объявленным переходом и включена в ошибку; не только чётность конечного режима.
3. Для ступенчатой доли уже проверенных слов и сдвинутой линейной аппроксимации разность первообразных ограничена 1/(8W²). Интегрирование по частям на участках Z и сумма ошибок двух средних дают \(P[b_H+(P/D)(b_H-b_L)]/(4W^2)\). Это сохраняет последовательный скан; не synchronous reset.
4. Для one-switch пути L1-норма второй производной распределения ограничена 4v+4v². Для transformed two-switch пути плотность 2(1−u) даёт по координатам допустимые границы 24v+32v² и 8v+8v²: их сумма не больше использованных 40v+40v². Они следуют из \(\|\partial_\lambda Pois\|_1\le2\), \(\|\partial^2_\lambda Pois\|_1\le4\), chain/product rule. Поэтому midpoint bounds /24M² обоснованы; согласие двух сеток не использовалось как доказательство.
5. Адаптивность не уничтожает равномерность этих оценок строк. Сумма по не более 18000 завершённым проходам сохраняет безопасное направление. Для незавершённого интервала нет нового наблюдательного ядра; риск остаётся.

Пересчитанные полные delta, включая неизменённый numeric reserve 0.0002: **0.0012116857023731545; 0.00021960410931119292; 0.00020182452145284992**. Начальные резервные bounds: **0.0756233391665013; 0.07645559141483578; 0.07654033800824164**. Все три initial slack при epsilon=0.1 положительны. Это не MC confidence intervals.

## 5. Binary64: что именно допускается утверждать

Условный контракт — binary64, обычное округление базовых операций, exp/expm1 не хуже 4 ulp, сохранённый порядок/тип вычислений и проверенные таблицы. **Review не устанавливает этот контракт измерениями для произвольной библиотеки, компилятора или аппаратуры.** При переносе нужны проверка контракта и контроль построенных таблиц; одной декларации «binary64» недостаточно.

Положительные униформизация/квадратура/свёртки допускают суммирование абсолютных строковых ошибок. F≤2048, 32 положительных члена при mu≤1 и не более 11 squarings соответствуют фактическому коду. Хвосты не получаются вычитанием 1−CDF. Потеря very-small series terms ограничена отдельно; clipping малой отрицательной величины после cancellation не считается доказательством точности.

Для `moments` нельзя использовать относительную ошибку относительно малого low-mode результата после вычитания. Проверяется **абсолютная** ошибка относительно верхних шкал b_H h и b_H²h². В ветви x<0.2 ряд B имеет контролируемый остаток; в другой ветви h−A не находится в режиме x→0. Учет формирования m,d,A,B, двух вычитаний и reward допускает заведомо избыточный локальный абсолютный budget gamma_256 на соответствующей положительной верхней шкале. Это не вывод из найденной тестовой невязки.

Чтобы сделать влияние аффинного сжатия явным, для review использована более свободная оценка, чем компактная строка инженера:

\[
\eta_V^{SR}=25\,\gamma_{256N_b}V_{max},\quad
N_b=3600,\quad V_{max}=0.6336514783227385.
\]

Здесь gamma_j=ju/(1−ju), u=2^−53. Локальные положительные matrix-vector операции, абсолютные ошибки moments/reward и нормирования входят в gamma_256; наращивание по всей резервной рекурсии — в gamma_(256 N_b). Восстановление c+k a из значений при k=0,1 имеет сумму модулей коэффициентов |1−k|+k≤23 при k≤12; множитель 25 оставляет также запас на финальное вычитание/умножение. Нельзя просто считать вычитание соседних V безошибочным.

Получается \(\eta_V^{SR}=1.620851237898976\cdot10^{-9}\), а вклад 2Nmax eta_V^SR равен **0.0000583506445643631**, вместо инженерного 0.0000167028720048416. С остальными заявленными компонентами арифметическая верхняя оценка становится **0.000143018263177913 < 0.0002**. Поэтому принятие резерва не требует принятия более тесного tally 0.000101370490618391 как единственной возможной оценки.

Нормированный фильтр требует отдельного аргумента для редких наблюдений. Положительный оператор не расширяет отношение максимального/минимального компонентного искажения; скалярная нормировка это отношение не меняет. Отсюда применим projective budget, а не равномерная абсолютная posterior-error оценка вида error/ell_min. Конечные хранимые строки дополнительно проверены точным суммированием их binary64 значений в Decimal: максимальные отклонения полной массы от 1 составляют **3.539e−16, 2.889e−16, 3.726e−16**. Их приведение к стохастическим строкам помещается в guard фильтра и kernel coupling. Это детерминированная проверка всех текущих строк, не замена априорного model/kernel bound случайной невязкой.

Дополнительно проверен весь support: для y<32 строки с k>y нулевые, остальные положительны во всех destination states; для y=32 все строки положительны. Наименьшие положительные элементы для трёх D — 8.049e−62, 8.097e−64, 8.102e−66. Поэтому после достижимого наблюдения все компоненты posterior положительны: общий вес допустимых входных строк сокращается при нормировании, а нижняя оценка остаётся порядка минимального положительного элемента таблицы. Произведения на следующем шаге не уходят в binary64 underflow. Начальное q с k=0 также допускает все категории y. Это усиливает проверку rare-observation аргумента именно для конечного production-пакета; не переносится автоматически на другие caps/rates.

Допуск выбора 1e−13 и `max(0,slack−D)` требуют оплаты накопленного нарушения; оно включено в Nmax·1e−13, а не игнорируется. Rsum ограничивает сумму положительных reward-шкал через сумму длительностей H; Vmax ограничивает потенциалы. При таком учёте cancellation в D и коэффициентах, редкая нормировка и терминальный остаток не обнаруживают превышения выделенного numeric reserve.

**Разделение статусов:** математическая рекурсия доказана в точной арифметике; контролируемая численная версия — условный результат при указанном контракте, не машинно-проверенное или аппаратное доказательство. Reviewer непосредственно исполнил `core.py`, но Numba отсутствовала; функции `simulate.py` проверены по неизменённым Python-телам после удаления только импорта/декораторов Numba в памяти. Независимого JIT-прогона здесь нет. Совпадение этих тел с декларативным правилом и трассами поддерживает алгоритм, но не сертифицирует компилятор.

## 6. Fixed / Precomputed: действительная невозможность и достаточность

Для заранее заданного расписания, условно на путь Z, независимы пуассоновские приращения по непересекающимся парам «слово, интервал». Сумма ожидаемых разных-разрядных пар даёт Q(Z) и верхнюю границу. Ровно два разных разряда в одном интервале достаточно для первого превышения; если оно уже произошло раньше, inclusion тем более сохраняется. Поэтому произведение вероятностей избегания этих событий даёт нижнюю оценку. Применение хорды к 1−exp(−exp(−mu_max)Q) на [0,Qmax] допустимо и даёт формулу (15). Это рассуждение **не переносится на endogenous stopping intervals**.

Независимый пересчёт явно перечислил все W начальных и конечных возрастов, не используя geometric-sum helper: первый возраст a−P+jP/W, последний P−jP/W; внутренние интервалы a или b. Через 1800 с индивидуальные проверки продолжаются, возраст не обнуляется. Перебраны все 156 расписаний на каждый D, всего 468. > Для объявленной модели чисто накопительных равномерных одиночных инверсий в массиве 524288 SEC-слов по 32 информационных разряда, скрытой симметричной двухрежимной CTMC с известными уровнями/генератором, чистым началом и последовательным R2-U восстановлением построено вычислимое управление периодом по собственному счётчику завершённых исправлений. ### A1. Полное перечисление deterministic baselines без production geometric sum

```python
import json, math
from pathlib import Path
import numpy as np
ROOT = Path('/path/to/checkout/experiments/RE-INTERNAL-COUNT-CONTROL-01')
c = json.loads((ROOT/'config.json').read_text())
W=524288; P=np.longdouble('0.18874368'); U=c['periods_seconds']
x=np.arange(1,W+1,dtype=np.longdouble)*P/W
bl=np.longdouble('2.8886786e-5'); bh=np.longdouble('6.1249308')
m=(bl+bh)/2; v=(bh-bl)**2/4; f=np.longdouble(31)/(64*W)
for D in (30,300,3000):
    k=np.longdouble(2)/D
    def M(t): return m*m*t*t+2*v*(k*t+np.expm1(-k*t))/(k*k)
    boundary={a:(np.mean(M(np.longdouble(str(a))-P+x)+M(P-x)),
                 np.mean((np.longdouble(str(a))-P+x)**2+(P-x)**2)) for a in U}
    rows=[]
    for kind in ('Fixed','Precomputed'):
        for a in U:
            for b in ([a] if kind=='Fixed' else U):
                n1=round((3600 if kind=='Fixed' else 1800)/a)
                n2=0 if kind=='Fixed' else round(1800/b)
                aa=np.longdouble(str(a)); bb=np.longdouble(str(b))
                EQ=f*((n1-1)*M(aa)+n2*M(bb)+boundary[a][0])
                QM=f*bh**2*((n1-1)*aa*aa+n2*bb*bb+boundary[a][1])
                lower=-np.expm1(-np.exp(-bh*max(a,b)/W)*QM)*EQ/QM
                rows.append((kind,a,b,n1+n2,float(lower),float(EQ)))
    for kind in ('Fixed','Precomputed'):
        chosen=min((r for r in rows if r[0]==kind and r[5]<=.1),
                   key=lambda r:(r[3],-r[1],-r[2]))
        cheaper=[r for r in rows if r[0]==kind and r[3]<chosen[3]]
        assert all(r[4]>.1 for r in cheaper)
        print(D,chosen,len(cheaper),min(r[4] for r in cheaper))
    assert all(r[4]>.01 for r in rows if r[0]=='Fixed')
```

### A5. Независимые moments и конечные таблицы

Для moment oracle использован блочный 6×6 generator с Q на трёх диагональных блоках, diag(b) в блоке (0,1), 2diag(b) в блоке (1,2). Суммы строк блоков экспоненты (0,1)/(0,2) дают первый/второй моменты.
