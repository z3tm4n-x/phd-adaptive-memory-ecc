## 2. Включение и конечный горизонт

Нужное определение, используемое в этом отзыве:

\[
B_H=\bigcup_{w,b}\{N_{wb}(Q_w)>0\}
\;\cup\;\bigcup_{w,k,b}\{N_{wb}(R_{wk}\cap H)>0\}.
\]

Все подготовительные Q_w лежат до H и оплачиваются полностью. Все scrub-tubes
зарезервированы заранее, независимо от результата чтения, ERR и выбора записи.
Для них оплачивается только та часть, которая лежит в H. В численной оценке
пересечения по-прежнему можно заменить полным верхним D: это увеличение оценки
длины, а не требование к интенсивности вне H. Закрытые концы не меняют вероятность
при принятом простом NHPP с непрерывной интегральной интенсивностью.

Независимая аргументация включения:

1. Вне B_H доверенная полная запись делает слово чистым в его собственной
   sigma_w. Более ранняя история стёрта; попадания во время подготовки оплачены.
   Нельзя перенести эту чистоту на общий t0: между sigma_w и t0 уже возможны ошибки.
2. До первого превышения, на полном сервисном окне без попаданий, coherent latch
   видит неизменившееся слово. Чистое слово остаётся чистым без записи либо после
   ERR-only записи; одиночная ошибка исправляется. Образ после latch неизменяем.
   Условное завершение записи до fence и отсутствие попаданий до fence дают
   следующий чистый endpoint. Это использует явно заявленную transfer-семантику,
   а не выводит её из ERR или из счётчика тактов.
3. Между такими endpoints более одного ошибочного бита требует попаданий как
   минимум в два **различных** бита. Повторные toggle в одном бите могут отменять
   ошибку, но не создают два ошибочных бита. Поэтому событие Pairs необходимо вне
   B_H; это не утверждение монотонности истинного toggle-risk.
4. История первого интервала начинается в sigma_w и не разрывается в t0.
   Уже опасное состояние в t0 покрывается тем же событием пар. Разрешённое
   дополнительное покрытие превышений до t0 консервативно.
5. Последний неполный интервал заканчивается в H_end. Если последнее чтение или
   запись пересекает H_end, все влияния внутри H оплачены через B_H либо пары.
   Для доказательства события в H не требуется ни отсутствие попаданий после H,
   ни чистота на будущем fence. Будущий назначенный fence используется только
   для верхней оценки длины последнего интервала.

Следовательно, при объявленных условиях
`E_exec,H ⊆ Pairs ∪ B_H`. DUE/возможная miscorrection после первого превышения
не используются для ретроспективного доказательства безопасности. Application
reads не изменяют состояние и не сдвигают scrub; их физическая корректность,
как и скрытая ECC/паритет, не получена из этого data-only доказательства.

### MINOR-01 — буквальное B шире области оплаченной интенсивности

**Доказанный дефект формулировки.** PROOF.md, «Histories, service event, and
inclusion», определяет B через полные R_wk, touching H, и предлагает сохранять
complete tubes. Следующая оценка Pr(B) использует только H. Для последнего tube,
выходящего за H_end, это не обоснованная оценка буквально определённого B:
после H интенсивность не задана. Произвольно большая интенсивность там может
увеличить Pr(B), не изменив риск в H и опубликованные интегралы.

**Минимальная правка:** заменить B определением B_H выше; ограничить утверждение
о чистоте последующими fences внутри H и явно описать терминальный неполный
интервал. В разделе service exposure писать интеграл по R_wk∩H, с последующей
оценкой его длины через D. Сохранить полные Q_w и их отдельное pre-H слагаемое.

**Критерий закрытия:** текст включения и оценка вероятности относятся к одному
событию; нигде не нужна интенсивность после H. Доказательство выше уже показывает
достаточность этой локальной правки. Влияние: **формулировка**, не число, не новый
эксперимент. Не требуется добавлять post-H rate или менять CSV/расписание.

## 3. Вывод и независимая численная проверка

Для каждого из 524288 слов использованы именно
`sigma_w=g(-20000000+24(w+1))` и первый fence
`g(floor(w*100000000/524288)+24)`. Их разность в ticks равна
`20000000+floor(wP/N)-24w`. Последовательное перечисление всех адресов подтвердило
строгий рост, максимум **107416921 ticks**, минимальный промежуток стартов 190 ticks
и замыкающий промежуток 191 ticks. Подготовка занимает 12582912 ticks;
оставшийся до t0 запас равен 7417088 ticks. Это не нулевой возраст всех слов.

Clock envelope должен выполняться для **любого интервала** одного фиксированного
допустимого clock trajectory с внешней привязкой к t0. Uniform bound допускает
также conditioning на независимые экзогенные часы. Выбор траектории часов по
радиационным событиям не разрешён доказательством. ±0.5 ns — проектное абсолютное
условие, не измеренное свойство генератора и не RMS jitter.

Пусть D=u(24), L=max(u(P),u(107416921)), T=u(20000000), в секундах,
K=N·496, I2=300·sum(r_j²). Независимость двух per-bit NHPP и Cauchy–Schwarz дают
`Pr(Pairs) ≤ K L (I2+T r_pre²)`. Разные слова независимыми быть не обязаны.
Интервалы, пересекающие t0, сохраняются целыми до применения Cauchy–Schwarz;
общая pre-H верхняя интенсивность лишь увеличивает интеграл.

Для 300-s блока старт пересекающего tube лежит в [a−D,a+300]; старты одного слова
разделены минимум p_minus=l(P). Проверено точное неравенство
`300*p_minus ≤ 300+D < 301*p_minus`, поэтому максимум числа стартов — **301**.
Это packing argument, а не повторное использование duty=Delta/tau. Оплата
полной длины D с обеих сторон границы увеличивает, а не уменьшает upper.
Зависимость окон от исхода исключена оплатой **всех** зарезервированных slots
и всех 32 моделируемых битов. Независимость B_H от Pairs не требуется.

Таким образом,

\[
U_{exec}(r)=\min(1,A+B_c r+C r^2),\quad
A=KL I2+32ND\,301\sum_j r_j,\quad B_c=32ND,\quad C=KLT.
\]

check_bounds.py, witness.py или другие production helpers. Она читает точный
Git blob CSV, использует рациональную арифметику, перечисляет реальные формулы
адресных endpoints и отдельно решает квадратичное уравнение с Decimal90.

## 4. RTL, service chronology и квалификация

### Соответствие заявленному цифровому witness

По reference_slot.sv и reference_schedule.sv:

- Один clk200 с enable раз в два base clocks; фазы 0/8/10/12/13/19/21/24
  согласованы с old-age проверками 7/9/23 в always_ff.
- Bus P0…31 — data, P32…38 — parity positions 1,2,4,8,16,32,39;
  P39…47 — zero padding. Прямой P[38:0] не является кодовым словом decoder.
- DQ и ERR фиксируются вместе; decode формирует зарегистрированный write_image.
  Последующие изменения входа не обновляют этот образ.
- Scrub пишет при `(corrected OR any latched ERR) AND NOT uncorrectable`.
  Чистое/ERR=0 не пишет; ERR-only пишет; DUE подавляет запись и успешный ack.
  Application read никогда не пишет. Preparation пишет trusted image без чтения.
- Отсутствие trusted_valid, transfer qualification, пропущенный фиксированный
  reservation и неисправность не разрешают незаметный перенос расписания.
  Soft reset прекращает новые обращения и допускает fence уже принятого;
  hard reset очищает epoch validity, а не удостоверяет чистоту SRAM.
- Принятие application read требует окончания к следующему scrub и интервала
  не менее 48 ticks; scrub имеет приоритет. На границе tick24 возможен следующий
  slot без дополнительного пузыря. Предположения о подготовке и календаре не
  требуют сдвига scrub из-за допустимого насыщенного потока чтений.

Собственный parity-check matrix Reviewer имеет столбцы `64|p`, p=1…38,
и 64 для overall parity. Решение семи parity coordinates через таблицу всех
128 синдромов независимо построило кодовые слова и ожидаемые 3955 test vectors.
Их SHA256 точно совпал с записанным RTL input:
`e51c32925bca9d1dc44228552af40ac341c95cb69dbd62e74084619562916f45`.
Это проверяет ожидаемый stimulus/code mapping, **не исполняет RTL**.

хэши изменённого source проверены. Логи показывают успешную компиляцию и FATAL
при direct-bus packing и пропуске ERR-only write. Это адресные sentinels к двум

## 6. Максимальная допустимая формулировка и решение следующего gate

> Для закреплённой reference-организации 524288 слов по 32 моделируемых data bits,
> независимых внутри слова singleton-toggle NHPP с заданным frozen r(t),
> последовательной доверенной подготовки от собственных sigma_w и фиксированного
> 24-tick read/conditional-write/fence расписания, при объявленной абсолютной
> clock envelope и корректных transfers вне оплаченного сервисного события B_H,
> получен достаточный upper вероятности первого capability exceedance в H,
> включая опасное состояние в t0. При дополнительно предполагаемом
> r_pre=max(r_j) он равен 0.000962653442214173738773…<epsilon_analysis=.001.
> Сервисные пересечения и начальная история включены; остаётся положительный
> численный запас 0.000037346557785826261227…. Цифровой witness согласован с
> заявленным ограниченным контрактом по выполненной проверке. Это условный
> проектный сертификат, не физический WCET и не full-device reliability guarantee.

Обязательные ограничения принятия:

- Общая NHPP/independent-increments предпосылка продолжается через t0; pre-H upper
  — внешнее предположение, не вывод из будущего максимума. Frozen r не установлен
  как физическая огибающая. Cross-word independence не требуется.
- Полный 39-bit hardware code и три SRAM не превращают data-only модель в
  подтверждённую модель скрытой ECC/parity, MCU или реальных parent events.
- Сохраняются фиксированный профиль immutable/read-only, отсутствие application
  writes, outcome-independent календарь, полная подготовка, квалифицированные
  fences и invalidation вне valid epoch. Нет бесплатной задержки/переназначения.
- Интерфейс резервирует **12.582912%** nominal tick time под scrub. Это стоимость
  обслуживания, не доказательство выгоды адаптации или полного resource budget;
  три микросхемы, подготовка и controller не бесплатны.
- E_cap не тождествен системному отказу; .001 не получено как миссионное требование.
  Существование достаточного fixed schedule не доказывает универсальную
  достаточность Fixed, минимальность выбранного класса или бесполезность информации.
- Нужен будущий общий event-space transfer:
  `E_cap,physical ∩ V^c ⊆ E_exec,model`, `Pr(V)≤delta_joint` и
  `U_exec+delta_joint≤epsilon_analysis`. Численный запас — только допустимый
  бюджет, **не** измеренная/доказанная joint coverage и не доверительный уровень.

**Ограниченное принятие допустимо сейчас в формулировке этого SR.** Для закрытия
локальных замечаний достаточно поправить определение B/конечный interval и
название корпуса; новый широкий RE/SR cycle и пересчёт не нужны. Численного
блокера для рассмотрения следующего joint physical-transfer contract не найдено.
Физические неизвестные блокируют только перенос к устройству, а не этот
условный математический/численный результат. Они не получают статус закрытых
за счёт данного PASS_WITH_MINOR.

Это поддерживающее основание для положений 1 и 4. Решение о принятии,
следующем physical bottleneck и достаточности для диссертационного положения
остаётся за Orchestrator/PI. Этот отзыв не регистрирует RES/HYP, не закрывает
Issue №15 и не разрешает изготовление платы или следующий эксперимент.

## Appendix: компактный воспроизводимый численный контроль

Следующий самостоятельный фрагмент запускается из корня exact checkout,
использует только стандартную библиотеку и не запускает production calculator:

```python
import csv, hashlib, io, json, subprocess
from fractions import Fraction as F
from pathlib import Path
p = Path('experiments/RE-CY62167-EXECUTOR-TIMING-GATE-01/reference-continuation-01')
c = json.loads((p/'config.json').read_text())
o = json.loads((p/'bounds.json').read_text())
raw = subprocess.check_output(['git','show',c['rate_commit']+':'+c['rate_path']])
assert hashlib.sha256(raw).hexdigest() == c['rate_sha256']
r = [F(x['r_bit_s_1']) for x in csv.DictReader(io.StringIO(raw.decode()))]
assert len(r) == 288 and min(r) >= 0
N, P = 524288, 100000000
u = lambda n: (F(200000*n,19999)+F(1,2))/10**9
l = lambda n: (F(200000*n,20001)-F(1,2))/10**9
gap = max(w*P//N+24-(-20000000+24*(w+1)) for w in range(N))
assert gap == 107416921
D,L,T = u(24),u(gap),u(20000000)
assert 300*l(P) <= 300+D < 301*l(P)
A = N*496*L*sum(300*x*x for x in r)+32*N*D*301*sum(r)
B,C = 32*N*D,N*496*L*T
U = A+B*max(r)+C*max(r)**2
assert U == F(o['U_exec']['exact']) < F('.001')
f = lambda x: A+B*x+C*x*x-F('.001')
lo,hi = (F(o[k]['exact']) for k in ('r_pre_limit_lower','r_pre_limit_upper'))
assert f(lo) <= 0 < f(hi) and max(r) < lo
print('PASS', gap, float(U), float(F('.001')-U))
```
