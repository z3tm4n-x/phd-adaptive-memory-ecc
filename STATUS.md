# Состояние проекта — 23.10.2026, новая постановка автора

**Цель:** заметно снизить затраты на защиту адаптивным управлением при Q(T)≤ε. Итог — **08.12**. Основной сценарий — долгоживущие данные и фиксированный код, сравнение с лучшим постоянным режимом того же кода. Выбор кода — отдельный многокритериальный сценарий с полной ценой. Приложение показывается отдельно; физика GEO/LEO не меняется.

**Новая приёмка:** PR246/247 слиты; [решение, проверка и продолжения](docs/reviews/ORCHESTRATOR_FIFTH_20261023.md). Первоначальный FAST допускает гарантированные 136 с при прежней ρ. Остаточная цена пока не подтверждает 5×. Новый контроллер и Q редкого режима не приняты; восстановление после loss прежнее. [Предыдущая приёмка](docs/reviews/ORCHESTRATOR_FOURTH_20261023.md) сохраняется.

**Шаг назад 23.10:** автор разделил адаптацию при заданном коде и выбор кода. Прежние пределы общей загрузки против t2 не отвечают новому основному вопросу. Нужен пересчёт, а не перенос старого запрета или обещание 5×. Неоптимальный постоянный кандидат с половиной бюджета также не заменяет лучший режим. Квалификация лётного образца не требуется; модельный вход измеренным не объявляется.

cFE остаётся основанием архитектуры таблиц, не универсальной долей памяти. Доля долгоживущих данных — параметр. При f<1 общий бюджет Q распределяется между областями; частичный расчёт не гарантирует весь банк. Аппаратная цена остаётся параметром. Физический вход, смысл Q и сроки сохранены; объект сравнения и метрика изменены явно по решению автора.
