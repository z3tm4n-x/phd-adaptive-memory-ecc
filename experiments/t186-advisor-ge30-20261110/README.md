## Что именно воспроизведено

Архив `advisor-inputs.zip` SHA-256 `82757eb3add56f84c5722d6446e3468cf67c532975548dc0294c7b969eb4813d`. Оба внутренних файла побайтно совпали с приложениями пользователя и хешами №186. Авторский C скомпилирован GCC 15.2.0 с -O2 без изменений. Генератор профиля F использует Python random seed 7. Для каждого профиля A…H C стартует с seed 1, генерирует 1500 независимых потоков и внутри повтора передаёт один поток всем шести исходным правилам из rules.txt. Генератор использует SplitMix64 для инициализации xoshiro256**, прореживание по максимальной интенсивности сегмента, два разных равномерных слова и по одному равномерному разряду в каждом. [Дословный stdout](original-stdout.txt) · [Воспроизводящий запуск](original.py).

Значения в pA…pH — частота **разрядных инверсий всего банка**. Генератор уже умножил эталонную частоту на s=39·65536/(38·524288)=39/304. При метках 2 темп родителей равен половине этой величины. Для исходного W=656 полная банковская экспозиция и L=12,845056 мс сохранены искусственно. Темп отдельного разряда увеличен в 65536/656 раз. Для результата на 65 536 слов поток на реальном числе слов сгенерирован заново по заданному закону; в пределах банка все правила имеют общее зерно и общие частицы. Событие — первое физическое превышение веса 1 в каком-либо полном внешнем слове.

На перечисленном в комментарии C подмножестве A,B,G,H,F максимальные частоты штатного исполняемого файла для 4L, age32, age64 и age1680_512 равны соответственно 0,0807 / 0,0200 / 0,0227 / 0,0473. В комментарии даны округлённые ориентиры 0,079 / 0,024 / 0,025 / 0,049. За исходный результат принимаем сохранённый stdout с указанным seed. На A у 4L получено 121/1500, у age32 и age64 — по 28/1500.

**Точная сверка источника.** В C при первом отказе обрывается числитель счётчика проходов, знаменатель остаётся T. Для A у 4L получено 22,9838% сканирования, при продолжении до T — 25,0000%. На E у age1680_512 это 0,2220% и 0,4169%. Независимая обработка XOR-масок на исходном binary64-календаре сохранила все 72 000 признаков первого превышения. Проверены также рождения в последнем необслуженном промежутке. В трёх траекториях B по двум степенным правилам там остались рождения, новых первых превышений в выборке они не дали. На направленной трассе две разные позиции одного слова в таком хвосте дают настоящий отказ. [Сверка на исходных часах](legacy-results.json) · [Исполнитель](legacy.c).

Отдельный контроль на том же W=656 использует целые наносекунды и абсолютный номер раунда. Отказов на B/age3360_512 стало на один меньше, на D/age1680_512, E/age1680_512 и G/fixed4 — на один больше. Эта чувствительность включает дискретизацию времён и замену цепочки сложений binary64 номерацией раундов. Первоначальный результат сохранён отдельно. [Контроль целочисленного времени](ideal-results.json).

## Профили, состояние и границы

Аудит проинтегрировал буквально выпущенные десятичные сегменты, проверил всю сетку от 0 до T, пик, надфоновую экспозицию, максимальный положительный наклон и сумму первоначального избытка с положительной вариацией, включая скачки. Общий бюджет на банк U=3,701792763 с⁻¹. У D высокий старт 0,125870223 плюс 110 подъёмов суммой 3,692666577 дают **3,818536800 с⁻¹**. У E 15 095 подъёмов дают 506,734563427 с⁻¹, или 136,889 квоты. D и E — стресс-профили. На E у зарегистрированных L/32L, L/64L и лестницы получено 3, 13 и 61 превышение из 1500. Последняя частота 0,04067 имеет интервал 95% [0,03179; 0,05190].

Проектные формы A,B,C,F,G,H укладываются в квоту вариации. При строгой проверке буквальных файлов округление также имеет значение: у фоновых сегментов уровень ниже b на 3,31·10⁻¹⁵ с⁻¹, B превышает квоту экспозиции на 1,08·10⁻⁶ инверсии, наибольшая погрешность роста у F составляет +2,42·10⁻¹⁰ с⁻². Поэтому ни один из восьми текстов не обозначен как точный представитель всего математического класса. В симуляции использованы исходные десятичные значения, в доказательстве — точные ограничения Ц1. [Аудит сегментов с отклонениями от каждой квоты](profile-audit.json).

При старом мгновенном чтении возраст обновляется во время чтения соответствующего слова. На новом порту у аналогов советника исправление публикуется на release и следующий частый проход можно начать после завершения текущего. У правил №196 разрешения выдаются на общих границах по полным отчётам. Для лестницы 3,5,10,19,38,75,149,298,596 нулевых ячеек разрешают последовательные уровни; внутри интервала исправление сбрасывает вариант на первом доступном решении. Ни профиль, ни времена частиц контроллеру не выдаются. [Регистрация](https://github.com/z3tm4n-x/phd-adaptive-memory-ecc/issues/196#issuecomment-6763451035).

Обе политики используют одно условное правило обслуживания E. Снимок в модели относится к началу операции, к release удаляется исправляемая ошибка снимка и сохраняются поздние XOR. Рождение до release может впервые превысить вес 1, даже если последующая запись его уменьшила. После превышения внешний укороченный расширенный код Хэмминга продолжает выдавать свои решения; обнаруженный DED сохраняет слово, ошибочная коррекция за радиусом оплачивается. Распознанный неисправимый снимок делает отчёт зарегистрированного правила непригодным. Обращения продолжаются, начатый E оплачивается целиком, слова последнего прохода со start≥T не покупаются. Реализации с иной реакцией на отказ имеют свою цену. Исходный авторский C оставлял эту реакцию неопределённой.

## Воспроизведение

Из корня репозитория в Linux. Дословный повтор выполнен на Python 3.14.4 и GCC 15.2.0. Ниже `../tmp/advisor-raw` — приватный каталог вне Git, `$ZIP` — путь к исходному архиву. Крупные построчные таблицы остаются в этом каталоге, их SHA-256 сохранены в JSON. Файлы источника в Git не включены.

```sh
p=experiments/t186-advisor-ge30-20261110
python3 "$p/original.py" --zip "$ZIP" --work ../tmp/advisor-raw --check
python3 "$p/legacy.py" --zip "$ZIP" --work ../tmp/advisor-raw --check
python3 "$p/run.py" --zip "$ZIP" --work ../tmp/advisor-raw --check
python3 "$p/profiles.py" --work ../tmp/advisor-raw --check
python3 "$p/bounds.py" --check
python3 "$p/tables.py" --check
python3 "$p/verify.py"
```

Направленная проверка исполнителя включает XOR-погашение, попадание во время ремонта, обрезанный последний проход, отказ в хвосте и сравнение всех десяти политик с пошаговым посещением проходов на коротком сроке. [План](PLAN.md) · [Полный первоисточник времён порта](https://www.infineon.com/assets/row/public/documents/10/49/infineon-cy62167g30-cy62167ge30-16-mbit-1m-words-x-16-bit-2m-words-x-8-bit-static-ram-with-error-correcting-code-ecc-datasheet-en.pdf). Для дополнительной сверки с научной версией PR449 укажите `--theory-root ПУТЬ` у `verify.py`, где ПУТЬ — checkout `a25dbe2252058bae0f930d902a032377466b974c`. Проверяются исходный Git-объект проверяющей программы, все фазы календаря и независимые подстановки 32L и 64L.
