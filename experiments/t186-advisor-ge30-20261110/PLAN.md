# План сверки после передачи календаря

Файлы авторского ZIP приватны. Проверяем неизменные два SHA-256 из №186, сохраняем буквальный stdout при GCC -O2, seed=1, 1500 парных реализаций каждого A…H и метках двух различных слов. Все шесть строк rules.txt воспроизводятся. Геометрию, экспозицию и подъёмы проверяем по выпущенному тексту с его округлением, включая скачки между сегментами и высокий старт. Нормировка относится к полному банку даже при искусственном W=656.

Независимый событийный исполнитель повторяет функции выбора на старом L и W=656, считает первое достижение веса ≥2 в любой момент до T, включая хвост. После превышения сохраняем маску и применяем внешний SECDED до T, обнаруженный DED не пишет слово. У старых правил часы возраста меняются только на исправлении. У зарегистрированных правил непригодность сбрасывает историю. Длительность быстрого режима измеряется между началами проходов, цену — по начатым словам и ремонтам. Проверяем перенос ошибки, совпадения, условную запись и префикс последнего прохода на коротких трассах. Зарегистрированный нуль выдаётся после scan+drain.

На полном W=65536, опубликованном L и том же законе воздействия сравниваем все шесть аналогов советника (множители периода сохраняются), постоянный L и правила по завершённым отчётам L/32L, L/64L, степенное по [регистрации №196](https://github.com/z3tm4n-x/phd-adaptive-memory-ecc/issues/196#issuecomment-6763451035). Для степенного выбираем обязательный сброс на первом доступном решении после исправления. Для двухпериодных переход только на общей границе. Общая инициализация и локальный канал исправны на модельных траекториях. Одни частицы на все политики одной реализации. Номинальное слабое E использует согласованный снимок на start и исправляет на release с переносом поздних XOR. При обнаружении сверхрадиусного снимка применяется тот же внешний декодер. По новому сервису у аналогов советника обновляем возраст при завершении ремонта, решение устанавливается после полного прохода. Возраст для исходной формулы берём у начала прохода, как в C.

Выдаём наблюдаемые первые превышения с биномиальным интервалом 95%, полную известную занятость по операциям, времена, переключения и оконный верх пика. Классовое сравнение использует отдельный достаточный постоянный календарь, нижний свидетель Ц1 на том же устройстве и сертификат только соответствующей регистрации. Цены управления, CPU, энергии, непрерывной исправности и возможной работы после неисправности остаются условиями.
