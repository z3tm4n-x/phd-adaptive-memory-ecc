# RE-CY62167-COVERAGE-THRESHOLD-01 — входной блокер

Дата: 2026-09-15. Исполнитель: Research Engineer (Codex), текущая отдельная RE-сессия.
Статус: **BLOCKED_INPUT / NUMERICAL_DELIVERY_NOT_COMPLETE**.

## Результат и четыре решения

Полный квалифицированный DREG-rate недоступен. Восстановление выбранного среза
блокирует отсутствие замороженного transport. Замена другой суммарной колонкой
не квалифицирована: ранее заявленное тождество энергетического преобразования
опровергается исходными коэффициентами. Поэтому I1, I2, a_upper, b_upper,
численный запас и допустимая задержка не вычислены и записаны как null.
Это не нулевые значения и не доказательство непустоты или пустоты области.

| Предмет оценки | Вывод |
| --- | --- |
| Численный сертификат registered-модели для конкретных Delta | **Не установлено**: корректное сопряжение SR-03 принято в своей области, но нужный численный вход отсутствует. |
| Требуемый coverage upper для переноса | **Достаточно** условно подтвердить отдельный контракт сопряжения и 0 <= delta_cov_upper <= s(Delta), при s(Delta) >= 0. Численное значение требования **не установлено**. |
| Подтверждение такого upper имеющимися физическими материалами | **Недостаточно**: нет квалифицированного вероятностного контракта покрытия полного устройства. |
| Принятие конкретной физической политики Fixed | **Не установлено**. В этой поставке получено только символическое требование и диагностика входа, даже численное требование пока не завершено. |

## Почему имеющийся upstream не заменяет DREG

Замороженный build_rates из RE-CY62167-ECC-RISK-BRIDGE-01 использует
энергетическую плотность upstream с множителем mreg(E)/kbar(E) для накопительного
data-bit потока. mreg берётся из сохранённой registered_direct_by_energy.csv;
kbar — из MULT_POINTS замороженного upstream_interface. Высокоэнергетическая
компонента также умножается на mreg[-1]/kbar[-1]. Нулевая зарегистрированная
direct-доля не делает этот множитель единицей.

Точный аудит целых счётчиков выявил различия на 29, 40, 80, 124, 164 и 186 MeV.
Например, при 186 MeV mreg=12969/8356, kbar=12972/8356, отношение=4323/4324,
не 1. Отличие есть и для хранимых floating-point коэффициентов. Все 14 узлов,
числители, знаменатели, точные дроби и идентичности исходников сохранены в
outputs/input_audit.json. Сопоставление выполнено через AST/literal_eval и
Fraction без импорта основного научного вычислителя и без разбора сырых CY.

Это опровергает заявленное тождество преобразования, но само по себе не вычисляет
разность интегрированных rates выбранного окна: случайное равенство свёрток
не проверено. Одной суммарной upstream-колонки недостаточно для восстановления
энергетически взвешенного DREG по этому правилу. Её использование как иной
консервативной огибающей здесь также не обосновано и не разрешается автоматически.

## Сохраняемая математическая граница — без численного исполнения

Обозначения: N_w=2^19, n=32, tau=1 s, H=86400 s,
r=nu_C_bit_DREG_s^-1 / 2^24. Делится суммарный поток накопительных data-bit
поступлений, не direct hazard и не уже побитовая интенсивность. r имеет единицы
s^-1, I1 безразмерен, I2 имеет единицы s^-1, a безразмерен, b имеет единицы s^-1.

При квалифицированном полном наборе согласованных постоянных 300-секундных
блоков, периодических проверках с фиксированными фазами и общем детерминированном
пределе 0<=Delta<tau сохраняется duty-формула SR-03:

    I1 = integral_H r(t) dt
    I2 = integral_H r(t)^2 dt
    a = N_w * C(32,2) * tau * I2
    b = 31 * N_w * I1 / tau
    U(Delta) = min(1, a_upper + b_upper * Delta)
    s(Delta) = 0.001 - U(Delta)

Численно выполнение всех duty-условий здесь не подтверждено: временная сетка
согласована по контракту/metadata, но сам rate отсутствует. Средняя загрузка не
заменяет оконную огибающую; при несоблюдении условий потребуется исходная
детерминированная оконная оценка SR-03. Известная по прошлому случайная задержка
не становится детерминированной: ожидание нельзя убрать таким переименованием.

Для неотрицательных квалифицированных коэффициентов достаточная область:
0<=Delta<1 s и 0<=delta_cov_upper<=s(Delta), только если s(Delta)>=0.
Поскольку epsilon<1, это равносильно a_upper+b_upper*Delta+delta_cov_upper<=0.001.
Равенство допускается. Граничные случаи (алгебра, не пройденные численные тесты):

- a_upper>0.001: область пуста, включая delta_cov_upper=0 и Delta=0.
- b_upper=0 и a_upper<=0.001: любой 0<=Delta<1 s, coverage upper<=0.001-a_upper.
- b_upper>0, a_upper<=0.001, coverage upper=0: Delta<1 s и
  Delta<=(0.001-a_upper)/b_upper. Если отношение>=1 s, максимум на строгой
  области Delta<1 не достигается; 1 s — только супремум.
- a_upper=0.001 и b_upper>0: только Delta=0, delta_cov_upper=0.
- При насыщении U=1 остаток равен -0.999, а не 0. Отрицательный остаток не
  разрешает нулевой coverage. Непрохождение upper не доказывает невозможности
  физического устройства или всех политик Fixed.

Никакой статистический интервал не строился. Контроль численной ошибки
не заявлен: вычисления интегралов не было. Старый next_plus после округлённой
суммы не является доказательством полной огибающей; этот путь отключён.
Исторический U_reg не использовался для rate, цели ответа или калибровки.

## Физическое основание

Проверены существующие REPORT в RE-CY62167-PROTON-01,
RE-CY62167-DISTANT-MCU-OBSERVABILITY-01 (включая observation_contract.json),
RE-CY62167-PAPER-COMPLETION-01 на закреплённом дереве, а также SR-03 и disposition.
Они не обеспечивают верхнюю вероятность общего события нарушения покрытия:
зарегистрированные постобработанные кластеры не тождественны parent events;
не установлены полный pre-cluster процесс, split/merge/censoring, фактическое
внутреннее W и parity-покрытие. Point response и central_mean не являются
физической верхней огибающей; равномерность по bits и независимая пуассоновская
модель остаются допущениями. Допуски RES-004 не переносились.

Для device-level вывода нужны отдельно событие V нарушения покрытия,
доказанное сопряжение физического E_cap с объявленной моделью вне V и
P(V)<=delta_cov_upper на том же горизонте/среде. Вычитание epsilon-U только
задаёт допустимый бюджет; оно не измеряет P(V). При статистическом подтверждении
должны быть заданы совместное покрытие всех используемых границ и отдельная
оплата вероятности нарушения этого подтверждения. Здесь их нет.

Один приоритетный недостающий физический контракт: **количественный контракт
неохваченных E_cap-релевантных путей полного слова**. Он должен документировать
связь parent events и зарегистрированных данных (включая потери/слияния),
их отображение в data+parity слова и вероятностную верхнюю границу нарушения
этой связи для указанного горизонта и среды. Его измерительное основание должно
связывать исходные журналы до кластеризации с экспозицией/fluence и режимом чтения;
для неизвестных W/parity нужна подтверждённая карта либо доказанная инвариантная
огибающая. Подтверждение P(V)<=s(Delta) при прочих выполненных предпосылках
изменило бы решение о достаточности переноса именно этой Fixed. Это запрос на
контракт, не обещание, что одно дополнительное измерение закроет все пробелы.

Отдельно остаются фактический верхний предел correcting-write latency и
процедура чистого старта. Delta не измеренный WCET, datasheet tWC>=45 ns — минимум,
не верхняя задержка; epsilon_analysis не требование лётного изделия. Физический
parent event, зарегистрированный кластер, toggle, ECC outcome, E_cap, DUE/SDC
и отказ системы не отождествлены. Нулевая доказанная нижняя direct-граница
не означает нулевого физического риска. Полный actual-CY m0/m1 не построен.

## Проверки, ограничения и следующий шаг

Машинный входной аудит завершился успешно: идентичности, 14 пар коэффициентов,
шесть несовпадающих узлов, frozen GOES members/metadata и три защитных остановки.
Остановки имеют returncode=1 намеренно и не являются ошибкой научного расчёта.
Независимое вычисление интегралов — NOT_RUN. Mutation-тест ошибочной нормировки,
проверки пропусков/дубликатов/конечности/неотрицательности selected-rate,
численные boundary-тесты Delta=0/Delta<tau/нулевого/отрицательного остатка —
NOT_RUN. Никакой PASS по ним не присвоен. Проверки кода не подтверждают физику.

Для продолжения требуется предоставить один из двух exact-SHA источников,
указанных в INPUTS.md. Затем нужны исправленные recovery/calculator/independent
checker с консервативной арифметикой и адресными тестами, новый pre-execution
commit до CY-расчёта, полный небольшой selected-rate без stub, численный REPORT
и только после этого отдельный Scientific Review. Текущая поставка готова
лишь к проверке входного дефекта и корректности остановки, не к приёмке
численного ответа всего задания. Scientific PASS, новый RES и закрытие Issue
не присваиваются.
