# T113 — рост на входах и повторных подъёмах

Issue [#113](https://github.com/z3tm4n-x/phd-adaptive-memory-ecc/issues/113).
Ветка `t113-onset-growth`, исходный main
`5b463280be672d1c0fcc839b95c786d7c624b8be`.

Определения до расчёта — [METHOD.md](METHOD.md), закреплённые входы —
`config.json`. Первый коммит PR фиксирует определения до нового расчёта.
Принятые T67/T72 читаются без изменения. Основной RTL не выполняется.

## Повтор

Из корня репозитория, Python ≥3.10, зависимости `requirements.txt` и один
из уже поддерживаемых T67 способов чтения netCDF (netCDF4 или libnetcdf,
в том числе установленный VTK):

```sh
python -B experiments/t113-onset-growth/run.py
```

Команда проверяет SHA закреплённых файлов, запускает 21 направленную
проверку, использует существующий `T72.prepare` для проверенного кэша,
выполняет весь охват и сравнивает собственные результаты побайтно.
По умолчанию результаты не перезаписываются. `--write` явно пересоздаёт
только `t113-onset-growth/outputs/`; `--tests-only` не требует сети.

Кэш задаётся `--cache PATH` или `T113_CACHE`; по умолчанию — `t113-cache`
в системной временной папке. Если кэша нет, загружаются **только** ранее
выбранные 1097 файлов T67 (~1,6 ГБ), не новая выборка. Старые checksum,
маски, отклик, парсер и таблицы сохраняются. Изменённый SHA/недоступный
файл прерывает повтор с явной ошибкой; нулевая траектория не подставляется.
Исторические отсутствие источников и потерянные качества уже отражены
в принятой таблице доступности и новом индексе. Большие исходники не в git.

## Таблицы и передача

Все CSV имеют UTF-8, первая строка — имена полей; `.gz` — обычный gzip.
Точные CSV/JSON имеют приоритет перед округлением в кратком отчёте.

| Файл в `outputs/` | Содержание и тип оценки |
|---|---|
| `event_levels.csv` | 47×3 строки: все окна/уровни, main/screened, 60 с (special_201709 — 300 с). Свидетель минимального разрешённого времени подтверждённого входа, его интеграл и oracle-U счёт; минимумы роста имеют отдельный `record_id` |
| `crossings.csv.gz` | Все исходные строки T72, новые интервалы/страты, цензурирование, раздельные H/лог/наблюдаемое e-время, UTC/версия/SHA/качество каждого экстремума |
| `coverage.csv.gz` | Все исходные статусы доступности, сверенные с кэшем, плюс цензурирование/соседние пары; нулевое покрытие не превращается в нулевой рост |
| `quiet_episodes.csv.gz` | Подтверждённые и цензурированные начала/концы; конец после 24 ч тихих бинов доступен с конца последнего бина |
| `declines_and_hold.csv.gz` | Каждый повтор × два w/h: наблюдаемый спад и условные сроки LOW/последней тревоги; фактический FAST/SLOW неизвестен |
| `growth_extrema.csv.gz` | Описательные экстремумы и положительные квантили по прибору/направлению/модели/маске/порогу/каденсу/страте/зоне |
| `growth_distribution.csv` | Объединение по приборам/направлениям без заявления независимости; дубли пары из перекрывающихся окон удалены внутри страты; несовпадающие истории помечены |
| `count_index.csv.gz` | Индекс прежних ожиданий U: extrema по исходной сетке с точными периодом/фазой/задержкой/раскладкой; не закон ERR при E |
| `handoff.json` | Кандидаты условного класса, метрики/ограничения, точный запрос оставшихся предпосылок теоретику |
| `reproduction.json` | Проверки, SHA входов/кэша/новых выходов и численные сверки с T72 |

Исходные 213480 строк счёта не копируются: они доступны в
[`T72/available_counts.csv.gz`](../t72-r0a-onset-inputs/outputs/available_counts.csv.gz),
SHA закреплён в конфигурации. Счёт начинается в `quiet_exit`, не на новом
подъёме и не в окне w; чистое начало — допущение этого диагностического U.
Основная таблица показывает отдельно P=0,05/6 с, фазу 0, доставку ERR 0,
uniform layout, на начало целевого бина; это **явно старый диагностический
сценарий**, не неизвестная реальная задержка, принятая нулевой.
Другие фазы/задержки, pending и packed pass остаются в полной исходной таблице.

## Предел результата

Это описательные функции бинов data32/протоны/10 мм Al. Квантили не имеют
95%-покрытия будущего. Выбранный 2× запас не исключает произвольный рост
внутри минуты. Ни один label «после пика», низкий λ или длинный спад не
определяет состояние ERR-контроллера. Применимость к full38/фон+вспышки/
3 г/см² требует спектрального переноса и отдельного закона ERR при E.
D*, ε, пик, задержка и запас 10% не изменены; Q(T) этим расчётом не доказана.
