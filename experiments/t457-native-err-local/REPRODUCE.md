# Воспроизведение проверки №457

Из корня репозитория, Linux/WSL с Python 3, компилятором C, Icarus Verilog
и его заголовками VPI:

```sh
python3 experiments/t457-native-err-local/reproduce.py --check
```

Команда в новом временном каталоге компилирует модель и VPI-мост, выполняет
все **26 детерминированных прогонов** из `cases.py`, разбирает журналы,
пересчитывает интервалы захват–release и пороги и сверяет три производных
файла **побайтно**. В состав проверки входят четыре отдельно скомпилированных
намеренно неверных DUT: ранний ноль; потеря последнего ERR; формальный
флаг FAST при фактически отложенном старте; опрос в неактивном кадре.
Ожидается отказ именно на соответствующем инварианте, а не ошибка сборки.
Для нестандартной установки задайте `VPI_INCLUDE` (по умолчанию
`/usr/include/iverilog`). Приватный генератор, Интернет, NumPy, Vivado
и плата не нужны. `--from-capture` проверяет ранее сохранённые трассы и
не заменяет описанный свежий запуск.

**Действительно исполненные источники.** Базовый main:
`34a6875ee0803e46a47e520d6f4bd5e2008ecb80`; глава и принятые пакеты
не менялись. До опыта — [CONTRACT](CONTRACT.md) в
`3e3c09ac1ae6989a1b466ca94bf7df1d36bd69bd`.
`build_model.py` хеширует четыре входа: публичный replay.c №448,
memory_oracle.py №104, calendar.json №456, result.json №457. Из replay.c
берутся дословные диапазоны объявлений, ceil_pos, registered_cells и
choose. Прежний внешний декодер и генератор не используются. Признак
обнаружения в этой ветви — «переданный count положителен»; истинное
состояние памяти и идентичности частиц недоступны функции решения.

**Эталон и цена.** Стенд инвертирует позиции в битовых масках; oracle.py
повторяет список инъекций и использует birth-labelled Word/MemoryOracle
(begin, observe, toggle) из №104. Момент записи и release берутся из №456,
а не из старого write/release №104. Порядок при совпадении определён:
инъекция до соответствующей выборки; пакет на сечении входит в решение,
после него — нет. Установка с пропуском оставляет уже назначенный быстрый
старт. Это модель номинальной сетки 10 нс, не физический ACK микросхемы
и не WCET вычисления. На длинной траектории разрешён перескок лишь
установившегося пустого промежутка без входов и блокировки. Для одного
и того же перехода сравниваются буквальное/ускоренное исполнения (хеш
всех событий и все результаты без счётчика ускорения). Максимальная
пауза после 256L проверена буквально. window_audit.py не использует
внутренний тариф симулятора: он суммирует вырезки из пар G–R и отдельно
проверяет десятичные подстановки в бюджет. Независимая научная рецензия
этой новой связки не проводилась.

**Техническое расхождение не скрыто.** В первом варианте
`f19790a7898c7bb92a014470030ff39b0fbcd0e4` на чистом раунде 1282
эталон ожидал 2L, стенд выбрал L. Отладочный вывод VPI показал
`invalid=2` для логического нуля ширины один бит и ложный признак ERR:
учитывались недействительные старшие биты контейнера VPI. В
`29737b16cac6832609140096d6368b4ee689538f` учитываются только
объявленные биты, X/Z в них отвергаются. На том же входе получены
`det=-1, invalid=0` и 2L. Заодно стенд явно проверяет 10 нс между
модельными фронтами. Прежние числа не использовались; функция №448,
фазы, критерии и бюджет №457 не переопределялись.

**Проверенный снимок кода и результатов:**
`2e8a1c0b395e341f21d819548ed779458f3070b4`. В чистый архив вошли
только пакет задачи и четыре перечисленных входа, без .git, старых
журналов или .build. В Ubuntu/WSL2 (Python 3.14.4, GCC 15.2.0, Icarus
и vvp 12.0) свежая сборка, все прогоны, отрицательные проверки и сверка
дали exit 0. Экспорт Windows с CRLF в upstream replay.c: **40,36 с хоста**,
GNU time max RSS 36048 кБ; все 21 файл неизменны относительно исходного
архива. Экспорт с каноническим LF: **40,38 с**, max RSS 35700 кБ; все
21 файл после опыта совпали с соответствующими Git-объектами. Это не
измерения времени или памяти аппаратного контроллера. Хешируется
канонический LF только для исходного `text=auto` replay.c; три остальных
входа проверяются по байтам. [Контрольные суммы и предел проверки](validation.json).
