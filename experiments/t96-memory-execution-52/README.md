# №96, п. 5.2. Ошибки в памяти и исполнение правила по ERR

На четырёх словах обе версии контроллера №465 исполнили то же расписание, что и событийный эталон. На 8192 общих воздействиях совпали момент первого превышения, записи, полные отчёты, установленный шаг и следующее чтение порта. Вероятность первого превышения оценивается в **5,884%** с точным 95%-м интервалом **5,384–6,415%**. Расчётный верх для тех же четырёх слов, фаз и импульсов составляет **7,324%**. [Машинные результаты](result.json) · [Фиксация до запуска](https://github.com/z3tm4n-x/phd-adaptive-memory-ecc/blob/ce897d227a528c2efb70920c3f18c7cdaa380494/experiments/t96-memory-execution-52/PROTOCOL.md)

### Что исполнялось

Цифровая память хранит четыре слова по 32 информационных и шесть проверочных разрядов. Две половины каждого слова читаются по адресам ×16 `(0,4), (1,5), (2,6), (3,7)`. На выводе данных DQ появляется результат декодирования, на выводе ERR — признак ошибки при чтении. Каждая частица инвертирует одну равномерно выбранную позицию в одном слове (4/5) или по одной в двух соседних словах (1/5). Инъекция записывает метки в ячейки. Сам контроллер получает только DQ, ERR и штатные разрешения. Он выбирает адрес, выдаёт записываемые 16 бит и определяет время следующего обхода. На активном конце WE# стенд принимает фактические данные шины. При записи сохраняются живые ошибки в этом слове, возникшие с начала обращения. [Стенд](pins.cc) · [Исходный RTL](../native-example-20261111/native8.sv)

Горизонт от первого чтения адреса 0 равен 3 614 957 нс. Длительность номинального такта 10 нс, полного обхода 2800 нс. Два пуассоновских импульса длительностью по 5600 нс приходятся на раунды [1281,1283) и [1285,1287). От стресса №500 сохранена интегральная экспозиция каждого импульса, 1/5 инверсии на слово. Для четырёх слов это 4/5 инверсии банка и 2/3 родителя в среднем за импульс. Сжатие времени и привязка к первому повышению шага заданы до прогона. Все разрешения исправны. Событие для $Q$ — первое одновременное присутствие двух разных ошибочных позиций в одном слове, в том числе между чтениями. После него счёт затрат продолжается по конвенции №500 до конца горизонта, включая неполное обращение. Цифровая память при ненулевой маске тогда продолжает выдавать ERR и правильные данные. [Размещение, фазы и параметры](config.json) · [Исходный 16-словный опыт](../t186-reduced-comparison/README.md)

Реализованы 10 766 частиц и 12 869 инверсий. Зарегистрированы 12 640 записей, 9106 полных положительных отчётов и 10 554 063 полных отчёта всех типов при 10 560 048 начатых обходах. На 2207 траекториях произошёл один переход с шага 1 на шаг 2. На 5985 произошёл также возврат. Первые 1280 чистых обходов занимают 1,024 мс порта на каждой траектории и объясняют большую долю частого режима. Все средние включают траектории с превышением и без него. Обе конфигурации получили один набор случайных входов. Полуширина интервала вероятности равна 0,0051575 при заявленном пределе 0,011 в долях единицы. [Счётчики и распределение переключений](result.json)

**Основание верха.** До первого повышения посещается каждый раунд. Повышение происходит на чётном раунде. До $T$ достижимы только шаги 1 и 2. Сохранение шага 2 ведёт в следующий чётный раунд, а возврат к шагу 1 добавляет посещение. Новое повышение возможно только на кратном 256 раунде. Поэтому каждое слово обязательно обслуживается на двух известных фазах всех чётных раундов. Если перед таким посещением в слове была старая изолированная ошибка, она устранена к +160 нс при отсутствии нового попадания. Для первого превышения нужны метки **разных родителей** в разных позициях одного слова. Обе попадают либо между двумя обязательными стартами, либо по разные стороны следующего старта, пока его запись ещё возможна. Дополнительные посещения способны устранить старую ошибку или сохранить новую по принятому закону записи.

Для слова в промежутке $j$ обозначим ожидаемое число инверсий через $M_j$, а часть за первые 160 нс после его начала через $D_j$. При чистом начале и обрезании по $T$ сумма математических ожиданий подходящих пар даёт верх $\tfrac{37}{38}\sum_{w,j}(M_j^2/2+M_{j-1}D_j)$, где $M_{-1}=0$. Условная вероятность разных позиций равна 37/38. Два попадания одного родителя приходятся на разные слова. Для разных родителей использован пуассоновский факториальный момент. Возможный повторный учёт опасной траектории допустим для верхней оценки. Второй расчёт перечислил наносекундные корзины импульсов и отдельно учёл двух разных родителей внутри одной корзины. Обе формы дали одинаковую дробь. [Интегралы по фактическим фазам](inputs.py) · [Проверка по корзинам](crosscheck.py)

### Запись, изменившая следующее чтение

В раунде 1280 порт опубликовал полный нуль на 3 586 260 нс, предложил шаг 2 на 3 586 500 нс и установил его на 3 586 700 нс. В паузе на 3 586 901 нс была инвертирована проверочная позиция 32 слова 1. Следующее чтение адреса 0 началось на 3 589 600 нс (раунд 1282). При чтении адреса 1 оба RTL захватили ERR=1 и DQ=0x3411 на 3 589 900 нс. На 3 590 000 нс по WE# записано 0x3411, остаток нулевой. Полный счёт 1 опубликован на 3 591 860 нс. На 3 592 300 нс установлен шаг 1, и уже на 3 592 400 нс началось чтение адреса 0 раунда 1283. В отдельном случае два разных разряда одновременно ошибочны на 111 нс, третий удар на 113 нс снимает одну ошибку до первого чтения этого слова. Момент превышения остаётся 111 нс. [Оба входа и трассы](witnesses.json)

### Что проверено

- Yosys собрал неизменённый RTL из №465 с `CHECK_LOCAL=0` и `1`. На каждой траектории проверялись реальные переходы порта, адреса, выборки DQ/ERR, данные и остаток при WE#, публикации, команды и первое следующее обращение. За общим тихим началом сверено 2 488 511 строк случайных трасс **для каждой конфигурации**. Отдельно сверена 49 091 строка в 59 направленных случаях и на четырёх траекториях с запуском от reset. В выборку направленных случаев входят все 38 одиночных позиций, последний адрес, повторное попадание, границы выборки, записи и горизонта. [Эталон](reference.py) · [Сверка и критерии](run.py)
- Общий чистый префикс до 3 584 000 нс исполняется на настоящем RTL. Затем копируется достигнутое состояние, включая такт, обе части регистров CXXRTL, память, счётчики и наблюдаемые сигналы. Для реализаций 0–3 от обычного reset буквально сверены состояние на границе, дальнейшие сигналы и полная цена. Python-эталон хранит время рождения каждой живой ошибки и сам строит календарь по истории полных отчётов. Общими входами служат календарные константы и список частиц. [Сборка и контроль снимка](build.py) · [Стенд](pins.cc)
- Исходное ядро программного опыта №500 отдельно исполнено без изменения кода с исходного чистого состояния на всех 8192 воздействиях. Во временной копии конфигурации изменены только число слов и число адресов. Для каждой траектории совпали девять величин, в том числе время первого превышения, обе длительности порта, число положительных отчётов, смены шага, время частого режима и конечное число ошибочных позиций. В №500 завершённая запись учитывается при освобождении порта (+200 нс), здесь строб считается на +160 нс. На случайном профиле все назначенные записи успели завершиться. Различие определений на обрезанной записи проверено адресными примерами. Интервал независимо пересчитан по бета-квантилям SciPy. [Код повторной сверки](crosscheck.py)
- Первый отладочный случай — чистый reset, пустой список частиц и $T=8400$ нс. При первом чтении наблюдатель первоначально показал снятие OE# на +80 нс, эталон ожидал +70 нс. Причина была в чтении комбинационных выводов CXXRTL до их стабилизации после фронта. Наблюдатель исправлен повторным вычислением при том же уровне такта. Время не продвигается. После исправления независимо повторены семь граничных опытов Icarus для каждой версии. Полный нуль к +2500 нс допускает старт 1282, первое подтверждение в +2505 нс сохраняет 1281. [Стенд Icarus и проверка фронтов](../native-example-20261111/timing.py)

Модель использует объявленные пары адресов, видимость ERR для всех 38 позиций и заданный остаток записи. Паспорт и журналы не устанавливают эти три свойства конкретного кристалла одновременно. Эксперимент проверяет исполнение правила на коротком профиле. Сроковые оценки ГСО и частоты аппаратных отказов требуют своих входов. Для неизменённого контроллера в №465 получены 158/182 Slice LUT и 93/94 триггера для двух версий на xc7z020clg484-1. Эти числа относятся к прежнему синтезу при 10 нс. ### Повтор из корня репозитория

Основной запуск выполнен в Ubuntu с Python 3.14.4, NumPy 2.3.5, Yosys 0.52 (`fee39a3`) и G++ 15.2. Требуются CXXRTL-заголовки соответствующей версии Yosys (пакет `yosys-dev`). Если они в другом каталоге, передайте `--include` с путём, в котором лежит `cxxrtl/cxxrtl.h`. Для граничных тестов использован Icarus 12.0. Дополнительная сверка ядра №500 выполнена под Windows с Python 3.13.5, NumPy 2.2.4, Numba 0.61.2 и SciPy 1.15.2.

```sh
python3 -B experiments/t96-memory-execution-52/run.py --work /tmp/t96-step52 --check
python3 -B experiments/native-example-20261111/hardware.py timing
python3 -B experiments/t96-memory-execution-52/crosscheck.py
```
