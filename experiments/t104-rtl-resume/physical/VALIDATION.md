# Основания и пределы проверки T104 physical

## 1. Композиция цифровых свойств

Проверяется не монолитная копия контроллера, а фактические RTL-компоненты
и соединяющие их инварианты. Стрелки ниже означают передачу обязательства,
не независимость каждого доказательства от остальных:

```text
CPU/X → admission + ID FIFO → ordered XPM → fast payload → E → ordered XPM → ID join
            два общих кредита           ↑       │                       │
                                       frame    └─ ERR → generation/history
                                                        ↓
          местный same-edge veto ← candidate/CRC/cache ← slow rule/timers
```

| Узел | Проверяемое свойство | Отдельно принято/доказано |
|---|---|---|
| `prove_backend.py` | Все смысловые выходы E совпадают с `registered/e_backend_registered.sv`; atomic busy, ERR, release и данные, normal/prevalidated | Двоичные входы, начальные значения RTL; аналоговые окна отдельно |
| `prove_components.py` | Счётчик эквивалентен +1/насыщению; фазы/обязательные слоты/подготовка/lock; настоящий production-width slow_rule | Контроль frame усилен произвольным must_execute; реальный warmup/mod3 доказан отдельной частью |
| `prove_history.py` | Фактические два регистра сохраняют source timestamp и уже увеличенное поколение | +1 обеспечено предыдущей леммой; ordered event FIFO — vendor contract |
| `guard_proof.py` | Cache/подготовленное разрешение относятся к текущему поколению; same-edge invalidate/loss/fault запрещает LOW | CRC может произвольно принять пакет; это усиливает свойство поколения, но не доказывает CRC |
| `prove_candidate.py` | Неизменность128 бит payload, выравнивание18 стадий, target и cache-tag | Проверка одного пакета не пересекает следующий beacon; ниже выведен запас времени |
| `check_crc.py` | Фактические sender/byte/pipeline и сравнение относительно `zlib.crc32` | GF(2)-аффинность проверена структурой полинома/XOR; ноль и128 базисных векторов покрывают все payload, ещё проверки ошибок |
| `prove_chain.py` | Фактические capture/prepare/grant/response, полные данные и ERR, ordered exactly-once | Календарь и E по леммам; ordered транспорт; произвольное удержание ответа |
| `prove_join.py`, admission | Полный64-битный ID, owner, данные, не более двух общих кредитов | Ordered metadata FIFO и response channel; кредит возвращается только при внешнем consume |
| `prove_transport.py` | Фактическая handshake-обвязка не теряет/не повторяет payload при любых междоменовых чередованиях | Декларированная цифровая модель XPM; payload-независимость управления позволяет побитовое доказательство |
| `prove_progress.py` | Потребление → свободный handshake≤80 быстрых фронтов для обеих ориентаций5:1 | Непрерывные часы, цифровой3-stage sync, до следующего запроса; не аналоговая граница метастабильности |
| `prove_map.py`, тест полного домена | Биекция/покрытие `(w,h)↔A_x16`, x8-byte lanes не наложены | Условный W32_seq+H_low, не заводская карта |

Машинные итоги — [outputs/proofs](outputs/proofs). Обычные случаи доказаны;
мутанты имеют достижимые контрпримеры. Неразрешённые оставшиеся свойства
некоторых **мутантов** не объявляются доказанными; одного контрпримера
достаточно для их отклонения. `permit-reachable` и `consumption-reachable`
намеренно утверждают невозможность полезного перехода и получают контрпример,
проверяя невакуумность. Это не ошибки нормального RTL.

### Generation64: факторизация без скрытого ограничения ERR

Два прямых solver-прогона полной64-битной guard-модели не завершились в
заданное время. Вместо повторения одинакового перебора использована более
сильная побитовая проверка. Из фактического RHS `generation_equal` SAT
доказывает: все четыре16-битные части равны ⇒ каждая из64 позиций равна.
Затем gate разрешает пакет уже при совпадении одной выбранной позиции;
остальная логика invalidation, lease/cache,18-stage установки и подготовки
остаётся фактической. Такой gate пропускает **больше**, а не меньше пакетов.
Индукция доказывает сохранность этой позиции; все позиции имеют одинаковую
copy/equality-рекурсию, поэтому аргумент применяется к каждой позиции.
Поколение может произвольно изменяться на invalidate — сильнее реального +1.
Не предполагается ограниченное число ERR; насыщение исключено отдельным
10-летним верхом числа fast-фронтов. Ни runtime reset, ни сброс Q-бюджета нет.

### Как получен общий предел, а не набор компонентных трасс

Реальный frame задаёт8 control-слотов по164ξ, application reservation196ξ,
frame1568ξ, ka3 и freeze320ξ. E всегда заканчивается внутри164ξ; приложение
готовится до своей атомарной операции. Frame-lemma запрещает наложение grant
и доказывает устойчивость `prepared_word`/IO-address во всём busy.

При общей огибающей burst1 и10k/s соседние внешние поступления разнесены
не менее100 мкс. От initialized idle сумма входа **до eligible**, календарного
ожидания, приложения, ответа и100 нс backpressure укладывается в T135-r4
2,778069624 мкс с10%. После consume весь четырёхфазный хвост и три FWFT
очереди/кредит возвращаются в idle≤581,0058 нс; резервируем1 мкс. Сумма
<100 мкс. Индукция по внешним поступлениям поэтому обосновывает начальный
idle для следующего запроса, а не предполагает его только из двух кредитов.
Для перегрузки сохраняются safety/credits, но не3 мкс.

История: ERR не чаще одного на164ξ, loss после sync имеет burst3 и не более
2002 переходов за срок по действующему сценарию. FIFO512, расчётная
occupancy с запаздыванием flags≤275. От исходного фронта (с loss CDC) до
обработанной истории, доставки кандидата и применимого freeze — верх
9,618566490 мкс. Когда новые события продолжаются, местный FAST действует
сразу и LOW не разрешён до совпадения processed_generation. Кандидат
target=f+2; roundtrip≤600,506 нс < минимального frame1567,98432 нс, поэтому
не пересекает следующий beacon. Его4-битная frame-lease не смешана с64-битным
поколением; старый lease не переживает полный оборот frame-tag.

Точные рациональные выражения — `bounds.py` и прежний неизменённый
`integrated/bounds.py`; теоретические основания общего сервиса — T135 r4.
Этот расчёт не доказывает новую Q(T) и не переносит цену на иной поток.

### Общие зависимости и действительно независимые части

Yosys/ABC, извлечение фактических RTL-фрагментов и `pdr_check.py` общие для
формальных прогонов; они не являются независимыми oracle друг для друга.
Модели XPM в safety и progress общие. XPM_FIFO — доверенный ordered/FWFT
контракт, а не повторно доказанные BRAM/transistor internals.
Отдельные арифметические/событийные основания: старый Python E reference
для трасс (не импортирует новый backend), ghost sequence/ID queues,
арифметическое x8→x16 отображение, zlib CRC, рациональный паспортный
I/O-checker и независимая pad-level SRAM модель. Совпадение с ними не
устанавливает физическую группировку или радиационную применимость.

Соглашение о3-stage цифровом разрешении стандартного CDC — явная инженерная
предпосылка временных верхов. Вероятностная физика метастабильности и
неограниченная остановка часов не включены в детерминированный10 мкс.
Конфигурация выбранной точки статична при elaboration; runtime config-порта
в выбранном top нет. Обновление параметров требует нового квалифицированного
старта вне рабочего горизонта. Не заявляется проверка произвольной смены
конфигурации на ходу или бесплатного сброса накопленного бюджета.

### Внешние окна, а не фиктивные синхронные4 нс

Все значения ниже — номинальные ns от GO; их сохранение доказано miter:

| Переход | Первая часть | Вторая часть приложения |
|---|---|---|
| CE/OE active → захват данных/ERR → OE off | 4 →60 →64 | чтение96 →152 →156 |
| Адрес второй части | — | read92; write148 |
| DQ drive → WE low → WE high → drive off | 92 →92 →132 →140 | write152 →160 →200 →208 |
| Логический release | R92; E148 | read184; write216 |

Read-to-drive28ns > паспортный tHZ18ns с учётом routed/board разброса;
WE high заканчивает запись при остающемся CE low, OE high. Поэтому для
этой циклограммы применим tPWE35ns, не особый43ns случай OE-low.
tAA/tACE45ns распространяются на данные и ERR; tDOE22ns; tSD25ns;
tHA/tHD/tSA0ns; tRC/tWC45ns. Не придумывается положительная нижняя задержка
выключения SRAM: для input hold считается, что данные могут исчезнуть сразу
после самого раннего выключения OE/CE.

Из финального DCP извлечены **все17 input и41 output**, Slow/Fast,min/max.
Глобальные extrema намеренно составлены без CPR-кредита: input0,211…1,508ns,
output1,016…3,787ns, clock spread0,916ns, setup0,012ns, hold0,331ns,
uncertainty/jitter0,566ns. Каждый печатный параметр дополнительно расширен
наружу на0,001ns; арифметика рациональная. Паспортное время SRAM45ns не заменено
нулевой задержкой. Формулы и все20 неравенств — `check_io.py`/`outputs/io.json`.
Минимальный запас0,346600ns у импульса WE; input hold≥3,613960ns;
commit ремонта заканчивается минимум за10,797160ns до верхней границы E.

Сверка DS187 именно PL, не PS SMC/MIO: для HR LVCMOS33_F8/−1C таблица52
даёт TIOPI/TIOOP/TIOTP=1,41/3,12/3,13ns, таблица53 TIOTPHZ=2,37ns,
таблица57 TOCKQ=0,56ns, таблица56 D setup/hold=0,01/0,33ns. Последнее
hold требование консервативно заменяет меньший routed arc0,191ns и вместе
с outward rounding даёт0,331ns. Табличные выходные значения относятся
к reference load (Table55), не автоматически к15pF. Полный actual routed
path использует15pF, package и оба corners; составляющие из таблиц **не
складываются повторно** поверх него. Численных паспортных min для этих
путей нет; ранние фронты получены из min speed-file arcs, а не из типовых
или максимальных значений паспорта. Дальнейший перенос на плату требует
сохранения диапазонов SI/нагрузки, а не объявления reference-load типовым.

`board_sta.tcl` проверяет внутренние paths и бюджеты PL input2,5/output5ns;
`inspect_io.tcl` открывает этот же DCP без изменения placement, извлекает
clock insertion/setup/hold и не сохраняет изменённые диагностические
ограничения обратно. Его every-edge I/O slack **не является приёмкой**.
Приёмка интерфейса — фактическая фазовая композиция с паспортом.

Часы: реальный MMCM от100MHz генерирует250/50MHz. Предполагаются
ξ∈[0,99999;1,00001]ns и разброс пары событий≤0,5ns; это не доказано для
штатного Fox-осциллятора. STA сохраняет0,5/0,1ns uncertainty, дополнительно
учитывает tool jitter. Данные SRAM не являются асинхронным событием CDC:
их устанавливает выдержанная CE/OE циклограмма, ERR захватывается тем же
проверенным окном; loss/start проходят стандартные XPM.

### DRC/CDC disposition

- `PLBUFGOPT-1`: post-route phys_opt создал fast_replica→fast BUFG.
  Это неоптимальная цепь, не отключённый timing path. Фактическое дерево
  входит в setup/hold/pulse-width и во внешнюю композицию. Дальнейшее
  искусственное удаление ради отсутствия предупреждения не требуется.
- `ZPS7-1`: демонстратор не инстанцирует PS7. Генерация boot/bitstream и
  запуск на ZedBoard не выполнены; перед таким запуском требуется platform
  configuration. Для fabric post-route результата не заявляется ARM/PS.
- Три WRITE_FIRST advisory: остаётся стандартный XPM FIFO с vendor-контрактом
  защиты пустого/полного состояния и корректного FWFT. Проверена обвязка
  и реальная vendor simulation, не внутренности BRAM. Самовольный переход
  WRITE_FIRST→READ_FIRST не произведён.
- `report_cdc`:16 информационных CDC-3,0 warning/critical. Gray-pointer и
  handshake bus-skew ограничения выполнены; минимум по указателям2,931ns.
  Все12 категорий check_timing нулевые. Два ignored exception — vendor
  async-reset paths, физически отсутствующие при этой конфигурации.
  Пользовательских false paths, скрывающих внутренний дефицит, нет.

## 3. Что не установлено

Не выполнены физические испытания, квалификация часов/адаптера, подтверждение
реальной ECC-пары и D*, boot/ARM. Не доказана физика vendor CDC/BRAM.
Прямой монолитный64-битный guard-proof имел timeout; он заменён описанной
композицией, не засчитан успешным. Более ранний абсолютный E→physical
монолитный miter тоже не завершился; используется цепь прежнего принятого
E→registered доказательства плюс новый registered→physical miter и независимые
E-трассы. Нет универсального ограничения приложения вне заданной огибающей,
энергетического или полного экономического вывода. Эти пределы не скрыты
успешным STA и не расширяют принятую научную область.
