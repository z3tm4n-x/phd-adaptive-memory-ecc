## Что именно ограничено

- OOC clocks4/10/8/10нс; jitter0.05нс для каждого, uncertainty setup0.5/hold0.1нс.
  Они **ASSUMPTION**, не паспортная точность/измерение осциллятора ZedBoard.
  XDC предполагает внешние BUFGCTRL_X0Y0…X0Y3 через HD.CLK_SRC; сами
  clock buffers/MMCM отсутствуют в OOC. Их нули в resource report не означают
  нулевую цену реальной системы. Generated clocks ещё не реализованы.
- Все виртуальные порты имеют min/max IO delays0.1/0.5нс своего домена.
  Это не45нс SRAM и не трассы FMC. `HD.PARTPIN_LOCS`/pads для этих портов не
  назначены, поэтому внешние сегменты не маршрутизированы. `check_timing=0`
  для отсутствующих ограничений не доказывает физического покрытия SRAM IO.
- 14 адресных false paths только к первому FF toggle/fault. Остальные FF
  синхронизаторов проверяются обычным setup/hold. Gray: max4нс и консервативный
  общий skew2нс по обеим копиям. Stable request max8нс, response к виртуальному
  endpoint max4нс; обоснование минимальных12/16нс — PLAN. Datapath-only
  исключает обычный hold именно здесь; удержание обеспечивается протоколом.
  Глобальных inter-clock false paths/clock groups нет.
- Slow/Fast, **оба min/max**, production speed file1.12 от22.11.2019.
  Коммерческий диапазон0…85°C и VCCINT0.95…1.05V — область DS187, не
  фактическое измерение. `set_operating_conditions commercial/maximum/85°C`
  настраивает power estimation, не определяет эти STA corners.
- `platform/config.json` сохранён как исходный preflight-паспорт633dae4.
  Его прежние null не заменяют новые clock constraints и фактические отчёты.

CDC report **не очищен waiver-ами**: у обоих имеются 1042 CDC-1 Critical,
14 CDC-3 Info, 2 CDC-6 Warning, 1164 CDC-15 Warning. Стабильные payload/derived
control cones требуют композиционного обоснования; PDR RPC сам по себе
не снимает замечания к настоящим endpoints. Gray: у -1 общий skew 2.034 нс
при цели 2 нс, дефицит 0.034 нс; у -2 skew 1.511 нс, запас 0.489 нс.
Ограничение общее для обеих копий CPU/X: его нарушение не тождественно
нарушению отдельного канала и не является оценкой вероятности CDC.
Инструментальная DRC предупреждает об отсутствии PS7; PS/ARM в задачу не
добавлялись. Трассировка внутренних routable nets у обоих завершена без routing
errors; наличие физически непривязанных портов раскрыто отдельно.

## Правки и регрессия

1. Gray хранится в FF уже закодированным: устранён комбинационный encoder
   после бинарного счётчика. На фронтах значения/латентность прежние.
2. Порог следующей заявки вычисляется при предыдущем capture; overflow
   означает, что никакая следующая unsigned64 метка не удовлетворит интервалу.
   Убрано переменное64-битное вычитание из same-edge ветви alarm. При двух
   captures прежний приоритет последнего присваивания источнику1 сохранён.

60 unit tests,49 тестов А;185 Gray границ,163 границы actual core spacing;
мутант с потерянным overflow отвергнут. Два тождества unsigned64 доказаны SAT
в отдельном арифметическом miter — не выдаются за proof всей очереди.
Прежние E24/k43, RPC PDR при256/97 и416/32,352010 integrated edges и
отрицательные контроли прошли. `integration.json` побайтно совпадает с633dae4.
Времена E148/write32216, резервы164/240 и календарь не изменены.

## Точный остаток и два пути

Полные3нс/4нс/2нс, E/observed-write/CDC с10% **не подтверждены**.
Требуются SRAM/FMC pad wrapper, actual IO min/max/load и turnaround;
условия адаптера нельзя выдавать за измерение. У combinational CE/OE/WE/drive
ещё нужно исключить физические hazards, сохранив циклограмму: RTL-фронтовые
тесты сами этого не доказывают. Плата/ревизия/J18 не осмотрены, source clock
ξ/edge-bound не квалифицирован, защищённое начало остаётся внешним start_ok.

Остаётся формальная композиция реальной очереди/endpoint/календаря/E,
перечисленная в INTEGRATION §3. Выход1: адресно разнести широкую проверку
конфигурации/меток и fanout управления, сохранив приоритет ERR, абсолютный
grant и доказанные задержки CDC; затем повторить250МГц и физические pads.
Выход2:200МГц, но **только с полным новым временным расчётом/календарём**;
нынешний отрицательный slack не обещает успеха простой смены clock.
Это инженерный checkpoint, не предложение заменить принятые научные входы.
Main/А/T104-budget/T110/T114 не менялись, В/Г и отдельный Reviewer не запускались.

Правило HD.CLK_SRC сверено с [AMD UG905](https://docs.amd.com/r/2022.1-English/ug905-vivado-hierarchical-design/Context-Constraints);
фактические команды исполнялись в2025.2. Для запуска на плате одного OOC
clock context недостаточно.

## Повтор и снятие блокера

В Ubuntu/WSL, из корня checkout:

```sh
vivado-wsl -version
python3 -B experiments/t104-rtl-resume/platform_probe.py --write
```

Можно задать `--vivado <executable>`. Probe только запрашивает версию и parts;
ожидаемый exit Vivado=2 при зафиксированном блокере. Не трактовать этот exit
как провал timing. Лог/журнал остаются в `.build/platform-probe`; компактный
отчёт включает их происхождение. Обёртка выдаёт предупреждение en_US.UTF-8,
но Tcl исполнился и оба запроса вернули определённый результат.

Найден локальный установщик
`/home/z3tm4n/tools/Xilinx/.xinstall/2025.2/xsetup`; прочитана только `--help`.
Он поддерживает добавление устройств через Add. EULA не приняты, установка
и загрузки не запускались. Два пути: добавить Zynq-7000 support в2025.2
или предоставить другую установленную Vivado с обоими exact parts. После
этого повторить probe; наличие Kintex/Artix не повод заменять выбранную FPGA.

Устройство само по себе не закрывает все входы. Следом нужны проверенные
clock/generated-clock constraints, declared uncertainty/reset, OOC-контракт
всех портов, SRAM/FMC wrapper и конкретные min/max/load-допущения.
`vivado_ooc.tcl` пока лишь guarded flow; он ещё не выполнен до post-route.
Полный XDC не объявлен готовым. Нельзя blanket false-path скрывать Gray
или stable bundled buses. Отчёты должны отдельно проверять внутренние3нс,
выход4нс/возврат2нс, corners setup/hold и 10% полного E/write/CDC/очереди.
Положительный внутренний WNS на4нс этого не заменяет.

Если последующая проверка -1/250 не пройдёт, остаются две разрешённые
ветви:200МГц **с новым полным календарным расчётом**, либо локальный pipeline/
упрощение при250МГц и семантическая регрессия. Сейчас оснований выбирать
между ними ещё нет: аппаратный timing не измерен. PS/ARM и этапы В/Г не начаты.
