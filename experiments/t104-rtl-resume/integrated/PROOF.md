# Состав проверки и общий временной договор

## 1. Действительно соединённые пути

```text
CPU/X → общий admission2 → payload FIFO/XPM → локальный app slot → E
   └─ ID/owner FIFO50 ───────────────────────────────────────────┐
                    E release → return XPM/FIFO → held response ┘
E ERR / loss transition → generation64 + местный veto
                       → history FIFO512 → правило/таймеры50
frame beacon f → XPM → (processed generation, LOW, target f+2, CRC)
               → XPM → проверка/lease cache → freeze → local CONTROL → E
```

Внутрикадровые CONTROL не проходят медленный handshake. Приложение не делит
транспорт с кандидатами. У каждого полного запроса один ID/owner остаётся в
slow FIFO до фактического потребления ответа, включая исполнение и held reply.
Два ingress-порта имеют общий лимит2, CPU получает приоритет при совпадении.
Приняты только выровненные read32/observed-write32, mask≠0, word<W; нет ARM/AXI.

E и source-staged XPM-handshake переиспользованы побайтно из eab470d. Их прежнее
29-property all-input доказательство эквивалентности и legal-go специализация
сохраняют область; это не повторно выполненное новое физическое доказательство.
Внутри E нет нового такта. Source snapshot/preparation и reply transport находятся
вне grant→release; новый register начального reset в clocked_top — до qualified start.

## 2. Что доказано и что проверено трассами

`prove.py` инструментирует настоящий RTL, не копию переходов:

- Counter:8byte max-flags равны reduction-AND соответствующего байта; value'
  равно value+1 либо value, насыщение/инициализация. SAT-индукция на64битах.
- Calendar: независимая ghost-фаза0…391 и явная таблица сопоставлены всем
  локальным countdown/позициям/ring; зарегистрированные due/execute совпадают
  на нужных фронтах. Must-execute абстрагирован произвольным битом: доказательство
  safety охватывает более широкий класс. Начальная фаза при !running явно
  входит в инвариант; это assert, не дополнительное assume.
- Отдельный production-W524288 warmup/mod3 доказан PDR: decrement только на
  freeze, первый проход и каждый третий слот обязательны. Совместно леммы
  восстанавливают действительное must-execute. Решение хранится до своего
  start; поздний alarm его не переписывает.
- Rule: переходы processed generation, source timestamp, NW/NH/NR, equality
  и monotone fault; индукция. История повторов/пропусков поколений вызывает
  fault/FAST, а не присваивание последнего fast-ID без обработки.
- Guard: произвольные доставленные пакеты, произвольное CRC-accept, снятое
  tag-rejection. Это усиленная проверка **поколения**, не proof CRC/tag/liveness.
  Поколение в окружении меняется только вместе с местным invalidate, но может
  принять любое64битное значение. Каждая LOW-line имеет ghost G_line=G_current;
  prepared LOW имеет то же свойство; на invalidate/loss permit=0 на том же фронте.
- Admission: действительный prefix executor с FIFO-count контрактом. Инвариант
  credits=число metadata,0≤credits≤2; pop только при consume; две ready не
  могут быть активны одновременно. Доказательство не предполагает, что физический
  return payload всегда верен: это отдельное обязательство.

Физически64бит G_line не копируются в каждую line. Инвариант guard делает
`cache_low && (G_line==G_current)` тождественным `cache_low` в каждом достижимом
состоянии; то же для prepared generation. Поэтому удаление этой избыточной
копии эквивалентно полной64битной проверке, **не обрезание поколения**.
В source/history/candidate/snapshot/comparison сохраняются все64бита; сравнение
разбито на четыре16битных, intervening event аннулирует его результат.

Метка target modulo16 — отдельная сущность. У4direct-mapped frame-lines индекс
кодирует2младших бита, хранятся2старших. Пакет f обслуживает f+2; flight≤1мкс,
повтор tag не ранее25.087749мкс. In-contract roundtrip завершается до следующего
beacon. Ни произвольную задержку, ни runtime reset этот договор не допускает.
Fault на оставшийся pending beacon не объявлен однокадровым watchdog in-flight.
Проверка frame identity/CRC на полных трассах и условная граница flight не
выдаются за отдельное unbounded доказательство vendor CDC/метастабильности.

Проверяющий `check.py`: Python E, независимая абсолютная формула календаря,
отдельная целочисленная реализация правила, порядок/owner всех ID, каждый pin
на каждом занятом фронте, exact history packets, generation и Python CRC32.
Используются реальные XPM-модели Vivado. Общие зависимости честно сохранены:
ETransaction/ServiceConfig — прежний независимый эталон; simulation использует
тот же HDL/инструмент, не является вторым физическим SRAM-прибором.

Трассы WB4/NW40/NH80/NR130/PAIR200 позволяют наблюдать LOW/восстановления/много
оборотов tag. Production defaults не меняются. Отдельный clocked-top тест
использует настоящий MMCM и все production параметры;180секундную выдержку
он не симулирует. Её переходы охватывает индуктивная проверка таймеров.

Полное no-loss/no-repeat всей payload-цепочки проверено трассами. Для общего
доказательства нужны ordered/exactly-once контракты XPM и композиция всех
in-flight состояний с E. Индукция по двум кредитам сама по себе этого не доказывает.
Сохранены неудачные попытки: первоначальный monolithic calendar PDR дал undecided;
включение ghost-фазы/начального состояния замкнуло индукцию. Старый formal mutant
календаря мог остаться undecided; реальный trace-mutant frozen skip отвергнут.
Точный статус каждого финального proof — verification.json, не число запущенных
проверок. Непрохождение/timeout не переименовываются в доказательство.

## 3. Всеобщая условная граница очереди, а не выборочный максимум

Единицы далее нс. ξmin=.99999, ξmax=1.00001, размах фронтов J=.5.
Условие clocks/startup: постоянные250/50 от одного MMCM; vendor CDC имеет
оговорённое цифровое продвижение после инициализации. Аналоговая метастабильность,
срыв PLL и runtime reset не объявлены исключёнными математически этой моделью.

ERR публикуются только CONTROL/observed-write, с источниковым разнесением≥164ξ;
loss меняется не чаще одного slow edge. За миссию T135 допускает≤1001loss-rises,
следовательно≤2002переходов; дополнительной квоты ERR нет. При совпадении причин
одного fast edge пакет сохраняет ERR и loss и получает один новый G. Это не
объединение наблюдений разных фронтов. Пары ERR сравниваются по source timestamp,
не по времени вычитки очереди.

Поток после CDC может сгущаться. Для любого интервала t≥0 взят верх

`A(t) = min(2002, 3+t/(20ξmin)) + 1+(t+J)/(164ξmin)`.

3 учитывает spread loss-CDC≤36.500360нс, меньше двух slow периодов. Время
prefix L=212.502120нс включает3fast стадии и10slow тактов на pointer/FWFT;
service C=20ξmax, ещё один C оплачивает использование обновлённого состояния.
Это консервативные цифровые пределы для3FF synchronizers, FWFT/read latency0,
постоянного read-ready; отдельный formal vendor-FIFO WCET не предъявлен.

`B = sup_t [A(t) - max(0,(t-L)/C)] = 258.4485159661`.

Добавлены16 ещё невидимых read-pointer обновлений: `ceil(B)+16=275<512`.
Супремум проверяется в0,L и точке насыщения loss: функция кусочно-линейна,
после насыщения slope ERR ниже service. Никакой неявной 65535-ERR остановки нет.

`d_history ≤ L+C+sup_t[C A(t)-t] = 5189.022209025`.

После последнего нового события: loss→veto36.500360 + history + ожидание
следующего beacon/первого target-freeze `(3*1568-320)ξmax+J` + dispatch8ξmax+J.
Итого **9618.566489025нс**, всё внутри10мкс. При продолжающихся событиях
местный FAST применяется сразу; это не обещание свежего LOW вопреки новой истории.
Таймерные переходы также получают ближайший f+2 кандидат в этом бюджете.

Самого полного поколения за10лет не больше числа fast edges
`ceil((315576000*1e9+.5)/(4ξmin))+1 = 78894788947889481 <2^57`.
Насыщение64 исключено в данном горизонте без runtime reset и без новой
вероятностной добавки; настоящие loss/recovery остаются в прежней цене.

## 4. Кандидат и приложение

Верх кандидата480ξ+J включает beacon staging16ξ, запас request-XPM120ξ,
slow обработку40ξ, source capture40ξ, candidate-XPM24ξ, check/CRC84ξ,
installation8ξ и48ξ остатка. С10%528.555280нс<1мкс. Полный roundtrip обоих
каналов с acknowledgments ограничен600ξ+J<1568ξmin; новой очереди по кадрам
нет. Эти тактовые подсчёты опираются на постоянные clocks/ready и штатные
handshake стадии; трассы отдельно дают максимум276нс, не подставленный в верх.
Начало подготовки f+2 за3136ξ до target, раньше требуемых1440ξ.

При idle app-канале вход:20ξ sampling +80ξ slow FIFO +40ξ source stage +24ξ
fast CDC +8ξ eligibility =172ξ+J. Выход:4ξ release capture +8ξ source stage
+120ξ CDC +80ξ destination FIFO +20ξ exposure =232ξ+J. Ready backpressure100нс
отдельно. Средства обработки ARM/другого внешнего master здесь не реализованы.

Совместный burst1/rate10000/с означает межприходный интервал≥100мкс. При пустом
старте и верхе ответа<3мкс все transport queues освобождены до следующего
допустимого первого VALID: этим замыкается предпосылка idle, не выбором редкого
потока после испытаний. Вне этой огибающей credits2 сохраняются, срок не обещан.

С внешними320/320, ожиданием одного кадра и более дорогой observed-write:

`d_response ≤ 1.1*(320+1568ξmax+.5+217.002160+320+100)`

`=2778.069624нс`.

Для любого окна Lw=1e6нс, расширения Lw+3000:

`bus ≤ [8E*(Lw/(1568ξmin)+2) + 209+.0001*(Lw+3000)`

`       +217.002160*(1+10000*(Lw+3000)/1e9)]/Lw`

`=0.7627470464315872`.

В CONTROL каждый слот оплачен E независимо от LOW/ERR; приложение и X входят

Стресс STRESS1 с1400нс удержанием ответов сознательно исключён из этой строки.
Lifetime/quiet means и обычная доступность T135 остаются обязательными; их
17.484321% не заново сертифицируются этим bound-калькулятором.

## 5. Внешний интерфейс и почему нет STA PASS

SRAM002-20054Rev.*F:Figure5p6,Figure6p8,tablep10/notes28–34.
CY62167GE30-45ZXI:45нс address/CE→data/ERR; OE22нс; HZ18нс; pulse35нс,
data setup25нс/hold0;30pF — **паспортная тестовая нагрузка**, не измерение
адаптера. Условный write pulse margin.49776нс показывает, почему нельзя
подменить неизвестный pad skew нулём. Регистры WE/OE убирают RTL age-decode,
но не доказывают pad waveform автоматически.

Предложены42уникальные FPGA/FMC/TSOP назначения. Здесь FMC обозначен именами
сетей master XDC, не номерами контактов разъёма;
полная схема переходника и соответствие контактам ещё не предъявлены.
Документы не дают проверенной функции `word,alias→A[19:0]`:
X/Y из AN88889 — условие примера, не A0-пара.
Чистый старт всего массива и clock-failure containment также внешние условия.
Нет молчаливой вставки `2*word+alias`, SDC/flight claims или программирования платы.

Финальный OOC включает правило, календарь, LOW, generation, очереди и MMCM,
но порты SRAM/app виртуальны, max/min=.5/.1нс. Ни false path всего домена,
ни снижение uncertainty не добавлены: только штатные XPM exceptions.
15CDC-3 информационных цепей;12категорий check_timing0 — не timing PASS.

История структурных попыток: широкое событие→FIFO (staging), target arithmetic→
приём (предрасчёт), широкий CRC-enable (always-clocked byte pipeline),
calendar→beacon enable (snapshot), повторный FIFO-reset gating (vendor gating),
receipt feedback (checking state), wide cache tag (direct-mapped epoch),
вход reset (boundary register), soft/hard размещение E. После двух неудач
размещения не продолжен перебор seed: рассмотрена общая внешняя временная
модель. Её связь с внутренним ERR path показана диагностикой того же routed DCP.
Это интерпретация причин, не утверждение, что все остальные paths закрыты.

Остаются варианты/решение из REPORT. Для100МГц известны лишь прежние условные
R110.5011/E170.5017/read32221.0022/write32251.0025нс; новое исполнение/сетка/
очереди/STA/ΔQ не установлены. Этот резерв не подменяет выбранные250/50.
