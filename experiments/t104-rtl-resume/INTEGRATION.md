# Связанный исполнитель E: интерфейсы и пределы проверки

Продолжение от `be7342cd1b8a84fde8575091000cbc372c914673`, та же база/ветка
из PLAN. Здесь нет реализации научного правила T119, изменения Q(T) или
проектирования платы. Физический E/ERR по-прежнему входное условие T104/T114.

## 1. Разделение событий и доменов

`executor.sv` связывает новые `executor_core`, `e_backend`, календарь,
permission gate, два `app_frontend/rpc_cdc` и command receiver. Порты CPU/X
симметричны, CPU выигрывает равенство времён; вторым источником может быть
заранее учтённый DMA/служебный инициатор. Это **общая** огибающая предложений,
не два независимых burst=1. MMIO/телеметрия X_work остаются отдельным условием.

| Событие | Что происходит / что ещё не произошло |
|---|---|
| Первый VALID | Начало внешнего ожидания; при занятом кредите payload держит инициатор |
| `app_ready && app_valid` на source edge | Захват стабильного запроса, не запись SRAM |
| Request crossing | 3 ступени toggle-sync, захват core на4-м фронте; CRC/ID/поля проверяются целиком |
| Календарный grant | Только+1312ξ кадра; начало общего lock двух alias |
| Release | Запись физически закончена по условной циклограмме; только сейчас запускается ответ |
| Source reply/ACK | Ответ пересёк домен и получен; lock уже освобождён |
| Return credit | ACK вернулся в память и затем в source; только теперь следующая заявка этого источника захватывается |

По одному месту CPU и X: копии payload в регистрах не являются новыми
независимыми местами. В стоимость входят выполняемый запрос и held reply.
Не принятый VALID может ждать снаружи, но считается в огибающей от его первого
появления. Его отзыв/изменение диагностируется, а не превращается в новую заявку.
Слишком долго удержанный ответ сохраняется; watchdog не отменяет запись.

Первое VALID отмечается аппаратно нижней оценкой времени из3-stage Gray
crossing счётчика core-edge. Полные64 бита tick не пересекают домен как обычная
бинарная шина. При заявленных часах/подфазах отставание ограничено; проверка
трасс допускает44ξ, диагностический интервал использует48ξ запаса. Поэтому
монитор spacing<5508ξ — необходимая проверка, **не** сертификат внешней
огибающей180000/с. Она не доказывается только наличием монитора.

Снятие VALID после handshake нормально. Ready зависит от законности предложения;
источник не должен ждать Ready перед выставлением Valid. Request ID64 строго
возрастает для каждого источника; испорченный/replay пакет не перематывает
принятый ID. CRC32 — reflected0xedb88320, init/final XOR0xffffffff; эталон
использует независимый zlib и известный вектор123456789→cbf43926.

Request packet —28little-endian bytes: meta32(kind1:0,mask7:4),address32,data32,
ID64,first_VALID64; сверху CRC32. Ответ — ID64,data32,error1. Сам ответ
сохраняется в стабильном bundled register до ACK; физическая целостность
регистров/ответного канала относится к прежней δexec, не доказана CRC команды.

Полная команда —48bytes: mission32,config32,sequence64,issued64,not_before64,
deadline64,expires64; затем CRC32. От **захвата полного mailbox** до gate:
3sync+capture+3CRC chunks+publication=8core edges≤32,500320нс условно.
От внешнего первого VALID дополнительно возможно ожидание source-edge
≤10,500100нс; это не скрыто внутри32,500320. Отправитель обязан учитывать его
при выборе срока. Опоздавшая команда всегда отвергается, окно LOW не расширяется.
Правило/его доставка до mailbox остаются этапом В, не реализуются здесь.

## 2. Старт, параметры, reset

Memory-domain конфигурационный порт —12полей по32бита. Адреса0…11:
config_ID00104114hex, W,38,ka3,g196,c164,lead320,batch8,app_offset1312,
app_write_charge240,app_read_charge208,read_charge104. Требуются все поля,
совместимость со статическим WORD_BITS/INVERSE и отдельный start_ok.
Одновременные write/commit, неизвестные адреса, старый write-charge208,
неполный комплект и повторный commit не запускают новую миссию.

Это порт того же memory-clock, **не готовый AXI/AHB MMIO/CDC wrapper**.
До arm все инициаторы и mailbox должны быть пусты/неактивны. start_ok означает
подтверждённые условия начала T104/T110 (включая K0≤1, отсутствие прежнего
E_cap/pending), а не выполняемую здесь очистку памяти. Bank после arm неизменяем.
Параметры научного правила не загружаются под видом этих сервисных полей.

Soft reset сохраняет фазы, очередь, CDC toggles и pending. Признанная ошибка
интерфейса вызывает sticky diagnostic и запрет будущих LOW; уже frozen skips
не переписываются. Такой консервативный sticky-режим не предъявляется как
реализация научного восстановления/hold T114: она требует согласованного
будущего правила. Power-cycle/потеря такта не являются допустимым новым началом.

## 3. Условный аргумент для рабочего W

Следующие доводы — композиционный разбор переходов при исправной двоичной
логике и заявленных временах. Это не единая машинная индукция всего netlist.

1. **Календарь.** Начальные next_start=0,pos=0. При pos<7 прибавляется164,
   иначе420 и pos=0. Индукцией получается s_j=1568floor(j/8)+164(j mod8).
   Состояние не меняется от длительности операции/очереди; пропуск увеличивает j.
   Freeze имеет ту же рекурсию со сдвигом320. Начальные0/1 обязательны;
   320<2·164, поэтому четырёхместное кольцо не затирает неисполненное решение.
   WORD_BITS влияет только на перестановку/начальные W mandatory; 3·174763=1
   modulo524288. Тест проверяет всю перестановку, а не только W8.
2. **Неделимость.** Grant при !busy; age увеличивается только на4. В E-block
   маска/образ/адрес фиксируются до следующего grant, reset их не отменяет.
   WE и оба alias принадлежат одной операции до её end_age.24assertions
   проверены индукцией при19-битном произвольном адресе (k43), включая
   достижимые пределы age каждого op. Поэтому предложение новой записи может
   ждать в очереди, но её SRAM-grant не предшествует release старого исправления.
   После её grant старое pending уже не может записаться поверх нового образа.
3. **Размещение.** Максимумы E148,501480нс и observed-write217,002160нс,
   edge/ξ допуски и10% помещаются в разрывы164/164/256ξ. Даже all-ERR контроль
   заканчивается до следующего grant. Это не оценка на основании редкости ERR.
4. **CDC/кредит.** Toggle request меняется только после возвращённого final_ACK;
   final_ACK возникает только после source consume. Следовательно, request_hold
   неизменен до удалённого использования. delivered запрещает второй приём;
   replied — второе формирование ответа. Response_hold неизменен до consume и
   следующей заявки. Capture/retire и send_response/retire взаимно исключены
   состояниями. Эти переходы объясняют сохранение одного обязательства на
   источник; bounded SAT дополнительно проверяет5свойств на40глобальных шагах
   при произвольных двоичных фронтах двух часов. **Машинная индукция CDC не
   замкнулась;100-step BMC исчерпал60с.** Ни один из этих исходов не записан как PASS.
5. **Очередь/ответ.** При bΣ=1 предложения разделены≥1/ρ=5555,555…нс.
   От физического первого VALID: source sampling+request CDC+один реальный
   кадр1568ξ+write+response CDC+100нс backpressure, всё с10%, ≤2148,320350нс.
   Возврат кредита занимает дополнительно≤57,000560нс. До следующего
   разрешённого предложения прежнее место свободно даже для того же источника;
   два места достаточны. Это рассуждение не разрешает два одновременных burst1.
6. **Скользящий пик.** В расширенном на E и0,5нс окне1мс не более5104начал
   контрольных операций. Посчитав каждую целиком, прибавив X_work и
   217,002160нс·(1+180000·0,001003), получаем upper79,76551260464%.
   Это независимая консервативная проверка реального1568-календаря;
   прежний принятый более слабый upper79,97480847344% не изменяется.

Точная рациональная арифметика — `contract_check.py`.10-летние ticks и j
помещаются в64бита; overflow насыщается/диагностируется, а не возрождает бюджет.
Эти доводы зависят от сохранности регистров, monotone clock и физических
верхов; generic RTL сам по себе не квалифицирует их под излучением.

## 4. Независимость и неудавшиеся попытки

`integration_check.py` сопоставляет pin-последовательность с ETransaction;
второй `MemoryOracle` не импортирует ни его, ни helpers RTL. Oracle получает
фактические WE-переходы/маски/значения, сравнивает сохранённые слова, coherent
preobservation, ERR и release. Он моделирует условную память; поведение за
первым превышением не является утверждением о физическом декодере CY62167.
Общие зависимости: stdlib, входные константы, формат трассы и Icarus.

Два многотактовых набора:5сценариев каждый;352010фронтов,7346операций,
224прикладных запроса. Inside-envelope наибольший наблюдённый ответ1835нс;
outside-envelope тест трёх быстрых предложений достигает3092нс с fault,
что не выдаётся за подтверждение3мкс. Проверяется сохранение всех ответов.
Пять разрешений включают CRC-error, replay, future activation и late deadline.
Отдельные тесты атакуют старый tuple, отсутствие start_ok, runtime rewrite,
первый VALID, изменение удерживаемого payload, адрес вне W, нулевую маску,
чужой kind и same-edge loss-before-freeze.

Три мутации отвергаются: потеря app ERR (прежняя component-сверка), отмена
pending при reset, освобождение source credit раньше ответа. Исходный RTL
не перезаписывается; мутанты/большие трассы временные, вне Git.

Backend-индукция с прежними17assertions исчерпала90с. Добавлены **доказываемые**
инварианты достижимого age/op и совпадение monitored kind, не assumptions и
не ослабление свойств; индукция замкнулась при k43.1-bit RPC k-induction до40
доказала базы, но не переход;8-bit100-step проверка исчерпала60с. Проверенная
8-bit40-step область указана отдельно. Новый код не наследует формальный
результат только по тому, что component-тесты проходили.

## 5. Что не квалифицировано / следующий вход

Нужны точные FPGA/корпус/speed grade, плата/IO-voltage/load, PLL/частоты/jitter,
pin mapping и STA constraints. В доступном PATH не найдены Vivado/Quartus STA/
nextpnr-xilinx.08.10 автор сообщил, что Vivado установлен, возможно на D.
Поиск имён vivado/settings64 в доступных каталогах D не нашёл установку;
путь/версия остаются неизвестны, не утверждается её отсутствие на компьютере.
Общий Yosys synthesis не заменяет LUT/BRAM/Fmax/post-route STA.
Особенно проверить CRC-пути, сравнения64бит и совместные dispatch/merge/ERR≤3нс.
ASYNC_REG — только атрибут; нужны размещение synchronizers, Gray bus skew,
max-delay стабильных bundled buses и физическое основание good-event/δexec.
Нельзя blanket false-path скрыть все пути между часами, включая payload.

Подготовлен `vivado_ooc.tcl`: без явно переданных part и непустого XDC он
останавливается; старый AC701 или выдуманные board constraints не выбирает.
После задания входов создаёт отдельный игнорируемый каталог, сохраняет XDC,
версию/part/SHA и отчёты synthesis/place/route, timing/CDC/DRC/exceptions.
Синтаксис команд сверён с [AMD UG835](https://docs.amd.com/r/en-US/ug835-vivado-tcl-commands).
**Сам flow в Vivado ещё не исполнен**; проверены только три остановки входного
контракта обычным Tcl8.6.12 (через Windows tkinter): нет аргументов; пустой part;
нет Vivado-команд в интерпретаторе. В Ubuntu отдельный tclsh не найден.
OOC не включает готовую pin-level плату и не присваивает
PASS даже при положительном slack: нужно проверить полноту ограничений,
отдельный предел3нс и физические входы/выходы. Пример после выбора платформы:

```powershell
$Flow = (Resolve-Path experiments/t104-rtl-resume/vivado_ooc.tcl).Path
$TimingXdc = (Resolve-Path $TimingXdc).Path
New-Item -ItemType Directory -Force experiments/t104-rtl-resume/.build/vivado-launch | Out-Null
Push-Location experiments/t104-rtl-resume/.build/vivado-launch
try { & $VivadoBat -mode batch -source $Flow -tclargs $FpgaPart $TimingXdc }
finally { Pop-Location }
```

Здесь все три переменные задаёт вызывающий по выбранной установке/платформе.

Generic registers не являются готовой радиационно-защищённой реализацией
timebase/очереди/CRC. Нет квалификации E/ERR, начального массива, MTBF,
реального CPU/X-потока, I/O-WCET и полного годового/миссионного аппаратного
прогона. Б не объявлен завершённым по bounded CDC и общему синтезу; В/Г не
начаты. Возможные следующие шаги: закрыть машинную композицию CDC/календаря
в этом же условном объёме либо, после задания платформы, выполнять привязку
и STA с её реальными ограничениями. Ни то ни другое не требует нового Q(T).
