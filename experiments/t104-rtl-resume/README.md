## Эталон до RTL

`reference.py` отдельно задаёт E/observed-write циклограммы, календарь,
атомарные разрешения и двухместную очередь с in-flight/held reply.
Все38 позиции различаются в `memory_oracle.py`, который не импортирует эталон.
Oracle реализует один допустимый остаточный сценарий E: сохраняет новые
попадания внутри операции и удаляет сохранившиеся старые при исправлении.
Это тестовый представитель условного договора, не модель внутреннего кода
или доказательство E под облучением. Историческое первое превышение не стирается.

32 data физически доступны как два x16 alias одного internal32+6. Скрытые6
позиций не выдаются на DQ и не заменены внешним SECDED(39,32). Перед app-write
снимается один full38 ERR. Первый alias всегда читает оба байта и записывает
исправленное/смешанное low16, даже при high-only запросе; второй обновляется
по своим byte enables. Маска0 отвергается до grant. Данные/ERR снимка совместны.
Последующая app-read32 не выполняет inline repair и не создаёт новых контрольных
ERR-флагов многократным чтением той же неисправленной ошибки.

Сервис E с ERR занимает148ξ, без ERR92ξ, observed write32216ξ, read32184ξ;
резервы164/104/240/208 — другие величины. Полный lock действует до release,
включая промежуток между двумя alias. Offer/буферизация — не принятие записи;
grant — начало атомарной операции; ACK потребителя — после completion/release.
Soft reset не отменяет pending и не создаёт чистую память/новый бюджет.

Календарь первых тестов: g196/c164,8 слотов, gate320, ka3; новое правило T119
не реализовано. `Permission` — уже научно разрешённая внешним правилом команда;
эталон проверяет её доставку/целостность/сроки, а не законность самого LOW.
После ERR/loss нужны восстановление канала и новая команда после hold внешнего
правила. Будущая В обязана доказать это условие; heartbeat сам LOW не возрождает.
Read-back raw clock loss делает фазовую предпосылку недействительной.

## Повтор

Из корня репозитория (Python>=3.10, проверено3.12.14, только stdlib):

```sh
python -B experiments/t104-rtl-resume/run.py
```

В среде с `iverilog`, `vvp`, `yosys` в PATH весь текущий ограниченный пакет:

```sh
python -B experiments/t104-rtl-resume/run.py --rtl --formal --regression-A
```

**Icarus12 в Ubuntu**, не13. Для изолированного выбора бинарников есть

`--write` у общей команды обновляет четыре компактных JSON только этой задачи.

Выходной успех проверяется явно,

## Граница интеграции и формальной проверки

`absolute_calendar.execute_due/word_due` и `app_due` — сигналы **до фронта**,
по которым следующий блок принимает операцию на том же фронте. Зарегистрированные
`execute_pulse/slot_pulse` — телеметрия после фронта; использовать их для grant
означало бы сдвиг на4ξ. Аналогично `e_backend.err_due` доступен до фронта64ξ,
а `flag` — после него. Проверка трасс сравнивает и pre-edge сигналы.
ERR/DQ берутся совместно в60ξ; ERR не пропускается через отдельный независимый
синхронизатор. Byte enables первой E-записи — оба байта, requested low16
смешивается с исправленным latch. Второй alias сохраняет свою маску.

`permission_gate` принимает уже доставленный согласованный снимок; в связанной
версии `command_receiver` вычисляет CRC перед `cmd_integrity`. Это не
доказательство δexec. `cold_init` исходит только из однократного arm банка
параметров при внешнем start_ok. Generic timebase и CDC реализованы;
физическая защита регистров и квалификация CDC не следуют из симуляции. В/Г не начаты.

В `formal/backend.sv` проверяются несовмещение чтения/drive, WE только под
lock, стабильность адреса/образа, отсутствие нового accept во время операции,
невозможность ранней отмены, однократность flag и завершение без владения шиной.
Прежние17assertions дополнены6инвариантами age/op и связью принятого kind:
24утверждения —60переходов и замкнувшаяся индукция k43 с19-битным адресом.
Это индукция **только E-backend**, не очереди, CDC или всего исполнителя.
Модель однотактовая, двоичные определённые входы, начальное состояние RTL;
после этого go/reset/data/ERR произвольны. Ни задержки метастабильности, ни
физические данные SRAM из этих assertions не выводятся.

Первый harness дал контрпример с `go=X/cold_init=X`: Yosys `-set-def-inputs`
покрывал только порт clk, а не внутренние anyseq. Источник локализован по
counterexample; символические сигналы сделаны настоящими входными портами,
двоичная область явно закреплена. RTL для устранения этого контрпримера не
менялся. Это не доказательство устойчивости к X/метастабильности. Временные
логи диагностики игнорируются Git; ошибка повторяется в отдельном harness,
если снова заменить входы внутренними anyseq при прежней SAT-команде.

## Суть для автора

- Сначала отделена семантика нового E от исторического clean-U.
- Новое попадание после чтения может остаться после завершения: тест это сохраняет.
- Запись приложения наблюдает ошибку до изменения данных, в том числе check-bit.
- Незавершённая запись и фаза не исчезают при программном reset.
- Контрольные примеры отвергают потерю ERR и старое исправление поверх новых данных.
- Комплект обслуживания согласован с T114; настройки правила пока не подменяются.
- Связанные очередь/арбитр/CDC/параметры проверены на ошибочных и обычных трассах.
- Индукция атомарного E-блока закрыта; весь CDC и платформенная STA ещё открыты.
