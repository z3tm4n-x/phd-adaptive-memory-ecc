# №96. Какие отказы контроллера на 64 КиБ нужно ограничить за десять лет

**Физический верх для ГСО остаётся открытым.** При сроке 315 576 000 с и всей квоте исполнения 6·10⁻⁶ суммарная средняя частота опасных исходов должна быть не выше 1,9012853·10⁻¹⁴ с⁻¹. Положительный расход на общие причины и остальные исключения уменьшает этот потолок. В цифровом опыте один переворот захваченного ERR одновременно отменил обязательную запись и дал ложный полный ноль. Отдельные одиночные перевороты исказили записываемые данные и увеличили уже выданный период с 2L до 8L. Проверка одного только счётчика этих путей не покрывает. Предлагаем защитить захват, свидетельство окончания обхода и хранение выданной команды до её использования. ## Что подставлять в квоту

W обозначает пропущенную, просроченную либо неверную по адресу, данным или временам обязательную запись. A обозначает ложный полный ноль либо непричитающийся редкий старт. Исключением считается сам ложный ноль, даже если следующее решение осталось быстрым. Недостоверный отчёт с уже пропущенной записью относится к W. Распознанный сброс с выполненной правильной записью, сохранённым календарём и своевременным безопасным продолжением относится к цене I.

Для группы первичных причин g обозначим через ν_g(t|h) частоту возникновения причины при достигнутой истории h, через p_W и p_Aonly — условные вероятности приписанного ей первого опасного исхода записи и разрешения без W. Для одного инициирующего эпизода, дающего оба исхода, используется один вклад. Если несколько повреждений нужны совместно, их объединяют в один общий сценарий либо считают в модели накопления состояний при переходе к первому исключению. Классификацию фиксируют до подстановки физических данных. Обозначим через B_проч и B_общ вероятностные верхи за весь срок для прочих и общих причин, исключённых из суммы одиночных. Достаточно

```text
B = B_проч + B_общ
    + ∑g ∫₀ᵀ E[1{доказательство продолжается} ν_g(t|h) (p_W + p_Aonly)(t,h)] dt ≤ 6·10⁻⁶.
```

Здесь учитываются последствия, возникающие до конца срока. Стойкое повреждение конфигурации с несколькими плохими выходами учитывается один раз. Формула следует из оценки вероятности хотя бы одного события ожидаемым числом помеченных инициирующих событий. Две причины с неизвестной зависимостью допускают верх суммы. При неизвестных исходах безопасно положить p_W+p_Aonly≤1. Для остатка δ−B_проч−B_общ≥0 средняя суммарная опасная частота регистров ограничивается величиной этого остатка, делённого на T. Уже отрицательный остаток не даёт квоты на регистры. Частота исхода имеет размерность с⁻¹, B безразмерен.

**Цена отсутствующих вероятностей.** При p=1, одинаковом поточечном верхе на бит во всех трёх классах FF и расходе всей квоты только на них требуется ≤5,83216·10⁻¹⁷ с⁻¹ на бит. Для одного пути с бюджетом всей системы, при исправном календаре и независимом от его состояния поточечном верхе частоты, можно оценить время уязвимости. Для одиночного переворота сохранённого ERR окно от +60 до +70 нс занимает за срок не более 9,919·10⁶ с на бит. Для сохранённых 16 DQ от +60 до снятия драйвера +180 нс — 1,092·10⁸ с на бит с округлением вверх. По точным значениям предельные однопутевые частоты соответственно 6,0494·10⁻¹³ и 3,4372·10⁻¹⁵ с⁻¹ на бит. Эти два потолка каждый расходуют всю квоту. Последняя цифра любого печатного округления не заменяет точное неравенство. Для точного подсчёта взяты потолок числа календарей плюс один краевой календарь, 32 768 операций на календарь и времена 11,00010/121,00120 нс с обоими фронтами ±0,5 нс и масштабом часов. В каждый потенциальный слот допущено исправление. Отдельно учитываются искажение самого захвата, входные и выходные пути и длительные нарушения. При произвольной корреляции частоты со временем обслуживания среднюю частоту за срок нельзя просто умножить на эту долю. [Арифметика и точные границы](check.py) · [Значения](results.json)

**Условный численный пример.** При опасных частотах W и Aonly по 5·10⁻¹⁵ с⁻¹, B_проч=B_общ=10⁻⁶ получаем B=5,155760·10⁻⁶ и остаток 8,4424·10⁻⁷. Допустимая суммарная частота регистров после этих двух резервов равна 1,2675235·10⁻¹⁴ с⁻¹. Эти входы до инъекций зафиксированы для проверки подстановки. Физические параметры подстановки для выбранной ГСО пока отсутствуют. [Предварительная фиксация](PROTOCOL.md)

## Происхождение физических данных

Vlagkoulis и соавт. измеряли статические сечения PL на протонах в PSI (2022, точки 30…200 МэВ) и тяжёлых ионах в CERN/GSI (LET 2,30…12,45 МэВ·см²/мг). На графике при 150 МэВ оценка порядка 10⁻¹⁴ см²/бит для FF и 6·10⁻¹⁵ для CRAM. При LET около 8,8 для FF порядок 7·10⁻⁹ см²/бит. Это приближённые отсчёты с графика, без доверительного верха. ESA каталогизирует испытание группы на XC7Z020-CLG484 (запись 374) и отдельно на XC7Z045-2FFG900 (371 и 378). Маркировка -1, ревизия и принадлежность каждой точки сводного постера конкретному образцу не указаны. Авторский архив CERN идентифицирует XC7Z020 для отдельной серии. Протонное сечение CLB FF нельзя автоматически присвоить ILOGIC, OLOGIC или целой функции контроллера. Расчёт авторов для 800 км и наклонения 98° относится к низкой орбите. [Оригинал постера, разделы PL и OMERE](https://indico.esa.int/event/439/contributions/7941/attachments/5183/8216/SEFUW_v1.1.pdf) · [Реестр ESA, строки 371, 374, 378](https://esarad.esa.int/?handler=DownloadDb%2F1000&id=324) · [Описание исходных серий](https://github.com/JVrachnis/fpga-config-scrubber/blob/9708635875dae746fe0e264b02ef30c0c81d4c81/README.md)

Ориентир для чтения единиц можно получить при моноэнергетических протонах 150 МэВ и условии, что каждый сбой любого из 273 CLB FF опасен. При принятом графическом отсчёте 10⁻¹⁴ см²/бит и полном бюджете только на них соответствующий поток равен 1,9012853·10⁻¹⁴ / (273·10⁻¹⁴) ≈ 0,00696 см⁻²·с⁻¹. Это обратный расчёт в условной геометрии пучка. Поток на ГСО и доверительный верх сечения этим способом не устанавливаются.

Для подстановки по типу ресурса r требуется верх частоты на бит λ_r(t)=∑_s ∫Φ_s(E,Ω,t)σ_{r,s}(E,Ω) dE dΩ за защитой **самой ПЛИС**, либо эквивалентная оценка по LET. Для дифференциальной направленной плотности потока телесный угол входит один раз. При интегрированном потоке соответствующее сечение должно иметь ту же геометрию. Требуются охват энергий и LET за пределами точек или верх хвостов, доверительная оценка переноса между образцами и режимами, число существенно задействованных битов конфигурации и верх общих событий с их последствиями. Пакет ГСО содержит проектные спектры за 3 г/см² и отклик **SRAM**. Он даёт задел для среды, но не перечисленные сечения ПЛИС и не совместную сроковую вероятность всех огибающих. Самая экономная следующая проверка физических данных — получить у хранителя записи 374 идентификацию образца и таблицы по видам ресурсов с экспозициями и числами событий, затем проверить перенос на локальную геометрию ПЛИС. Даже положительный ответ про CLB оставляет общие причины и ввод/вывод. [Принятый расчёт среды](../t186-ost-geo-3g/README.md) · [Тяжёлоионная работа группы](https://doi.org/10.1109/TNS.2020.3033188)

## Предложение защиты, сроки и цена

1. Сохранить уже работающую проверку фазы, ожидания, z и кандидата. На сечении L−300 нс требовать завершения последней операции от двух свидетелей. Второй независимо ведёт следующий адрес/число освобождений до 32768, липкий признак хотя бы одной выполненной записи и свою печать окончания. Сверять номер текущего прохода и последовательность именно фактических чтений/записей. Один и тот же регистр на двух входах компаратора такого свидетельства не даёт. На установке L−100 нс перепроверять согласованность и срок, иначе оставлять заранее готовый L.
2. Два раздельных регистра ERR на фронте +60 сохранят информацию о расхождении. По паре (0,1) без третьего свидетельства нельзя одновременно гарантировать обязательную запись и исключить лишнюю. Логическое ИЛИ гарантирует первую при одной потерянной единице, но может добавить ложную запись. Для неё понадобились бы согласование дополнительного времени, доверие к DQ и оценка нового окна попадания. Предлагаем три раздельные линии захвата ERR и 16 DQ, с контролем валидности каждого фронта. При одном независимом искажении выбирается большинство, расхождение портит историю. В текущем слоте остаются исходные адрес, +70 нс для формирования обязательства, +100 начала выдачи, WE#↑ в +160 и освобождение +200. Две валидные линии должны согласиться, если третья пропустила захват. При отсутствии достаточных своевременных данных нельзя подтвердить ни ноль, ни успешную запись. Неразрешимое обслуживание относится к W.
3. Продлить защиту фактически выданного периода до загрузки ожидания. Например, четыре бита кода периода хранить в расширенном коде Хэмминга (8,4), проверять при потреблении, отдельно проверять факт и epoch установки. Поправимая одиночная ошибка восстанавливает именно уже выданный период. Сброс истории готовит быстрый режим для ближайшей ещё открытой границы. При неисправимой команде до фиксации действует заранее разрешённый быстрый старт. Утрата уже принятой команды без достоверного дубликата и срока остаётся исключением. Ранее законный пропуск задним числом не отменяется. Уже начатая запись при достоверных адресе и DQ доводится до конца в том же слоте.
4. Проверена ограниченная вычислительная спецификация защиты. Для обоих ERR, трёх значений DQ, каждого из трёх каналов и 17 позиций все 306 одиночных подмен правильно восстановили образ и решение о записи. Кроме того, проверены 36 сочетаний при утрате одного захвата и 640 комбинаций условий выдачи для десяти периодов. Проверены 80 одиночных и 280 двойных повреждений установленного кода для десяти периодов. Первые исправлены, вторые обнаружены. Общий ложный ноль до разделения каналов проходит голосование незамеченным. Это проверка предложенных операций. Результат требует последующего размещения с сохранёнными копиями, проверки независимых разрешений и setup/hold, в том числе выхода DQ и избирателя. Исходный запас +5,18440 нс внешнего чтения не является запасом нового голосования. [Исполняемая проверка](check.py)

Оценка полезной разрядности добавки — 34 бита на две дополнительные выборки ERR/DQ и 4 бита на код уже установленной команды. Дополнительно предполагаются 16 бит второго счётчика завершений, один бит наличия исправления, один бит независимого подтверждения и липкий бит недостоверности. Получается **57 дополнительных битов** для перечисленных полей. В эту частичную смету ещё не входят независимый признак валидности каждой линии, защита факта установки/номера эпохи, голосование, разводка и выходной тракт. Фактические LUT, FF, время и потребляемая мощность новой реализации не измерены.

Если единичное распознанное повреждение обходится голосованием внутри штатного слота, дополнительных обращений к SRAM не требуется. В этом случае защитная надбавка к цене до первой доказательной остановки составляет не более 20,397479·I секунд плюс X для прочих занятостей. I ограничивает математическое ожидание числа **дополнительных общих интервалов** со сбросом истории, а не число импульсов fault. Стойкий отказ может затронуть несколько интервалов. В текущей версии обязанность один раз учесть старый отказ требует отдельного внимания на границе. При X=0 достаточна целая верхняя граница I≤64 863 для двукратности на проектном классе ГСО. Для архивных реконструкций исходная нижняя оценка при I=X=0 равна 1,1151. Физические верхи для I, X и совокупной вероятности исключений остаются незакрытыми.
