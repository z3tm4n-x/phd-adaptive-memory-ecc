# T72 — входы R0-A и численная проверка метода T73

## Суть для автора

Выполнена адресная передача из раздела Ж приложения T73 на **точном SHA
`7ed0f6c0770ba21f12b03493171006dd0b82cc84` (PR #78)**. Опубликованный
условный набор T73 проходит проверки для обеих защит. Более широкие бюджеты
раннего T72 при 2,5 г/см² дают риск **0,001075514 > 0,001**. Они сохранены.
Явная ревизия параметров того же правила проходит: риск ≤0,000997686 /
0,000593417; тихий налог за срок ≤0,932674% / 0,930930%; с оговорёнными
возвращениями ≤0,995351% / 0,963251%. Это требует более сильного монитора
и совместного U-WCET ≤89,9991 нс, **не подтверждённых характеристик изделия**.

Числа, конкретный отказавший член и поправка области нижней границы —
[RESULTS.md](RESULTS.md). Различия входов и точный остаточный запрос автору —
[contracts.md](contracts.md). Таблицы GOES охватывают все 47 окон T67,
1097 исходных NetCDF: 10415 пересечений и 213480 диагностических оценок счёта.
Это завершённая численная поставка для рецензии, не решение о принятии Θ.
PR #77 остаётся черновым; main и принятые пакеты не изменены.

## Повтор одной командой

Из корня репозитория:

```bash
python -B experiments/t72-r0a-onset-inputs/run.py --cache ../t72-cache --out ../t72-results
```

Команда выполняет 27 тестов, рациональную проверку T73, календарные и
ресурсные проверки, проверяет SHA-256 исходных файлов T67, строит все
таблицы GOES. При отсутствующем cache загружает около 1,62 GB по принятому
манифесту; архив и производные массивы остаются вне Git. Численный этап
можно отдельно повторить с `--numerical-only` (это не повтор GOES).
Python 3.12, NumPy 2.3.5 и один из уже поддерживаемых T67 readers:
netCDF4/libnetcdf/VTK; в этой среде использован VTK. Установки зависимостей
не выполнялись. Команда не содержит платформенных абсолютных путей.

## Что читать

| Файл | Содержание и тип величины |
|---|---|
| `inputs/t73_7ed0f6c.json` | Побайтовая копия конфигурации проверенного SHA теории |
| `config.json`, `inputs/t72_explicit_changes.json` | Ранние определения/бюджеты и **явные** новые предложения |
| `outputs/t73_checked_inputs.json` | Полные четыре набора входов после развёртки |
| `outputs/t73_directed_bounds.csv` | Рациональные границы, запасы, крайние кванты и независимые lower |
| `outputs/t73_summary.csv` | Верх риска/цены, нижняя цена сильного постоянного соперника |
| `outputs/verification_protocol.json` | 1024 геометрии, 2400 окон маски, 66 FIFO-трасс и полосы включений |
| `outputs/onsets.csv.gz`, `availability.csv` | Нативные модельные отклики T67, пересечения, цензурирование, версии/качество |
| `outputs/available_counts.csv.gz` | Ожидание посещённых инверсий и границы oracle-ERR при объявленных периодах/фазах/задержках |
| `outputs/author_events.csv`, `author_signal_counts.csv.gz` | Указанные автором события; отдельный счёт на момент доступности GOES-бина |
| `outputs/provenance.json` | SHA теории, хеши использованных исходников и входов |

Ключ связи onset/count — `record_id`; CSV сжаты стандартным gzip.
Рациональные решения принимаются до десятичного вывода. Поля `lower/upper`
ограничивают **значение указанной формулы**, а не двусторонний доверительный
интервал физического риска. В GOES используется double и объявленная
кусочно-постоянная модель бина; это не направленный физический upper.

`METHOD.md` сохраняет определения до обработки и журнал изменений.
`EARLY_RESULTS.md`, `EARLY_CONTRACT.md`, `controller.py`, `risk_inputs.py`
и `outputs/early/` — явно исторический кандидат до T73, сохранённый для
прослеживаемости; его числа не служат проверкой PR #78.
