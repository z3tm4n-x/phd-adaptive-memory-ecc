# T196: воспроизведение ограниченного результата

Из корня репозитория, Python3.10+; внешних библиотек не требуется:

```bash
python -B experiments/comparison-foundations-20261018/check.py --check
```

Команда ничего не перезаписывает. `--json` выводит новый расчёт на stdout;
`--check` требует побайтового совпадения с outputs/report.json и проверяет
3 blob-хеша принятых runtime-входов. Живые STATUS/MAP не исполнительные
зависимости: инструкции прочитаны на SHA в common-input.json.

806 адресных случаев включают760 малых геометрических проверок удаления
ячеек, строгие границы cut/PAIR/deadline, witness из каждого корректируемого
состояния, whole-period tail, сосед скалярного достаточного корня, начальный
пик/полный ресурс и направленное отображение. Это авторские проверки,
не независимая рецензия и не эмуляция всех пяти правил.

Принятый T119/r4 upper и его цена читаются из точных дробей report-r4.json;
повтор полного принятого пакета не заявлен. Новые upper/lower/resource/edge
подстановки вычисляются рационально независимо от engine.py/bounds.py T186.
No-app частный lower дополнительно равен вызову принятого T126.

Вывод: условный численный cut4мкс допускается при полном пути≤9.6415474мкс;
новый lower с полезными записями≥30.7912057065% и достаточный fixed-upper
≤43.6779721537%+край ограничивают лучший постоянный класс. Условный r4
сохраняет риск и ≥1.7610753240× по SRAM-bus. Никакого CPU/энергетического
выигрыша или автоматического допуска текущего stage3 из этого не следует.
