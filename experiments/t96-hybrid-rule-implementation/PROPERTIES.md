# Предпосылки, обязанности и план проверки Б–Г

А проверяет исполняемую спецификацию. Ни одна строка ниже не объявляет
выполненного формального доказательства RTL. `test_reference.py` —
направленные проверки эталона; будущие RTL и программа должны быть
**независимыми реализациями**, сравниваемыми с его трассой.

## 2. Формальные свойства этапа Б: кванторы и предпосылки

Во всех пунктах — новый RTL; шаг индукции по его состоянию, а не Python.
Параметры рабочего W и ка фиксированы handoff. Для абстрагирования данных
допустимо выбрать произвольный символический word/data и доказать симметрию;
малый W сам по себе этого не делает. Clock/reset/arrival/backend assumptions
должны находиться в harness и быть перечислены в итоговом отчёте.

- **Календарь.** Для всех j с s_j<T, при действительных часах/инициализации:
  один decision в d_j, ровно один U в s_j для каждого initial/mandatory,
  либо U, либо разрешённый skip для остальных. Следующий j=j+1, адрес по
  перестановке; сравнить s_{j+W}−s_j=P_s и s_{j+kaW}−s_j=P_l.
  Запрещены duplicated/missed start и фазовая задержка из-за backpressure.
- **Pending и запись.** Для любого принятого U нет постороннего grant до f_j;
  latch-образ сохраняется до write/fence. Для любой принятой app-write A
  никакой repair с latch, предшествующим accept(A), не пишет после commit(A).
  Более поздние законные записи допускаются. Предпосылки: исправный backend,
  единый lock всех aliases/full-word и отсутствие обходного DMA. Функциональная
  safety-проверка не добавляет app-write к области Q(T).
- **Разрешение.** Для всех последовательностей команд: частичный/плохой
  снимок не устанавливает LOW; atomic apply имеет один ACK; sequence монотонен.
  Для снимка, поступившего целиком до объявленного дедлайна CDC, apply≤d_j;
  иначе default S до любого ещё не frozen решения. Ранее frozen решения
  неизменны. Время считается от полного приёма в исходном домене плюс **весь**
  CDC/валидация/применение, не от удобного внутреннего ACK.
- **Приоритет и задержка.** Для всех потоков с A_p(u)≤45ns+0,04u и
  A_X(u)≤100ns+10⁻⁴u, max atomic≤45ns, FIFO и непрерывной работой сервера:
  completion−first offer≤D_app и 1,1D_app≤3µs. READY/queue waiting включены.
  Доказать service curve с B=2c⁺+g_p, R=1−B/(2g⁻), стабильность;
  глубину FIFO определить из backlog и минимального размера/счётной квоты
  запросов. Одного work-envelope недостаточно для числа почти нулевых пакетов.
- **Пик.** Для всех t≥0, даже после скрытого отказа, U-busy — подмножество
  исходных парных блоков. Добавить весь X-work; мера пересечения с любым
  `[t,t+1ms)` ≤0,8ms. Формула T80 (11) — достаточный upper. Проверка только
  окон, начинающихся в целых миллисекундах, недостаточна.
- **ERR/reset.** Для всех тревог до/в/после d_j: при доступной тревоге holdE
  не сокращается командой; saturating counter не wrap; reset программы
  стирает разрешение, но не pending/j. При потере часов сертификат не валиден;
  восстановление phase/mission state не заменяется новым init.

Инструменты formal/synthesis и platform-clock выбираются в Б. Установленный
frontend или обычная симуляция не означают выполненную индукцию, STA или WCET.

## 3. Эквивалентность В и сквозная проверка Г (только план)

В: сравнить observable trace программы/RTL с эталоном на одинаковом
входе: window/epoch, LOW/hold, command ACK, frozen decision, address,
latch/ERR/pending/fence. Включить пакет на deadline±1, повреждённую запись
команды, перестановку/дубликат, missing, новый epoch, старый пакет, overflow,
замирание CPU, разрыв LOW, ERR в d±1 и долгую потерю. Физический ложный счёт
при валидных полях отдельно остаётся δ_M. Конечные трассы не доказывают Q(T).

Г: один сохранённый SGPS-сценарий `sep_20240608_0255`, GOES-16/E,
1-min/main_loglog/screened, 08.06.2024. Связь с архивом и SHA — `config.json`:
строка T72 `record_id=2328`, существующий NetCDF
`sci_sgps-l2-avg1m_g16_d20240608_v3-0-2.nc`. Переиспользовать существующий
архив T67 и его неизменённый response/masks, не запускать новую кампанию.
NetCDF/cache в текущей среде не найден; в А нужен только план, не загрузка.
Если к Г копии нет: передать прежний cache либо один файл с указанным SHA;
не заменять сводную строку выдуманным временным рядом.

Заранее объявленное **условное**, не физическое, преобразование: для
сохранённого data32 протонного отклика x_i≥0 взять
ν_target=b+(B−b)min(1,x_i/(0,04 с⁻¹)). Этот масштаб не означает перевод
10 мм Al/data32 в 3 г/см²/full38. Пропуски остаются неизвестными.
Для continuous диагностической трассы применить causal slew-limiter в
H_l(ν): H_l(x)=x/l при x≤l, иначе 1+ln(x/l), l=0,001 с⁻¹;
скорость |dH_l/dt|≤0,048 с⁻¹ к текущему target. Считать отдельно исходные
биновые данные и преобразованную трассу; проверить все требуемые условия
Λ/редкости/возвращений, прежде чем связывать её с вероятностным выводом.
Это проект тестового сигнала, не оценка физического роста или новая теорема.

Пропадание монитора: 03:20:00–03:20:10 UTC, без выдач, затем новый epoch;
первое полное исходное окно после восстановления, прежние квоты/календарь.
Счёт условного канала с a_M=A_M=10⁶ и η=0,001 моделируется отдельно от SGPS,
фиксированный seed=103; реальные секунды не возникают из минутных бинов.
Сейчас этот прогон **не выполнен** и production-программа не написана.

Г измеряет новый блок без адаптации и тот же блок с программой/монитором:
LUT/FF/BRAM/Fmax/STA, CPU code/state/cycles/наблюдавшийся максимум, интерфейс
приёма/CDC/очереди. Частоты, измеренный максимум и доказанный WCET различены.
Загрузка интерфейса сравнивается с допустимым постоянным режимом при том же
сервисе/D*, а не с бесплатным отключением контроля. CPU% отдельно.
