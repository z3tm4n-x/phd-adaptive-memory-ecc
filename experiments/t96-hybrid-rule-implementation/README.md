# T96 — реализация фиксированного правила T95

Задача [#96](https://github.com/z3tm4n-x/phd-adaptive-memory-ecc/issues/96).
База: `3bcc554778544f0c7ca477c2a380e46c84ab7bf9`; принятая научная версия:
`8ecc8fb24213e03110789646725481cd34d09ab9`.
Научные файлы T95 и контракт T90 не изменяются.

## Область

CY62167, внутреннее 32+6, R0-A, ГСО, 10 лет, ε=10⁻³,
3 г/см², условный D*=0,0002802445, ERR + условный монитор,
g=140, ka=367, запас 10%. Источник точных параметров:
`../t95-method-regime-map/handoff.json`.

Реализуются календарь/исполнитель RTL, переносимая программа правила,
защищённые разрешения и диагностический интерфейс монитора. Потеря
монитора означает S на прежнем календаре и с прежним U_M: никаких
новых квот, отмены pending-write или экономного ERR-only перехода.

## Среда и уровень подтверждения

Начальная доступная платформа — x86-64/KVM, Intel Xeon Platinum 8573C,
GCC и Python. Полётный CPU не задан; платы, Vivado, RTL-симулятора и
кросс-компилятора в исходной среде не обнаружено. Системная установка
пакетов недоступна по правам. Доступная эмуляция будет отделена от
непроверенных синтеза/STA, CDC, физического интерфейса памяти и WCET.
Наблюдавшийся максимум времени — не WCET; тесты — не подтверждение
десятилетнего риска или физического D*/монитора.

## Поставка (в работе)

Одна команда повтора, код, направленные тесты и раздельная таблица цены
RTL / программы / доставки будут добавлены в этой ветке. Налог шины
не складывается с загрузкой CPU. Любое несовпадение с фиксированным
контрактом будет показано явно, без изменения доказательства.
