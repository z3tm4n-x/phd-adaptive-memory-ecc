# T188 — данные доступны, семантика для полной сверки закрыта частично

[draft PR #190](https://github.com/z3tm4n-x/phd-adaptive-memory-ecc/pull/190).
Статус: OWN RESULT проверки доступности/форматов, передано на рассмотрение;
новый принятый RES не создаётся. База и старт — [PLAN](PLAN.md).

Численные EDAC-данные **обоих** аппаратов скачаны, прочитаны целиком в
опубликованных окнах и закреплены хешами. Независимые EPD/HET и
ASPERA-4/IMA доступны; минимальные фрагменты реально извлечены.
Оцифровка EDAC-рисунков не требуется. **Для следующего этапа рекомендую
Venus Express, 01–20 декабря 2006, только для ограниченной описательной
сверки на крупном временном масштабе.** Файлы обеспечены; полнота экспозиции,
точная UTC-связь EDAC и нормировка IMA пока не обеспечены.

## Основание выбора и точный остаток

[Таблица двух аппаратов](SOURCES.md) содержит источник каждого поля и UNKNOWN.
Для VEX 2006 есть накопительный EDAC и независимый IMA одного аппарата,
без наблюдённого сброса EDAC. Выбор сделан по доступу и семантике;
корреляции, пороги, доли обнаружения и задержки **не рассчитывались**.
Март 2012 сохраняется как пример цензурирования: отсутствие IMA во время
события не означает пропущенного обнаружения EDAC.

Три рассмотренных варианта:

1. **VEX 2006:** 2–3 рабочих дня на карту доступных интервалов, проверку
   единиц/режима и описательное сопоставление роста на масштабе не менее часа.
   Рекомендуется: оба численных канала прочитаны. Точные задержки и показатели
   полноты требуют закрытия UTC/экспозиции, а не дополнительного вычисления.
2. **Solar Orbiter 2022:** полезный следующий случай, но сначала нужны
   словарь HIS/дедупликация, UTC и проверка качества HET V03 во время SEP.
   Список файлов есть; один предсобытийный день не удостоверяет весь эпизод.
   Эти условия за 2–3 дня без операционных сведений могут остаться UNKNOWN.
3. **Только опубликованные рисунки:** возможна качественная иллюстрация,
   но она не устраняет разрывы/отбор событий и хуже доступных численных рядов.
   Не выбирается как основной путь.

Точное численное воспроизведение рис. 4/9 не заявляется. У IMA разные
первичные описания фоновых каналов/нормировки, а у HIS отсутствует правило
агрегации разных сообщений. В S1 рис. 9 EPD является составным quicklook;
HET L2 не переименовывается в тот же набор. Если понадобится оцифровка именно
этой картинки: на просмотренном рендере 1221×1600 ось 04–11.09 имеет около
844 px, то есть около 12 мин/px. При **допущении** неопределённости выбора
центра линии ±2 px получаются примерно ±24 мин и ±3,4 счёта по оранжевой
оси 0–300 (176 px). Это лишь геометрическая оценка чтения, **не** установленная
полная погрешность времени/данных; оцифровка не выполнялась. Спектрограмма
не даёт без потерь восстановить исходные многоканальные счёты.

## Правила следующей сверки, до оценочных результатов

Первичный [PLAN](PLAN.md) закреплён коммитом
`ca9675648965112cc0c5fe081587fec6c8fc3903` до чтения рядов.
После проверки доступности уточнён обеспеченный вход: EDAC S2 v1 +
AMDA `vex-ima-bg`, запрос `[2006-12-01T00:00:00Z, 2006-12-20T00:00:00Z)`.
Весь запрос сохраняется, положительные всплески вручную не вырезаются.

- Положительные референсы — опубликованный комплекс 5/7 декабря 2006 из
  S1 §3.1, а не подъёмы EDAC. Это заранее отобранный case study, не новая
  независимая выборка; два подъёма не объявляются независимыми событиями.
- Отрицательные интервалы допустимы только при установленной совместной
  экспозиции и отсутствии события в независимом канале. Сейчас такой маски
  нет: остальные строки/дни не получают автоматически отрицательную метку.
- Правило первых 1/3 полных дней для настройки и остальных 2/3 для проверки
  из PLAN остаётся условным: здесь полные дни совместной экспозиции не
  удостоверены. Подтверждающее разбиение не сформировано; порог не
  настраивался, метрики на проверочной выборке не предъявляются.
- Для описательного сравнения допустимы только наблюдаемые сегменты без
  интерполяции через разрывы; операции/режимы должны быть отмечены.
  Временной сдвиг по максимуму корреляции не подбирается. Если UTC-связь
  EDAC не найдена, численная задержка остаётся UNKNOWN. Даже при UTC надо
  учитывать фазу IMA/опроса EDAC; 64/192 с не являются гарантией задержки.

Следующий выход за 2–3 дня — ограниченная сверка с явной таблицей доступного
и недоступного. Вероятность миссионного отказа, полнота обнаружения,
редкие квантили, физический CY62167/D* и 10-мкс аппаратный тракт этим набором
не проверяются. Научное принятие и запуск следующего этапа — решение оркестратора.

## Воспроизведение и проверки

Из корня ветки, Python 3.12 (реально 3.12.14):

```powershell
python -m pip install --target .cache/t188/vendor -r experiments/t188-flight-data-access/requirements-epd.txt
python -X utf8 experiments/t188-flight-data-access/reproduce.py --fetch --with-epd --vendor .cache/t188/vendor
python -X utf8 -m unittest discover -s experiments/t188-flight-data-access -p test_reader.py -v
```

Без `--with-epd` и `--vendor` воспроизводятся только текстовые EDAC/IMA;
это сокращённая проверка, не полный повтор поставки. `--cache` и `--out`
позволяют повторить в отдельном каталоге. `--fetch` скачивает отсутствующие
входы; несовпадение SHA-256 останавливает работу, не заменяет эталон.

Фактически: архивный MD5 совпал с Figshare; четыре входа прошли SHA-256;
повторная **сетевая загрузка в пустой cache** и извлечение дали те же хеши
inventory/образцов. Шесть адресных тестов прошли: пустые поля, повторы,
сброс через пропуск, fill против нуля, повреждённая строка и подменённый вход.
Проверки выполнялись локально, независимая научная рецензия не проводилась.
Выходные тексты закреплены с LF; скачанные метаданные сохраняются побайтно.
Финальный журнал — [run.json](audit/run.json), хеши выходов —
[sha256.json](audit/sha256.json). Полные скачанные данные и PDF в Git не входят.
