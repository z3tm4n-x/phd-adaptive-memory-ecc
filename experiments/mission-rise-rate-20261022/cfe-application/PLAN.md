## Что проверяем

Есть ли полезный банк, для которого нижняя цена обязательного приложения
не закрывает 5×, и достигает ли выигрыша хотя бы прежняя выбранная точка ERR?
[profile.json](profile.json) фиксирует проектные требования **до** численного
фильтра. Это предложение применения, не принятое изменение главного примера.

**SOURCE:** cFE поддерживает калибровочные/конфигурационные таблицы, отдельные
активный и неактивный образы, валидацию и управляемую приложением активацию.
Точные исходники NASA и границы извлечения — [sources.json](sources.json).
**ASSUMPTION / проектное требование:** четыре термометрических модуля, по четыре
канала; 12-битный код АЦП; для каждого кода поставляется точное 32-битное
калиброванное значение. Табличное преобразование даёт один доступ с постоянным
временем и сохраняет все поставленные значения без новой ошибки аппроксимации.
Ни число каналов, ни разрядность, ни тепловые пределы не приписываются NASA.

В этой форме данных нужны 16×4096×4 = 262144 байта на образ. Второй образ нужен
для подготовки целой версии без остановки чтения и для сохранения прежней
версии до следующей загрузки. Вместе это **W=131072 32-битных слова**: 256 КиБ
уникальных активных данных и 256 КиБ второго образа, не 512 КиБ уникальных
калибровок. Сжатие/полином может изменить объём, но равная точность и полный
доменный набор для такой замены здесь не доказаны; объём необходим именно
при объявленном формате. Всё W, включая неактивный образ, входит в прежний Q.

Частота получается из допустимого старения: скорость температуры ≤0.05 °C/с,
добавочная ошибка от старения ≤0.05 °C. Поэтому цикл + задержка ≤1 с.
Берётся наибольшее целое число прежних эпох, удовлетворяющее этому условию.
Каждый канал измеряется непосредственно перед одним поиском в таблице;
16 поисков распределены по первым 16 эпохам цикла. Весь активный указатель
закреплён на один цикл. Обход 4096 значений на каждом измерении не нужен.
Это проверяемое требование медленного теплового контроля, не управление
быстрым датчиком и не выбранная из ценовой сетки частота.

Обновление — по принятой команде новой калибровки, максимум одна попытка
в 30 суток, с первой возможностью после 30 суток; не реже не требуется.
Повтор после ошибки тоже расходует эту квоту. Между обновлениями банк может
храниться весь T: **предельная частота не является гарантией освежения**.
Нулевая последовательность обновлений допустима. OFF проверяется на T;
непрохождение достаточного upper не исключает OFF.

## Согласованная загрузка и её цена

Native passthrough, double buffered, noncritical (без третьей полной копии
в CDS). Перед файловой загрузкой cFE копирует активный образ в неактивный,
даже для полной замены. Оплачиваем копию, полную запись из файла, CRC после
загрузки, CRC при проверке и один проход проверки диапазона/монотонности.
Если конкретная сборка не делает второй CRC, его делает явно заданная
обёртка проверки; меньше указанного числа проходов не заявляем.

Две операции записи означают два полных логических прохода по образу.
Нативный C/OS не обещает разрядность доступов: параметр g=1..4 означает
число транзакций ECC на 32-битное слово. В основном upper берём g=4:
(3g+1)B чтений и 2gB полных ECC-записей на попытку, B=65536.
Байтовая запись требует корректного read/decode/merge и полной записи
полезных 32 бит существующим E; её prewrite уже оплачен как app_write.
Скрытый RMW, повтор или дополнительная копия сверх этой модели — UNKNOWN,
а не бесплатная операция. Это договор порта; бинарный cFE не измерялся.

После успешной проверки меняется ссылка на отдельный образ, полной копии
при активации double buffered нет. Старый образ не освобождается, следующая
попытка может его перезаписать. В случае ошибки активная версия сохраняется.
Работа загрузчика/проверяющего выполняется прерываемым работником приложения;
приоритетный контроль не ждёт весь проход. Читающий поток освобождает
указатель до активации. Применимость такого исполнения cFE порта — условие,
его WCET и стек остаются неизвестными.

Минимальное алгоритмическое рабочее место: 16×2 байта отсчётов +16×4 байта
результатов +4 байта накопителя переноса =100 байт **сверх W**. Указатели,
табличный реестр cFE, стеки, OS/file buffers, NVM/file I/O, CPU CRC и валидации
оплачиваются отдельными параметрами. Это не оценка всей RAM платформы.
Третьего полного образа в защищённой SRAM профиль не предусматривает;
если он потребуется, надо изменить договор памяти/риска, не прятать его
в 100 байтах. Целостность входного файла и верность калибровки отдельно от Q.

## Расчёт и критерии

1. Заморозить входы/хеши и открыть draft PR. Передать адресный договор #196.
2. Пробный запуск: точные счётчики без перебора T/epoch. Обязательный runtime,
   диапазон 0..N обновлений и отдельно предмиссионная загрузка/инициализация.
   Консервативно оплатить две полные дополнительные попытки до t=0.
   Пик: не больше одной транзакции прежнего read и write потоков в эпоху.
   Загрузчик последовательный; проверить его отдельный срок 1800 с.
3. OFF39/OFF44: прежний moment upper с P=T и граничным aperture; корректные
   дополнительные E игнорируются. Fixed39 k11 / fixed44 k44837: неизменённые
   достаточные свидетели, научные входы без изменений.
4. Предел core-выигрыша: upper достаточного fixed44 / lower обязательного
   app39. Он относится к занятому времени целевой SRAM вместе с кодеком,
   не ко всей неизвестной аппаратной цене и не к оптимальности fixed44.
   Если предел <5, объяснить и остановить ERR-расчёт. Если ≥5, **один**
   информационный расчёт прежнего k27 при rho=.048; цену удержаний взять из
   принятого PR235, без нового уточнения и без сетки параметров.
5. Верх полной загрузки = приложение + добавочный контроль + неизвестная
   периферия/контроллер. Показывать оба известных слагаемых отдельно,
   initialization/pending/post-A/bad history/observation/veto не удалять.
   CPU, energy, memory, шина, наблюдения — отдельные координаты/коэффициенты,
   не нулевая скалярная цена. Для ERR также нижняя цена неизбежной опоры.
6. Направленные проверки: счётчики/границы T, оба образа, занятость слотов,
   отсутствие смешения версий, полные проходы/байтовый предел, отсутствие
   гарантированного обновления, точное сохранение W/T/epsilon/научного файла,
   перенос цены только приложения. Чистый повтор из git archive.

Результат: одна короткая таблица, рекомендация и список физических данных,
которые действительно способны изменить решение. Не запускать архивную
кампанию, новое правило, аппаратные работы или принятые карты. Не называть
условную допустимость физической квалификацией; адресная рецензия остаётся
отдельной от исполнения чисел.
