Старые outputs и accepted code не меняются.

Python3.12.14, стандартная библиотека. Из корня репозитория:

```text
python -B experiments/mission-rise-rate-20261022/cfe-application/run.py --probe
python -B experiments/mission-rise-rate-20261022/cfe-application/run.py --check
python -B -m unittest discover -s experiments/mission-rise-rate-20261022/cfe-application -p "test_*.py" -v
```

`--probe` считает календарь/ценовой фильтр, без ERR и без записи файлов.
`--check` пересчитывает одну конфигурацию k27/rho=.048 и побайтно сверяет
outputs/result.json. `--write` заменяет только этот новый result.json.
Принятая карта write-retention и её hold-price main не вызываются:
из модуля используются только рациональная цена и преобразование дробей,
принятые результаты читаются по замороженным хешам.

Первый price probe .0243с: ceiling8.759460968, значит продолжение необходимо.
Итоговый расчёт одной конфигурации81.733с, Q-upper=.00038461946226264076.
Это время локального исполнения, не универсальный benchmark.

При первом численном запуске защитная проверка ошибочно требовала точного
равенства новому upper и принятому pilot-upper. Она остановила запись:
в pilot была сетка2 phase/16 q/2 refinement, в неизменённом common input —
8/192/5. Исправлена именно проверка сравнения: новый upper должен быть
не больше принятого для цены. Научный JSON, k/rho и настройки новой
интеграции не менялись. Прежняя более консервативная цена с pilot-upper
сохранена. Повтор той же конфигурации прошёл; это не поиск другой точки
и не повторное уточнение удержаний. Первый незавершённый запуск не
представляется успешным результатом.
