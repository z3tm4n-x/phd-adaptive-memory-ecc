## 1. Краткий результат

Level I дал положительный причинный свидетель в заранее зафиксированной области SEC-DED внешней SRAM. На основном срезе 4 MiB данных, SEC-DED (39,32), H=43824 h, epsilon=0.001, среднего бюджета 0.25%, пикового бюджета scrub 25% в окне 1 s и нагрузки приложения 10%/50%:

- сильный Fixed, учитывающий любой постоянный период и любую фазу, **доказанно не может одновременно уложиться в риск и средний ресурс**;
- простой причинный внешний контур, использующий только завершённую оценку предыдущего часа, имеет достаточную аналитическую верхнюю границу риска и укладывается в средний/пиковый ресурс и объявленную границу задержки;
- поэтому gate Level II открыт.

На Level II не найдено основания переходить к RES-003 как к практически необходимому контроллеру. Минимальный **установленный** причинный метод в этой постановке — простой внешний delayed-rate contour с локальным peak fallback. Strong Precomputed не получил отдельного допустимого свидетеля без использования будущей проверочной траектории; counter-only simple не сертифицирован для новой 39-bit/five-year/conditional-write постановки; RES-003 не переносится автоматически из принятой 32-bit/1-hour/CTMC области. Это не доказательство невозможности последних двух методов.

Отдельная архитектурная проверка показывает, что shortened BCH-кандидат с t=2 может устранить ресурсный конфликт на основном срезе. Следовательно, необходимость адаптации установлена **только при фиксированной SEC-DED архитектуре**, а не для любой допустимой архитектуры памяти.

## 2. Что является SOURCE, ASSUMPTION и UNKNOWN

Полный реестр приведён в `INPUTS.json`.

**SOURCE.** В ESA reference design документированы варианты SRAM 4/8/16/32 MiB, 32 data + 7 EDAC bits, значение 7.3e-7 errors/bit-day и 50 MHz prototype timing с одним wait state для 4 MiB и двумя для 32 MiB. GR712RC UM v2.17 задаёт два data cycles + wait states для чтения SRAM и минимум три cycles + wait states для записи. GRLIB-AN-0004 подтверждает read/correct и locked read/write при аппаратном исправлении для исключения DMA race.

**ASSUMPTION.** Значение 7.3e-7 перенесено на каждый из 39 защищённых физических разрядов. От старого пятилетнего ряда используется только нормированная временная форма: H=43824 h, CV²=6.24295991773, max/mean и lag-1 shape factor. Это исследовательское соединение двух входов, а не физическая калибровка конкретного JUICE прибора. Для 8/16 MiB взят консервативный 32-MiB timing. Нагрузка приложения, deadline 100 us и scrub peak 25% — исследовательский контракт.

**UNKNOWN.** Mission-specific epsilon/H, связь E_cap с отказом БВС, реальная flight workload envelope, эксплуатационная задержка внешнего environmental feed, WCET вычислителя и фактическая доля conditional writes. Проектный causal-input audit прямо не устанавливает practical operational delivery timing; поэтому внешний контур ниже является условным причинным comparator при заданной age=1 h, а не утверждением о готовом лётном канале.

## 3. Общий контракт

Событие — `E_cap` и метрика `F_A` по DEC-001: первое состояние, в котором хотя бы одно кодовое слово имеет больше ошибок, чем гарантированно исправляет выбранный ECC. Это не автоматически DUE, SDC или отказ системы.

Baseline ECC: SEC-DED (39,32), n=39, t=1. Область A — объявленный объём data 2/4/8/16/32 MiB, с соответствующим W=data_bits/32. Основной документированный диапазон — 4/8/16/32 MiB; 2 MiB — контроль.

Исполнение: последовательное чтение слова, ECC check, запись только при correction. Для hard resource admission причинный вариант намеренно оплачивает `read+write` для **каждого** посещённого слова. Это верхняя траекторная граница: реальный conditional-write scrub не может выполнить больше одной correction-write на одно посещение. Для доказательства невозможности Fixed, напротив, используется только read time. Поэтому separator не создаётся неблагоприятным учётом Fixed.

## 4. Level I — почему сильный Fixed недостаточен

### 4.1 Фазонезависимая нижняя граница риска

При постоянном периоде tau каждое слово проверяется раз в tau. В любом часовом интервале постоянной интенсивности и при любой фазе прохода у каждого слова существует не менее `floor(3600/tau)-1` полных межпроверочных интервалов, полностью лежащих внутри часа.

Для такого интервала с пуассоновским средним lambda на слово событие «ровно две инверсии в двух различных разрядах» имеет вероятность

`exp(-lambda) * lambda^2/2 * (n-1)/n`

и является подмножеством E_cap. Разбиение пуассоновского потока по словам и непересекающимся временным интервалам даёт фазонезависимую нижнюю границу. Для длинных tau дополнительно используется Cauchy lower bound по суммарному числу межпроверочных интервалов. Непрохождение верхней оценки Fixed нигде не используется как доказательство невозможности.

### 4.2 Основной 4 MiB свидетель

При epsilon=0.001 и среднем бюджете 0.25%:

- W = 1,048,576 слов;
- перенесённая средняя интенсивность = 1.24387328 events/h;
- перенесённый исторический максимум = 209.9799548 events/h;
- чтобы уложиться только в read-bandwidth 0.25%, Fixed требует `tau >= 25.165824 s`;
- уже при `tau=25.165824 s` нижняя граница `F_A >= 0.001571525 > 0.001`.

Проверка непрерывного класса не заканчивается этой точкой. На `[25.165824,900] s` использованная exactly-two lower bound является одномодальной; её значения на обоих концах выше epsilon. Для `[900,3600] s` непрерывная Cauchy lower bound уже при 900 s даёт `F_A >= 0.007844363` и далее монотонно не уменьшается. Поэтому **все resource-compatible Fixed periods до 3600 s исключены**, независимо от фазы.

Эквивалентная boundary-величина: чтобы Fixed имел шанс удовлетворить риск, одной только read-bandwidth требуется не менее **0.395040%**.

## 5. Level I — причинный свидетель

Используется один скаляр завершённого предыдущего часа:

`r(t)=nu_hat(t)/C`, `nu_hat(t)=nu(t-1h)`,

где r — число полных циклических обходов в час. Текущее/будущее значение nu контроллеру не выдаётся. Межпроверочные интервалы определяются условием `integral r dt = 1`.

Из Cauchy для каждого межпроверочного интервала и суммирования по словам:

`F_A <= (n-1)/(2 n W) * C * integral(nu^2/nu_hat) dt + delta_RMW`.

C фиксирован до проверки так, чтобы pair-bound расходовал 95% epsilon. RMW-окно оплачивается отдельно.

Для 4 MiB, epsilon=0.001:

- `C = 0.03560929816`;
- верхняя граница риска = **0.0009500000**;
- после независимого stress с четырёхкратно увеличенным RMW-слагаемым = **0.000950000728**, всё ещё <0.001;
- консервативная средняя занятость интерфейса, если резервировать write после каждого read = **0.142447%**;
- максимальная занятость в 1-s peak window = **24.0458%**;
- bound задержки 8-word запроса при app load=50% = **3.005 us** (<100 us);
- при данном delay contract допускается app load до **75.17%**; поэтому зафиксированные 10% и 50% проходят, 80% не проходит этот principal slice.

Получена связная область среднего бюджета

`0.142447% <= B_avg < 0.395040%`

при остальных principal условиях. Внутри неё causal witness проходит достаточную верхнюю оценку, а весь Fixed class исключён нижней границей. Заранее заданный срез 0.25% лежит с заметным запасом внутри.

Остаток до бюджета 0.25% составляет 0.107553 percentage point average и 0.954164 percentage point в 1-s peak window. Вычислитель требует один scalar update в час; его target WCET не измерен. Если его стоимость относится к тому же ресурсу, она должна укладываться в эти остатки. Это условие реализации, а не измеренный WCET.

### Missing-data fallback

При отсутствии предыдущей оценки применяется scan rate, соответствующий максимальному разрешённому rate. Он не увеличивает risk bound относительно causal schedule. Исторический source summary содержит 148 missing proton hours. Если **все 148 h** консервативно оплачивать peak-fallback rate, средняя занятость возрастает до **0.223172%**, оставаясь ниже 0.25%. Ресурсный запас исчерпывается приблизительно при 197.19 h такого fallback. Это sensitivity к сохранённой missing-count, не доказательство эксплуатационной статистики будущего канала.

## 6. Часовой и пятилетний срезы

Для того же 4 MiB и epsilon=0.001 на одном peak-hour исследовательском срезе lower-bound boundary Fixed соответствует read resource около **0.032605%**, то есть даже ниже минимального контрольного бюджета 0.1%. Следовательно, **на часовом срезе необходимость адаптации не установлена**.

Положительный separator возникает при пятилетнем накоплении риска. Часовой результат нельзя использовать как разрешение ежечасно обнулять mission risk budget.

## 8. Level II — минимальная достаточная сложность

Level II был открыт только после сохранения Level-I witness.

### Strong Precomputed

**NO DISTINCT ADMISSIBLE WITNESS ESTABLISHED.** Полезное нестационарное расписание, рассчитанное по фактическим будущим часам проверяемого 2021–2025 ряда, является leakage и не использовалось. В доступных preparation-time входах нет отдельного календарного/event predictor, задающего сильное open-loop расписание. Это `INCONCLUSIVE`, а не доказательство невозможности Precomputed.

### Simple external contour + local fallback

**MINIMAL ESTABLISHED CAUSAL WITNESS.** Один delayed scalar, одно выражение r=nu_hat/C и fallback. Bayesian/hidden-state filter, собственный счётчик исправлений и RES-003 bank не нужны для установленного separator.

Конкретные причинные строки сохранены в `outputs/causal_witnesses.csv`: решение часа i использует только rate часа i-1. При missing input выбирается peak fallback.

### Counter-only simple

**NOT ESTABLISHED FOR THIS DOMAIN.** Исторические q16/q32 — диагностические stochastic replays старого ряда, включая 30-seed sweep, но не сертификат новой 39-bit, five-year, conditional-write постановки. Их отсутствие в роли победителя не означает небезопасность simple. Новый stochastic law/tuning campaign для него не вводился.

### RES-003

**NOT COMPARABLE WITHOUT NEW SCIENTIFIC TRANSFER.** Принятый RES-003 относится к data-only SEC n=32, H=3600 s, epsilon=0.1, известной симметричной двухрежимной CTMC и собственному счётчику в конкретной последовательной модели. Здесь n=39, H=5 years, epsilon principal=0.001, временная форма — перенесённый исторический ряд, а базовое исполнение conditional-write. Автоматический перенос guarantee запрещён.

Следовательно, в проверенной практической области **не установлено никакого системного выигрыша RES-003 сверх простого внешнего контура**. Научная ценность RES-003 как собственного счётчикового метода в его принятой области этим не меняется.

## 9. Архитектурный конкурент: более сильный ECC

Проверен отдельный аналитический shortened binary BCH candidate `(44,32,d>=5)`, t=2. Это не drop-in замена документированного 39-bit SEC-DED.

Для principal 4 MiB / epsilon=0.001 / B_avg=0.25%:

- worst-case read+write period = **58.720256 s**;
- analytic upper bound для события >=3 distinct errors до correction = **5.57e-9**;
- average/peak service = 0.25%;
- delay bound при 50% app load = **1.568 us**.

Protected storage возрастает с 39 до 44 bits/codeword: **+12.82%** относительно SEC-DED coded storage; для 4 MiB data это 5.5 MiB coded storage вместо 4.875 MiB. При сохранении 48-bit interface оба codeword помещаются в один transfer, но BCH decoder complexity, target timing и WCET не реализованы.

Поэтому найденный конфликт Fixed/adaptation **не универсален по архитектуре ECC**. При разрешённом redesign более сильный код может оказаться проще, чем адаптация.

## 10. Conditional-write и независимые проверки

Опубликованный `verify.py` проверил 78 условий, включая восемь адресных сценариев:

1. clean word — write отсутствует;
2. single correctable error — correction write и count;
3. error после read — сохраняется до следующего обслуживания;
4. distinct second error внутри RMW interval — признаётся E_cap hazard;
5. correction последнего слова входит в snapshot;
6. partial pass не объявляется complete;
7. late command вызывает fallback;
8. locked scrub/app arbitration не допускает overlap.

Это малые независимые семантические трассы, не RTL simulation.

`independent_check.py` не импортирует `analyze.py`. Он отдельно:
- доказывает непрерывное исключение Fixed на principal resource-compatible tau;
- усиливает RMW term ×4;
- проверяет 148-h fallback sensitivity;
- проверяет exact Git-blob identity исполненных pre-verification файлов;
- перепроверяет stronger-ECC witness и hour slice.

Все проверки завершились успешно. Дополнительно все семь уникальных `(memory, epsilon)` пар из 17 замороженных Level-I witnesses прошли continuous-tau audit: минимальная нижняя граница после 900 s остаётся выше соответствующего epsilon. `outputs/execution_record.json` сохраняет версии, команды и SHA-256.

## 11. Прямые ответы на пять вопросов постановки

### 1. Где Fixed недостаточен и каким основанием это установлено?

В частности, для 4 MiB SEC-DED (39,32), H=5 years, epsilon=0.001, B_avg=0.25%, B_peak=25% и app load 10/50%. Более общая principal boundary по среднему ресурсу: **0.142447% <= B_avg < 0.395040%**. Недостаточность Fixed установлена не верхней оценкой, а фазонезависимой нижней границей вероятности exactly-two-distinct-bit event плюс отдельной continuous long-period lower bound, покрывающей все resource-compatible tau до 3600 s.

### 2. Какой минимальный метод выполняет полный контракт?

Минимальный **установленный** метод — простой внешний one-hour-delayed scalar controller `r=nu_hat/C` с peak fallback при недоступности входа. Он не использует собственный count filter или RES-003 state bank. Полнота практического утверждения условна на declared one-hour information contract и на стоимость вычислителя, остающуюся в явно рассчитанных residual resource margins; реальный operational feed latency не установлен.

### 3. Что система получает от RES-003 сверх simple?

В этой постановке — **дополнительная системная выгода не установлена**. RES-003 даёт научно принятый способ безопасной обратной связи по собственному счётчику без внешнего измерителя в своей CTMC/32-bit/1-h области, но перенос его guarantee на данный 39-bit/five-year/conditional-write объект потребовал бы нового научного основания. Поскольку simple external уже пересекает найденную системную границу, практическая необходимость более сложного RES-003 здесь не показана.

### 4. Есть ли основание вообще рассматривать RES-004 в практической части?

**Нет.** Level III не запускался. Не показана даже необходимость RES-003 для найденного separator, тем более отсутствует системная граница, которую можно пересечь только за счёт уточнения неизвестного D. Практическую ветвь RES-004 следует оставить остановленной; это не отменяет его принятого научного результата и публикационного потенциала.

### 5. Какой вариант реализации и какое ограниченное положение диссертации теперь обоснованы?

Для fixed SEC-DED architecture обоснован кандидат: **conditional-write sequential scrubber + простой delayed external-rate controller + local peak fallback**, при сохранении конкурентного Fixed режима. Ограниченное положение: *при временно неоднородной интенсивности ошибок и фиксированной SEC-DED архитектуре существует параметрическая область внешней SRAM, где причинное перераспределение обслуживания по доступной прошлой информации удовлетворяет совместным ограничениям риска и ресурса, тогда как любой постоянный период не может их удовлетворить*. Это положение условно на входную модель/transfer assumptions, resource contract и information timing; оно не доказывает универсальную необходимость адаптации, поскольку отдельный stronger-ECC variant может убрать конфликт.

## 12. Воспроизводимость и ограничения

Зафиксированные команды:

```bash
python analyze.py
python verify.py
python independent_check.py
```

`analyze.py`, `verify.py`, `config.json` были опубликованы до итоговой проверки. Финальное исполнение выполнено из байтов, чьи Git blob IDs точно совпали с pre-verification commit. Предварительная scratch-копия с текстовым расхождением отброшена как provenance и не используется; история ветки не переписывалась.

Новые Monte Carlo, retuning, GOES/COSRAD rerun, RTL, Vivado и practical RES-004 work не выполнялись.

Главные ограничения:
- transferred temporal shape — ASSUMPTION, а не физическая калибровка конкретной платформы;
- actual external feed delivery latency остаётся UNKNOWN;
- app traffic/deadline/peak budgets — исследовательский контракт;
- controller WCET не измерен;
- stronger BCH — аналитический architectural candidate, не реализованный replacement;
- E_cap не тождествен системному отказу;
- существенные новые выводы этого отчёта должны пройти отдельный Scientific Review.
