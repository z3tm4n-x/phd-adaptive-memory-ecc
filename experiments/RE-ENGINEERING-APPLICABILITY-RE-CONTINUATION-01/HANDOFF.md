## Материальные выводы и оставшиеся ограничения

48-bit/360-нс профиль сохранён как проект малого прототипа. Для него явно
нужны latch/unconditional commit, полный data+parity count, generation/epoch,
ACK исполняемого периода, отсутствие reset риска и квалифицированный timer.
Старая частота 133.333 MHz не является доказательством точной сетки этого профиля.

При масштабировании 39/32 резерв 1 с не проходит. .5 с имеет положительный
начальный запас в новом достаточном расчёте, условном на ещё не проверенный
арифметический резерв модифицированного банка. Это не разрешение развернуть
старую программу без новых коэффициентов/проверки её численной реализации.

Fixed=30 с при условном пике и epsilon=.001 сохраняется. «Один проход при .1»
допустим только в расширенном классе входа; в исходной U остаются 12.
Редкость положительных counts — не доказательство бесполезности нулевых.
Физический поток, direct events и профиль приложения требуют квалификации.

1.08 мкс — условная сервисная граница; 720 нс не универсальный максимум
непрерывной фазы. При 80% есть короткий deadline-контрпример. RTL, размещение,
целевой memory timing и CPU WCET не проверены из-за отсутствия backend/платформы.

## Независимость и SR

Новый код не вызывает helpers входного пакета. Общими остаются математическая
модель, интерпретация source и извлечённые константы. Алгебра SEC-DED и Python
endpoint не являются исполнением старого SystemVerilog. Резерв .001 для
модифицированного банка — условие экрана, не новый арифметический сертификат.

Существенные кандидаты для SR: RMW coupling/guard при адаптивных действиях;
остановленное продолжение при задержке/потере наблюдения; достаточная
full-word/backup оценка. Сервисная теорема рассматривается при полном
arrival/transaction контракте. Гарантию всего изделия, global optimum и
автоматическую полезность сложного управления не предлагать к принятию.

Критерии опровержения: несовпадение счётчиков вне оплаченного события;
допустимая трасса с N_started выше границы; применение не подтверждённой
команды/повторный budget reset; нарушение сервисной границы при её полном
контракте; отсутствие численного запаса после валидированного backend.
