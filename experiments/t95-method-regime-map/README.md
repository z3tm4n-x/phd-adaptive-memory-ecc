# T95: адресная проверка необходимой границы и передачи

Область заранее задана Issue #95: R0-A/internal38/3 г/см²,
основной D*=0,0002802445, контроль D*=0,00005, прежние Λ/Θ и запас 10%.
Новых кривых, симуляций, физических расчётов и общего оптимизатора нет.

## Воспроизведение

Из checkout ветки T95, Python 3.10+, только стандартная библиотека:

~~~bash
python -B experiments/t95-method-regime-map/verify.py
~~~

Режим по умолчанию вычисляет сертификат и сравнивает report.json.
Для осознанного механического обновления после изменения доказательства:
добавить --write. Принятые входы не изменяются.

Проверяются git-blob SHA семи исходных файлов до расчёта;
точные принятые SHA T88/T90 и selectors закреплены в inputs.json.
Рабочая строка взята из T90 actual_window_at_selected_g, а не g131.
Все новые величины рациональны. Decimal-вывод направлен, float не применяется.

## Что проверяется

- Два допустимых свидетеля: начальный пик и тихое начало/подъём/плато.
- Нижняя вероятность для всех P≥P0: умеренный диапазон и бесконечный хвост.
- Конечная монотонная инверсия lower и сосед на вспомогательном шаге 1 нс.
- Общий фазовый край 2Wc/T; контрпример для переноса парного 2c/T.
- Принятые M/M+1 T52, returning-край его цены, интервал оптимума.
- Тот же D* у всех вариантов; адресное повышение D у готовой ERR-политики.
- Риск S с начала, неизменённый U_M для потери по доказанному включению.
- Полная цена жёсткой маски, коэффициент и условие доступности.
- Запас 10%, peak/delay, неизменные календарные P_s/P_l, P_s≠Wc.
- Булевы инварианты erasure/expiry/hold/ERR/mandatory/initial;
  неизвестные физические поля остаются null.

Скрипт не доказывает теорему вместо текста. Predicate-проверки не моделируют
pending-write, очередь, аппаратные таймеры или программный WCET.
Точные принятые LOW/мажоранты ERR переиспользованы, а не пересчитаны
новой кампанией. Самопроверка не является независимым инженерным вердиктом.
