### Проверка поставленных результатов

Из каталога `experiments/t534-native256-fpga` нужны Python 3.12 и стандартная библиотека. Сетевых запросов нет. Архив объёмом около 1 МБ содержит оригинальные отчёты Vivado и четыре полные EBD, координаты размещённых элементов, исходные результаты симуляции, применённые ограничения и список контрольных сумм распакованных файлов.

```sh
python -X utf8 -B collect.py
python -X utf8 -B budget.py
```

Первый шаг проверяет каждый SHA-256, матрицу фактических наблюдений, привязку каждой из 17 или 51 цепей ERR/DQ к своему входу и регистру, минимумы и максимумы обоих углов по всем 36 выходам, 16 цепей данных и 16 разрешений драйверов. Для каждого размещения повтор с временем доступа SRAM 100 нс должен быть отвергнут. Затем программа пересчитывает число единиц **только в полезной части** ASCII-маски EBD и сверяет отличающиеся ресурсы по ведомости размещённых элементов. В архиве также проверяется присутствие ICAP, FRAME_ECC и экземпляров SEM по составу top и журналам генерации IP. Функциональная проверка внутренней схемы AMD, регистрация физического сбоя и оживление экземпляра платы сюда не входят.

### Полное повторение из исходников

Linux или WSL2, доступный в PATH Verilator 5.032, GNU C++ 15.2, GNU make, Icarus 12.0, Vivado 2025.2 (SW build 6299465, lin64), поддержка Zynq-7000 и Soft Error Mitigation IP 4.1. Проверено с Ubuntu 26.04 и ядром WSL2 6.6.114.1; повтор ведомостей выполнен Python 3.12.14 под Windows. Исходники компилировать из каталога с ASCII-путём — поставляемый генератор makefile Verilator может экранировать кириллицу в пути к своей библиотеке. Использованы пакет Ubuntu `verilator_5.032-1_amd64.deb`, SHA-256 `0e3b3ee4e232e10d8e0f8353d8b45db47649ff3757cbd251688b7c894a7cb105`, и установленный Vivado. Лицензионные исходники и контрольные точки производителя генерируются на стороне проверяющего.

```sh
cd experiments/t534-native256-fpga
out=$(mktemp -d /tmp/t534-replay-XXXXXXXX)
mkdir "$out/src"
cp -r rtl test board.xdc route.tcl route.sh simulate.sh "$out/src/"
(
  cd "$out/src"
  bash test/rule_check.sh "$out/sim"
  for m in F0 F1 A0 A1; do
    bash simulate.sh "$out/sim" "$m"
    bash route.sh "$out/routes" "$m"
  done
)
python -X utf8 -B collect.py --pack "$out/routes" "$out/sim" --bundle "$out/replay.zip" --results "$out/digital.json" --write
python -X utf8 -B collect.py --bundle "$out/replay.zip" --results "$out/digital.json"
python -X utf8 -B budget.py
```

Если Vivado запускается обёрткой, перед командами задать `export VIVADO=/home/z3tm4n/bin/vivado-wsl`. Временные папки размещения должны быть пусты до старта конкретного проекта. Сравнить логические строки, физические ограничения, ресурсы и полезные части EBD с `results/digital.json`. Исходные архивы сохраняют даты, локальные имена каталогов и служебные заголовки Vivado; SHA-256 архива удостоверяет поставку определённого запуска. Свежий запуск может иметь другой SHA даже при том же содержимом маски. В четырёх заключительных маршрутизациях длительность на проект составила от 2 мин 13 с до 4 мин 24 с, наибольшее зарегистрированное Vivado потребление памяти 3 229,609 МБ на процесс. Два одновременно запущенных проекта конкурировали за процессор и память. Для собственных запусков время зависит от машины.

### Границы функциональной и физической проверки

1. C++-наблюдатель использует целое время, собственную перестановку адресов, последовательность допустимых фронтов и формулу образа данных. Правильные DQ/ERR подаются только в апертуре выборки. Проверяются фактические CS/OE/WE, направление и данные DQ, запуск, отчёт, выдача периода и состояние занятости. Первые семь сценариев каждого режима проходят **каждый** адрес и каждый 10-нс такт до очередной границы. В фиксированном режиме наблюдается и пауза. В испытании общего ERR изменяется общий вход перед выборкой. Целевые изменения отдельного регистра производятся после выборки. Одновременное реальное воздействие на разные регистры из этих опытов не моделируется.
2. Каждый из семи переходов A наблюдается в полном граничном обходе после загрузки достижимого префикса. Префиксы отдельно достигаются из чистого пуска в Icarus. Для порога 2L чистая пауза исполняется по тактам и проверяется прикладное чтение. Для остальных проверяются все реальные границы пропущенных проходов, внутренность пустой эпохи сокращена. В опытах восстановления сокращены чистые средние кадры после проверки окончания первого кадра. Начало, последний кадр, пересечение общего сечения, установка команды и каждый следующий старт проходят через RTL. Ни отчёт о завершении, ни счётчик исправлений не подставляются вместо завершения адресного доступа. В опытах границы существующий полный отчёт задерживается либо подавляется только для проверки доставки. Отдельные записи регистра истории не являются битовыми физическими испытаниями.
3. Подстановка сигналов Observation/Correction/Uncorrectable выполнена в `test/sem_connection.sv` на настоящих связях обоих защищённых верхних модулей. В функциональном тесте заменены FPGA-примитивы и источник выводов ядра AMD. В четырёх маршрутизациях используются штатные примитивы, а в двух защищённых — сгенерированный AMD SEM с ICAPE2 и FRAME_ECCE2.
4. На входе SRAM и контроллере сохранены 100 МГц, предельные маршруты входов 2,5 нс, выходов 5 нс, неопределённости setup/hold 0,5/0,1 нс. При сопоставлении паспортных окон учитываются два крайних отклонения фронтов по 0,5 нс, масштаб частоты 0,99999…1,00001, 15 пФ, линия 0,1…0,5 нс в каждую сторону, фронты SRAM до 3 нс и заданные статические уровни. Проверка стендового адаптера проведена по проектному назначению выводов; измерений на изготовленном FMC здесь нет. DRC сохранила предупреждение ZPS7-1 для PL-части без PS7 во всех четырёх top. Начальную установку PS для ICAP должен обеспечить загрузчик. У защищённых схем RTSTAT-10 относится к сохранённым именам без маршрутизируемых нагрузок; все действительные маршрутизируемые сети проложены, ошибок маршрутизации нет. Список непотребляемых сетей дан в каждом `drc.rpt`.
5. В первом размещении F1 при ICAP 100 МГц был нулевой запас минимального периода ICAP и нарушение пути DQ0 −0,027 нс. В промежуточном размещении A1 с первой копией в ILOGIC остались −0,033 и −0,030 нс на двух захватах DQ0. Выбран отдельный такт SEM 50 МГц и размещены две копии захвата DQ0 в разных соседних slice. Последние ограничения одинаковы для защищённых F и A. Время диагностики и ремонта пересчитано для 50 МГц. Журналы в поставке относятся к заключительным прогонам. Скрипт цены допускает 1,5 плитки BRAM и отдельно проверяет три RAMB18, что устраняет возможное округление ресурса вниз.

Полностью размещённая схема подтверждает пути и параметры проекта. Для измеренной годовой частоты повторного сбоя, поведения платы и энергетических затрат нужны соответствующие физические входы. [Область вывода](REPORT.md) · [Квота и пороги](results/budget.json)
