Из корня репозитория (Git и Python3.12, стандартная библиотека):

```text
python -B experiments/t186-method-comparison/stage2/reproduce.py
```

Команда проверяет22 рабочих зависимости и25 Git-снимков документов,
заново генерирует train/test и сверяет их с закреплёнными данными,
повторяет обучение и59 проверок, воспроизводит60 строк и аналитические
верхи, сравнивает детерминированные выходы с сохранёнными. Затем измеряет
benchmark с общим лимитом120с; пропуски/остановки явно отражаются в JSON.
Выход повторения — `.cache/t186-stage2-replay/`, принятые файлы не меняются.
`--skip-benchmark` оставляет только детерминированный повтор.

`--train` и `--record` — команды формирования исходного пакета, обычному
повтору они не нужны. Обучение обязано быть закоммичено до `--record`.
Тренировочная версия не использует test и не получает будущую интенсивность.

Рабочие хеши исполняемых файлов/численных входов и документальные снимки
разделены в `provenance.json`: MAP/STATUS/RESEARCH_PLAN читаются посредством
`git show SHA:path`, не по текущим текстам. Нужен clone с соответствующей
Git-историей; неполный archive без объектов этих коммитов недостаточен.
Изменения живых организационных документов не ломают проверку пакета.
Это проверено в чистой копии39a2a28 вместе с отклонением изменённой
исполняемой зависимости; [протокол повторения](outputs/replay.json).

JSON/тексты нормализованы в LF. Сравниваются целочисленные события,
рациональные результаты и хеши сгенерированных данных; времена Python
и environment.json меняются. Библиотечные log/exp генератора и float-колонки
явно относятся к записанной платформе: универсальная побитовая переносимость
не заявлена. Изменившийся хеш входа остановит повтор, а не будет принят молча.
