# Детали до первого расчёта этапа 3

Генератор использует Decimal с precision50 и точно представленные десятичные
b/B. Единичные экспоненциальные интервалы получены из открытого53-битного
uniform; поток меток отдельный Random(seed XOR0x186032023). Это исключает
зависимость времён от расхода случайных чисел при выборе слова/бита.
Время складывается в Decimal и затем округляется вверх до целой наносекунды;
binary64-ulp длинной миссии не используется как временная сетка.

Чистые application-потоки раскладываются на49 фаз grant для uniform и245
фаз для каждого из read/write в bursty. Коэффициент перестановки адреса5
обратим по W. Для загрязнённого слова ближайший q находится по модулюW.
READ32 сам по себе ошибок не меняет; его полная цена и транспорт считаются
для всех обращений. WRITE32 всегда имеет оба commit132/200, даже при
чистом latch; ERR публикуется только при непустом snapshot60.

Граница времени T: инверсии/завершения вT учитываются; старт ровно вT
имеет нулевую цену и остаётся pending. Arrived включает VALID<=T;
started включает grant<T; completed/replied включают соответствующий
endpoint<=T. Входы/выходы транспорта и незавершённая SRAM-операция различаются.

Для цены наблюдения выдаются счётчики непересекающихся действий и
символические коэффициенты времени/энергии. Pre-observation полезной записи
уже включено в216нс и второй раз в SRAM-bus не добавляется. Оптимизация
повторных одинаковых прогнозов в Python не уменьшает заявленное число
часовых прогнозов алгоритма.
