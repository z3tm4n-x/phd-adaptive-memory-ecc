## Что стало исполнимым

За10лет полностью оплачены315576000000 чтений и столько же наблюдаемых
записей. Чистые операции считаются по периодическим классам остатков
arrival→grant:98 классов uniform и490 bursty для обоих типов вместе.
Загрязнённое слово явно встречается с ближайшим контролем или полезной
записью. Инверсия внутри неявной операции восстанавливает её состояние.
Оба commit записи132/200нс сохраняют рождения после start; pre-observation
60нс и публикация ERR64нс включены в write32=216нс один раз.

Считаются arrived/started/memory-completed/replied, pending на границеT,
частичные SRAM-операции, собственный ERR каждого правила, вся цена после
первого A. Бесплатного дренирования или очистки слова в начале записи нет.
Начальное состояние здесь чистое; direct/MCU/false/loss/outage в эти
диагностические истории не внесены. Они остаются членами полного договора.

NHPP-генератор обращает интегральную интенсивность постоянных и
экспоненциальных сегментов. Экспоненциальное приращение переносится через
границы, метки word/bit используют отдельный поток PRNG. Decimal50 и ceil
до наносекунды — явные численные соглашения. Это не оценка физической
неопределённости и не сертификат непрерывного редкого риска.

## Полная цена как набор измеренных коэффициентов

[cost.py](cost.py) сохраняет для каждой строки вектор действий и формулу
CPU busy=`sum(N_i*c_i_ns)/T_ns`. Все c_i неизвестны; CPU не складывается
с bus. Удельные энергия/биты для collector, ERR и application transport
также неизвестны. Для постоянного правила нет polling-драйвера адаптации,
но общие capture/transport и вся прикладная работа остаются в ledger.
Это полная отнесённая цена действий. Для фактической занятости CPU внутри
[0,T] потребуются ещё времена выполнения и остатки незавершённых CPU-действий;
они неизвестны. Потолки T/N_i применимы условно, когда вся отнесённая работа
должна завершиться внутри горизонта, и не заменяют эту краевую проверку.

Каждое адаптивное правило на10лет имеет1677168367346 nominal cut-сервисов
(около5314,62585/с), каждый полезный поток даёт2000 request-records и
2000 completed-reply-records/с. Для Chen оплачены87654 полных прогноза,
525924 умножения со сложением для шести признаков и87659 hourly updates;
кеш Python не делает повторные прогнозы аппаратно бесплатными.

Чувствительность непосредственно читается из коэффициентов: добавление
100нс к цене каждого cut увеличивает загрузку одного ядра на0,0531463
процентного пункта;100нс к каждому request и reply вместе — на0,04 пункта.
Это условные производные цены, не измерение контроллера. В JSON даны
отдельные необходимые потолки `c_i<=T/N_i`; они не являются совместным
достаточным ограничением CPU. Для полного R0-A нужны дополнительные
действия при false/loss/outage/recovery, а не нулевые слагаемые.

Полные r4 service-верхи отдельно дают максимум занятости любого1мс
76,119558624% uniform /76,293160352% bursty, ниже80%. Ответ с10% запасом
<=2755,502376нс<3000; write с запасом238,702376нс<240. Номинальный
максимум ответа в этих историях2472нс. Это условные календарные проверки,
не измеренные ARM/WCET или подтверждение полного r4.

На произвольной конечной тихой компоненте длины L каждый тип приложения
имеет `N<=1000*L_s+m`, где m=1 uniform или5 bursty. Возможная доплата
на компоненту по полным service-верхам402,004*m нс. При KQ<=1000 и
TQ>=0,9T верх дополнительной доли шины1,41541534e-12 uniform /
7,07707670e-12 bursty. Это явная цена краёв, **не** разрешение превысить
строгое среднее1000/с на каждой расширенной компоненте. Допустимость
профиля и отдельный строгий вариант обсуждаются с теоретиком.

## Скорость и проверка

Полная матрица заняла83,293с в зарегистрированном180-с лимите; точные
замеры и среда — [timing.json](outputs/timing.json),
[environment.json](outputs/environment.json). Генератор10лет занимает
около3,3с (медиана трёх повторов); только68765 экспоненциальных выборок
и81 сегмент вместо ожидаемых77215988,9975 кандидатов глобального thinning.
Старый10-летний thinning не запускался: множитель ускорения по wall time
не заявляется. На сутках Decimal50 медленнее принятого float-thinning:
примерно0,053с против0,017с. Преимущество здесь — стоимость, зависящая от
интеграла фактической интенсивности, и точность длинной шкалы времени.

32 адресные проверки включают45 сравнений dirty-executor с буквальным
обходом для всех15 принятых конфигураций, независимый принятый
MemoryOracle/ETransaction,12 краевых горизонтов записи/ответа, XOR и
сохранение первого A, регрессию пустого приложения, точные периодические
суммы и счёт631152000000 полезных операций. Генератор проверен через
интегральные координаты с70 знаками, независимую квадратуру и512
счётчиков пуассоновской модели. Среднее20,07422/дисперсия20,42501 при
ожидании20 — диагностика реализации, не MC-оценка mission Q.

Команда и протокол чистого повтора приведены в [README](README.md).
Принятые источники/семантика зафиксированы [provenance.json](provenance.json);
