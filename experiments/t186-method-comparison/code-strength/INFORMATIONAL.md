# Информационная строка full39: численная подстановка T196(7)

План v4/7e42ffb предшествует новому J. Основание — передача #1967259964f,
§4, и принятые T119(2)–(5)/приложениеА–Б. Это авторское численное
обобщение интерфейса. [Адресное заключение #196](https://github.com/z3tm4n-x/phd-adaptive-memory-ecc/pull/211#issuecomment-6337124557)
подтвердило применимость к v4/0111d424; это соавторская проверка,
не научное принятие или физическая квалификация. R1 меняет только цену repair.

## Что меняется относительно фиксированного full38 расчёта

При singleton-базе общий per-bit закон даёт ν1=39W*r=(39/152)ν_ref.
Поэтому b1,B1,FS1 **и порог ell1** масштабируются одним39/152.
Равенство H_(a ell)(a q)=H_ell(q) сохраняет rho=.048. Оставить ell=.001
при новом q было бы другим классом роста. Слова независимы, lower-parent
a=1 и multiword=0 только в условном p1=1; наблюдаемый нижний вес
phi=1−1/W после исключения текущего защищённого слова.

Полный39 декодер на весах0/1 выдаёт один ERR. App-read не удаляет ошибку
и не выдаёт ERR/G. Scrub и предмодификационное чтение full32 write наблюдают
её до удаления. Таким образом сохраняется причинное раскрытие T196§4.
При XOR/повторном касании история оплачена общим разрывом, поэтому
используется beta0=1/(2W), **не** физический коэффициент38/(78W).

## Календарь, фазы и таймеры

Для каждого нечётного зарегистрированного k={3,5,9,27} адрес j равен
inverse(k modulo W)*j modW. ПервыеW и j mod k=0 обязательны. Это даёт
фазы m_r=kg*r+(164−g)*(kr mod8), W131072 делится на8, gcd(k,W)=1.
Отклонение от равномерной сетки kg*r ограничено7(g−164).

Для интервала длиной Ps/M число фаз сверху ограничено W/(kM)+4.
В новом диапазоне проверен более явный достаточный остаток:

```
W/(kM)*(xi_plus/xi_minus−1)
 + 7(g−164)/(kg)*(xi_plus/xi_minus) + 2
 + 2J/(kg*xi_minus) < 4.
```

Плюс выполнен точный циклический перебор всех W фаз для каждого k.
Следовательно, в K(q) нужен4/W при **новом W**, не4/524288.

tau=Pl_plus+E_plus+app_write_plus+10us+2J. Source-PAIR90с, короткий90с,
длинный180с и NR округлены по медленным часам с отдельным неполным первым
тактом/endpoint. Для w выбирается минимум гарантированного short-hold и
source-PAIR. Проверены защищённые окна w_hat>=Pl+Ps+d0, h>=w>tau,
NR>=h_upper+tau, 34-битные счётчики. Равенство остаётся FAST.

## Направленная мажоранта и полный риск

`informational.py` повторяет формулы T119 с явными W/ell/календарём;
неизменный `intervals.py` предоставляет48-digit направленные операции.
В каждом конце пары отбрасывается будущее, используются lower-массы
объединения раскрытых окон и старых непересекающихся клеток. Искажённая
гипотеза независимости последовательных LOW не вводится.

K(q) не возрастает. На каждой **целой** q-клетке [l,h] сохраняются K(l),
u,v и оба остатка u+v(q−b)−K(l)q². Последняя функция вогнута, поэтому
неотрицательные концы покрывают всю клетку, не только точки сетки.
Для q<=b действует u>=Pl*b². Сохраняются все клетки всех четырёх k,
а не лишь конечный график. J=min(Pl*S2,u*T+v*FS).

U_A=Delta+D1+I0+J/(2W)+X0. В базе D1=I0=0 по явным p1/clean-условиям;
Delta=6e-6 за весь срок. E-cross — минимум двух верхов T110 с beta0:

```
X1 = beta0*(k*d + Pl/W)*S2
v  = 2*beta0*d*(T/Ps_minus + 1)
X2 = min(B*Pl,F) * min(B*v, b*v+(2*beta0/W)*FS, (2*beta0/W)*F)
X0 = min(X1,X2).
```

Выбирается наибольший k объявленной сетки с U_A<=epsilon/2. Fixed-периоды
выбираются прежним тестом, их условия/темпы не подгоняются под адаптацию.
Новый адаптивный upper не является lower и не доказывает оптимум.

Проверки включают exact воспроизведение старого T119 u/v/J при его старом
W/ell/calendar, масштабирование конуса, циклические фазы нового W,
все q-клетки и вложенные фазовые интервалы. Контрольная старая строка
проверяет реализацию формул; её численный риск/цена не переносится.

## Границы вывода

Полная цена использует новый coupling upper на плохих историях,
обычные hold-полосы и отдельный source-veto v. Она не делает Poisson-поток
из реального ERR и не обнуляет CPU/energy/hardware caps. Задержка decoder39,
изменяющая tau/окна, требует новой q-проверки; чисто ресурсный запас не
становится автоматически запасом информационного сертификата.

Для p2/p3 отдельного lower-channel/сопряжения пока не сертифицировали;
в sensitivity честно оставлен generic mandatory-upper на выбранном k.
Даже singleton-cell в этом файле имеет эту диагностическую основу, тогда
как основной singleton U_A находится в informational.json/results.json.
Чувствительность не выдаётся за уже проверенный информационный перенос
произвольной физической смеси. Interword/δ_env/δ_init остаются UNKNOWN.
