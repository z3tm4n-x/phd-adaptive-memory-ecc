## Проверка доставки и безопасное воспроизведение

Orchestrator сверил все 53 файла с SHA-256 и Git blob SHA-1 инвентаризации,
проверил идентичности восьми файлов коррекции и повторно запустил предоставленный
проверочный скрипт, предварительно прочитав его. Получено точное совпадение
715 числовых полей: 30 строк comparison, 25 paired и 5 family. Исследовательские
модули не импортировались, моделирование, пилот и повторные тесты не запускались.
[Запись этого прохода](outputs/delivery_normalization/orchestrator_delivery_audit_2026-09-10.json)
отделена от предоставленной записи RE. Перезапуск того же проверочного скрипта
не является независимой реализацией научного метода.

Для проверки сохранённых файлов из корня эксперимента:

```sh
python delivery_tools/verify_unknown_d_delivery.py . --out /absolute/path/outside-experiment-audit
```

Скрипту нужны NumPy и SciPy. Его выход должен находиться вне эксперимента.
При проверке нормализованного дерева он перечислит также добавленные служебные
файлы; исходные 53 проверяются по отдельной инвентаризации архива.

Повторный модельный расчёт, если нужен SR, выполняется только в отдельной копии.
До запуска проверить наличие и SHA-256 `outputs/selected_analogue.json`:
`1524a034e9d863f44be5741c913796d67e31f235f9f38b0f352f617a8a271dbe`.

```sh
python -m pip install -r requirements.txt
OPENBLAS_NUM_THREADS=1 python -u reproduce.py --full --workers 4
```

`--retune` не использовать. Без selected_analogue.json режим --full сам запускает
pilot, поэтому одного отсутствия флага недостаточно. Даже запуск без --full
перезаписывает часть outputs; --full также перезаписывает lock/records/NPZ.
Исходный snapshot и исторические записи должны оставаться неизменными.
