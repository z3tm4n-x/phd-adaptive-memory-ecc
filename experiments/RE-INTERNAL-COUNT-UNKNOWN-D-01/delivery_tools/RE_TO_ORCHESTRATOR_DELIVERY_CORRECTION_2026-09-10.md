## 6. Безопасный порядок публикации

1. Сохранить исходный ZIP 8829f443… неизменным. Перед заменой ещё раз проверить HEAD ветки и отсутствие чужих незакоммиченных изменений. При изменившемся HEAD сначала разобраться в новых изменениях, не делать reset/force-push.
2. Синхронизировать только experiments/RE-INTERNAL-COUNT-UNKNOWN-D-01/ с содержимым подтверждённого ZIP. Старые исходники, отсутствующие в архиве, не оставлять скрытыми альтернативами. main, RES, RQ, DEC и другие входы read-only.
3. Сохранить исходные 11 .py/.json, lock-файлы, execution_record и NPZ побайтно. Не запускать reproduce.py в единственной публикационной копии до фиксации: он перезаписывает некоторые outputs, а --full также lock/execution_record и NPZ. README/HANDOFF и старые отчёты исправлять прослеживаемо; допустим минимальный вариант — сохранить архивные документы и добавить это датированное исправление, обновив DELIVERY_REPORT.md со ссылкой на него.
4. Не исключать исходные данные вместе со всем cache/. Для данного пакета именно cache/heldout_*.npz — сохранённые первичные результаты сравнения. Самый простой путь без изменения загрузчиков — явно добавить пять файлов вопреки .gitignore:

```sh
E=experiments/RE-INTERNAL-COUNT-UNKNOWN-D-01

git add -A -- "$E"
git add -f -- \
  "$E/cache/heldout_30.npz" \
  "$E/cache/heldout_100.npz" \
  "$E/cache/heldout_300.npz" \
  "$E/cache/heldout_1000.npz" \
  "$E/cache/heldout_3000.npz"
```

   Остальные временные cache, __pycache__, журналы и таблицы компилятора добавлять не нужно. Если данные переносятся в другое постоянное хранилище, требуется явная карта путей, неизменные хэши и проверяемый способ получения. Одного названия ZIP недостаточно.
5. Инвентаризация входного архива и манифест публикуемого дерева — разные объекты. Приложенный delivery_manifest_2026-09-10.json описывает оригинальные 53 архивных файла и содержит SHA-256/Git blob SHA-1. Если документация исправлена, манифест конечного дерева должен отражать её новые байты и отдельно сохранить исходные архивные идентичности. Не изменять старые validation_lock/execution_record ради нового manifest.
6. Проверять не только рабочие файлы, но и подготовленные к commit Git blobs. Проверить scoped diff, наличие пяти NPZ, совпадение 11 исполняемых файлов с lock, и отсутствие старых параллельных модулей. Затем обычные commit/push в разрешённую ветку без PR/merge и без force. Новый commit обозначить как публикацию конкретного архивного snapshot, а не как ранее существовавший implementation commit.

Новый манифест либо служебный код не следует размещать среди корневых .py/.json эксперимента: экспериментальный hashes() включает эти файлы в свой набор. Манифест подходит для outputs/, служебный проверочный код — для отдельного подкаталога, например delivery_tools/.

## 7. Проверка без изменения результата и повторный расчёт

Приложенный verify_unknown_d_delivery.py читает ZIP или распакованный каталог и пишет только во внешний каталог аудита. Он не импортирует исследовательские модули, не генерирует траектории, не вызывает pilot и не перезаписывает исследовательские outputs.

```sh
python verify_unknown_d_delivery.py /absolute/path/RE-INTERNAL-COUNT-UNKNOWN-D-01.zip \
  --out /absolute/path/independent-delivery-audit
```

Его зависимости — NumPy и SciPy. Манифест имеет фактическую дату проверки. Это достаточный ограниченный путь для сверки уже сохранённых данных перед публикацией, но не самостоятельное доказательство воспроизводимости модели.

Повторный модельный расчёт, если он нужен SR, выполнять в отдельной копии с сохранённой настройкой PA-DOM:

```sh
python -m pip install -r requirements.txt
# selected_analogue.json должен существовать и совпадать с validation_lock.
OPENBLAS_NUM_THREADS=1 python -u reproduce.py --full --workers 4
```

**--retune не использовать** для воспроизведения зафиксированного выбора. Более того, reproduce.py при --full автоматически запускает pilot, если selected_analogue.json отсутствует; его наличие и хэш нужно проверить до запуска. Пилотную процедуру можно исследовать отдельно, не подменяя ею уже зафиксированную сравнительную постановку.
