# Полная цена одного условного пилота до T

Все числа — **OWN RESULT в условной модели**, точные дроби в result.json.
Номинальные пути REPORT не являются средними. На каждой истории продолжаются
основной календарь и учёт после первого скрытого A. Последняя начатая
операция оплачивается полностью. На nominal конце T неполного scan нет;
это вычисленный остаток, а не отброшенный край. Формула считает и неполный
scan при других допустимых ξ/J, unit-тест проверяет границы начал операций.

## Основные действия, repair и guard

Основные scan начинаются в блоках0,2,4,...; один блок=25701088 ticks.
Startup отдельно; учебная часть —120000W чтений. При допуске пропускаются
scan в блоках240002,...,251998; scan252000 сохраняется, затем прежняя фаза.
За весь T база имеет804697012699136 nominal чтений, физический верх
N_b⁺=804705059733504, нижний804688965795840 при сохранённом календаре.
Это границы **цены этого пути**, не нижняя цена оптимального метода.
D=786300928 — сокращение чтений только при допуске.

Безусловный по историям модели физический cap N_h=1610097765253120
сохраняет все потенциальные слоты, включая guard в drain/wait и края.
Он требует принудительного освобождения ресурса даже на плохих историях;
малый Q сам такого свойства не доказывает. Если этого договора нет, данный
hard upper неприменим и нужен отдельный член цены зависшего исполнения.

Для каждого фиксированного допустимого r и канала обозначим p_g вероятностью
**совместного** события good execution ∩ допуск; G_g — ожидаемое число
дополнительных guard-чтений на good execution. Их закон не установлен.
Используем δ_exec≤δ₀+δ_C только при покрытии соответствующих ошибок:

```
S = min(N_h, N_b⁺ - D*p_g + G_g + δ_exec*N_h)
H = min(S, 2*F_parent + U_joint*N_h)
F_parent ≤ b*T + F_s = 23500956141/1187500
E[protection bus fraction] ≤ (48.50048*S + 56.50056*H)/(T*1e9) + B_controller
E[protection core fraction] ≤ (68.50068*S + 56.00056*H)/(T*1e9) + C_controller
```

S/H — достаточные верхние оценки ожидаемых reads/repairs, не прогноз.
Член δ_exec*N_h оплачивает нарушения календарного исполнения/счётчика,
на которых нельзя просто подставить номинальное число обязательных чтений.
Коэффициент56.00056ns core заменяет R⁺ на E⁺ для repair-транзакции;
это разность верхов двух полных типов операций, не измеренный WCET приращения.
U_joint из A11 покрывает глобально плохие истории; тогда оплачивается весь
hard-поток. Множитель2 учитывает повтор одного родителя при weak E.
F_parent — верх интегральной интенсивности, не детерминированный лимит
реализованного числа родителей. При δ_C≤5e-5 коэффициенты приведены численно
в JSON; без обоснования квоты этот подставленный ожидаемый верх не установлен.

G_g включает ERR, false, loss, restore, удержания и дополнительные veto.
Разделение по причинам должно быть непересекающимся: один занятый слот
не оплачивается несколько раз из-за наложенных причин. Длительности/частоты
guard нового правила неизвестны; старые коэффициенты T119 здесь не подставлены.
Отказ по счёту или восстановление не дают нового α и не запускают учёбу заново.
Необязательные guard-события не превращаются в обязательную нижнюю цену.

Универсальный always-E cap, **только известные операции**:
protection bus≤53.572495961%, core≤63.521677281%; вместе с app/init
bus≤53.577345915%, core≤63.528527215%. Управление, CPU и энергия остаются
параметрами ниже. Этот верх не равен средней цене или невозможности выигрыша.

## Общее приложение и начальная загрузка

Сохранён принятый физический профиль запросов:315569688607 app-read до T,
0 полезных writes после init. Полный read уже включает48ns read-beats+20ns
decode:32ns полезная нагрузка и36ns добавочная ECC-работа, без двойного счёта.
App не делает repair и не публикует ERR. Физический верх app:
bus=.004849951001%, core=.006849931002% от T.
До0 оплачены W encodes+3W write-beats+W turnarounds;
добавочные амортизированные доли bus≤2.346706151e-11,
core≤3.177398667e-11. Это доли, не проценты.
Контроллер приложения/CPU/энергия не входят сюда как нули.

## Доставка, обработка и неизвестные ресурсы

Для консервативной полной цены прежний канал остаётся оплачен до T, даже
после единственного запроса. Верх cut/ready:78894788947892;
raw source edges/records≤78894788947889481 (57бит), максимум32bytes/record.
Это число пересылаемых bytes, не объём одновременно занятой RAM.
Среднее число raw records неизвестно. Обычные квоты сохранены:
E false≤315.576, outage≤31557.6с, loss episodes≤1001, restores≤1000.
Они не ограничивают число всех новых подтверждений G после восстановления;
добавочный veto V остаётся параметром под общим source-edge cap.

119989 суммирований/закрытий использованных C; один финальный запрос.
Online exp/log/inversion нет: используется заранее проверенный порог3,
насыщаемая сумма принимает0,1,2,3,>3 (3бита). Gate/timer полного календаря,
ready/cut, raw decode и отдельные cause handlers тоже оплачиваются.

Для непересекающихся видов работ i полный вектор:

```
CPU fraction = sum_i E[N_i]*c_i_ns/(T*1e9) + idle_CPU
Energy_J = sum_i E[N_i]*e_i_J + T*idle_W
```

Виды работ: init encode/write; app read/decode; control read/decode;
repair increment; cut/ready; raw decode; ERR/FALSE/GAP/RESTORE/veto handlers;
закрытие C; добавление к сумме; decision/install; calendar gate/timer.
c_i, e_i, idle, B_controller_average/peak, C_controller — **UNKNOWN**.
Handler-коэффициенты должны быть добавочными к raw decode, чтобы не удвоить
одну CPU-операцию. Преобразования в один скаляр без весов нет.

Raw SRAM=786432bytes; прежние transport/loss=131136bytes. Из PR272 сохранён
пример packed счётчика64bytes; дополнительный вариант group-state32bytes:
sum1, flags1, reserved2, used-index4, deadline8, rare-end8, budget/state8.
Итого пример метаданных131232bytes, не доказанный sizeof, RAM/BRAM/WCET.
Код, стек, heap, LUT/BRAM, дополнительное управление и буферы — UNKNOWN;
они не исчезают из бюджета. Нового буфера входных данных/копии банка не вводится.

## Отделённая нижняя оценка

PR272@ed85 при своём G/δ_exec даёт необходимую ожидаемую read-цену всего
объявленного детерминированного класса:≥0.4854605% bus,≥0.6898650% core.
Она здесь только цитируется, не пересчитывается и не объявляется оптимумом.
В ней допустимо опустить неотрицательные repair/управление; в верхе пилота
они оплачены параметрами. Полного сравнения победителей по двум неравным
границам или по одному успешному пути не делаем.
