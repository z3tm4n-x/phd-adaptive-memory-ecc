# Перевод нижней леммы в цену

26.10.2026, OWN RESULT к #186; подстановка принятых §5, (9)–(14)
[PR267](../../../theory/hybrid-p-r-20261026.md).
Единственный вход и источники закреплены в manifest.json. Принятая лемма
не переписывается. Новый переход и числа предъявлены независимой проверке.

## Область и физические апертуры

S — заранее фиксированный детерминированный per-word календарь, робастно
допустимый для всех r согласованного класса. Условные исправления разрешены,
их результаты не выбирают следующие посещения. OFF включён; разные фазы,
неравномерность и перераспределение риска допускаются. Сетки k, случайной
смеси расписаний и адаптивных посещений в доказательстве нет.

Для каждого фиксированного допустимого масштаба ξ ∈ [.99999,1.00001]
номинальный физический якорь посещения a = ξ·tick. Старый размах ошибок
концов J = .5 нс даёт консервативно start ∈ [a−J,a+J] после закрепления
общего начала времени. Это требует исходного общего clock/epoch договора,
а не произвольного накапливающегося джиттера. Будущие ошибки не выбирают
якоря. Сервис ограничивает release−start сверху E⁺ = 124ξ⁺+J.
Поэтому фиксированная апертура [a−J,a+E⁺+J] покрывает все исправления:

    d_E = E⁺ + 2J = 125.50124 нс.
    R_bus⁻  = 48ξ⁻ − J = 47.49952 нс.
    R_core⁻ = 68ξ⁻ − J = 67.49932 нс.

R_bus учитывает три x16 beat. R_core дополнительно резервирует decode20 нс.
Это две координаты двустороннего условного сервиса, не измеренные задержки.
Использованы самые неблагоприятные границы ξ/J, а не номинальные часы.

Для буквально заданного физического календаря можно использовать апертуры
[s,s+d_E], где s — его заранее заданные физические начала: выбранный d_E
заведомо не меньше E⁺. Поэтому нижний счёт применим ко всему принятому
физическому классу независимо от способа его представления в ticks.
Расширение вокруг якоря — дополнительный способ связать тот же результат
с исполнимым tick-календарём, а не требование batch8 ко всему сопернику.

## Счёт и края

В (9) взяты h = R/g, L = F_r/R−h/2, D = h+L. В (11)–(13):

    κ = (38/78) exp(−BL/W) ((b+R)/W)²,
    Hε = −ln(1−ε−δ_exec),  δ_exec = 6e−6,
    f(x) = [L−d_E x]₊²/(x+1),
    f(x*) = Hε/(κW),
    N_envelope ≥ W x* (T−D)/(L+d_E).

δ_exec — осторожное использование общего прежнего служебного бюджета
для сопряжения исправного исполнения и реального, не новая независимая
квота. Статистические α/ζ сопернику не назначаются. Взятый (b+R) не равен
старому B: старый свидетель PR250 не переносится.

Направленная инверсия даёт x* ∈
[43199.0391269441462864179166964,
43199.0391269441462864179167018] и
N_envelope ≥ 32253088167246.8602323.
Целочисленный необходимый счёт — **32253088167247**.

Для точного физического календаря принятое (14) вычитает одну незавершённую
операцию; вычет двух тем более сохраняет нижнюю оценку. Для связи с
расширенными плановыми апертурами отдельно обоснован тот же осторожный
вычет **двух операций**:

1. У T может быть не больше одной уже начатой незавершённой операции:
   исполнитель последовательный, pending=false в 0.
2. Не больше одной ещё не начатой операции может дать пересекающую T
   расширенную апертуру. Её якорь лежит в полосе (T−J,T+J].
   В заранее исполнимом последовательном tick-календаре расстояние соседних
   якорей (включая возможные граничные посещения) не меньше
   R_core⁻−2J = 66.49932 нс > 2J = 1 нс; двух якорей там нет.

Это достаточный краевой запас, не утверждение его точности для любого S.
Произвольные фиктивные планы после T в N_envelope не включаются. Если
связываемая реализация не гарантирует разнесение/исполнение её плановых
якорей, этот перенос от ticks остаётся условным; прямой физический низ
из (14) сохраняется, а события нарушения планового исполнения требуют
описанного ниже покрытия.
Начальная инициализация закончена до 0. Начальные апертуры у 0 не пересекают
первое плато: h ≈ 5379 с намного больше d_E+2J. Другой начальной незавершённой
операции нет. Startup и все завершённые операции последнего прохода остаются
в счёте; целый последний проход не вычитается.

Таким образом, на хорошем исполнении оплачено не меньше
**32253088167245** полных чтений. То же доказательство работает при каждом
фиксированном ξ; случайный выбор календаря по среднему Q этим не разрешён.

## От геометрии к ожидаемой цене

Нужны следующие точные условия исполнения G:

- совместное построение с исправным локальным сервисом в фиксированных
  апертурах; Pr(Gᶜ) ≤ δ_exec при каждой допустимой фиксированной r;
- на G плановые посещения не исчезают из-за ERR, обычной потери канала
  или физического A; их порядок/полнота и двусторонние времена соблюдены;
- ресурсная цена неотрицательна и учитывается до T также на Gᶜ и после A.

Первое условие позволяет применить вероятностную нижнюю лемму с вычетом
δ_exec. Второе переносит детерминированный N_envelope в поточечный нижний
счёт на G. Только после этого для каждой фиксированной r:

    E[C_read] ≥ (1−δ_exec) · R⁻ · (N_envelope_integer−2) / T.

Независимость G от родителей не нужна. На плохих историях нижний вклад
можно взять 0, не считая их фактическую работу нулевой. Малая вероятность
ошибок памяти сама по себе множитель или сохранение планового счёта не даёт.
Квота без двух названных связей не доказывает нижнюю ожидаемую цену.

| Координата, доля полного T | Геометрический низ на G | Нижняя ожидаемая цена при договоре G |
|---|---:|---:|
| Чтения защиты: чистая шина | ≥0.4854634% | **≥0.4854605%** |
| Чтения защиты: serial-core | ≥0.6898691% | **≥0.6898650%** |

Низы округлены вниз. Формулы остаются параметрическими по исполнению;
при отсутствии покрытия/сохранения расписания ожидаемый физический низ
остаётся UNKNOWN, а геометрический результат сохраняется. В текущей
расчётной модели это явные SERVICE/common-input предпосылки, не доказанное
свойство конкретной аппаратуры. Новый δ_C агрегатора к сопернику не добавлен.

## Общая работа и неизвестные цены

Приложение имеет 315569688607 полных чтений, без полезных записей после общей
инициализации. На G его отдельная нижняя цена — ≥0.0047498570% шины и
≥0.0067497970% serial-core; общий ECC уже внутри, повторно не прибавляется.
Инициализация оплачивает W encode и 3W write плюс turnaround, до t=0,
с амортизацией на весь T. Точные общие нижние слагаемые сохранены отдельно
в result.json; перенос на ожидание помечен тем же условием G.

Repair, CPU, энергия и управление не объявлены нулевыми. Repairs можно
не добавлять только для нижнего предела чтений. Полный вектор стоимости
имеет дополнительные неотрицательные члены; их неизвестные удельные цены,
память, idle и пиковое обслуживание остаются параметрами. Для CPU и энергии
численный нижний выигрыш не заявляется.

Этот результат необходим для всего объявленного допустимого класса.
Он не предъявляет допустимое S, не является его оптимумом и не даёт
коэффициента выигрыша гибрида без сравнимого достаточного верхнего результата.
