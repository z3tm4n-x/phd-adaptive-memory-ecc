# LEO / положение: поставка входа 23.10.2026

**Результат — выбран кандидат и уточнён договор по ответу #196, не рабочая
точка с подтверждённым Q.** Основной кандидат — SAC-C-подобная орбита и
внешняя защита SRAM семейства KM684000. Есть первоисточники реального
бортового определения положения, наблюдений ошибок этой памяти и её
моделирования. Они ещё не образуют единую численную цепочку для нашего слова,
защиты и срока. Причинное правило — [RULE.md](RULE.md), точные входы —
[candidate.json](candidate.json), основания и расхождения — [SOURCES.md](SOURCES.md).

Задание принято в [#206/6358318419][accept]; план зафиксирован до новых
расчётов коммитом `3e6a0644683d8215c3c5f5a621eb1cc9932ed06b`, draft [PR231][pr].
База — `52fbda1b955a57dd68e5c3fc19caa33020dd5c9b`; новая ветка
`leo-position-control-20261022` по новому ASSIGNMENT. Старые A1–A5 и единственная
таблица #186/#196 сохранены. OFF включён решением автора, прежняя заморозка
поиска снята. Автор этой поставки не является её независимым рецензентом.

## Один основной кандидат

| Поле | Значение и статус |
|---|---|
| Орбита | 707 км, 98.2°; номинальный SAC-C-подобный кандидат по Duzellier, PDF 5; не восстановленная эфемерида |
| Начало и фаза | 2002-09-28 00:00:00 UTC; круговая орбита, нисходящий экватор, геоцентрическая долгота 0° — **ASSUMPTION** |
| Срок / риск | 315576000 SI с (10 юлианских лет); ε=0.001 — исследовательское требование, не длительность показанного полётного участка |
| Защита | 4 г/см² Al, равномерная сферическая геометрия вокруг памяти — **ASSUMPTION**; готовый соответствующий отклик не найден |
| Память | KM684000, 512K×8, 3.3 В — семейство из полётного источника; полный суффикс, кристалл/ревизия и date code **UNKNOWN** |
| Предлагаемая организация | Два одинаковых корпуса x8 параллельно, x16, 3 адреса/полное слово; это наш проектный вариант, не устройство платы ICARE |
| Данные / размещение | 524288 B полезных, 131072 слова по 32 бита; 786432 B занято при обоих кодах; 1048576 B установлено |
| Коды / активные биты | (39,32) и (44,32); соответственно 638976 и 720896 B активных кодовых битов; остальное в выделенных адресах — padding |
| Приложение | Неизменённый основной `strict_uniform_stage4` из v4; полные полезные записи с чтением старого слова; сервисные задержки для KM не назначены |
| Сведения | BlackJack/RTG как источник положения; публикация решения каждые 30 с подтверждена короткой демонстрацией, максимальные возраст/ошибка/доставка до ECC **UNKNOWN** |

Геометрическая модель эпохи и фазы объявлена в `candidate.json`; точная
пропагация и координаты опасной области ещё не выбраны. Дату демонстрации GPS
используем как начало исследовательского сценария, не приписываем ей выбранную
фазу или десять лет измерений. Источники называют 705, 707 и 730 км: это разные
номинальные описания, не установленная погрешность одной орбиты.

**OWN RESULT, только арифметика размещения:** адреса `3w..3w+2` укладываются
в два корпуса 512K×8; доля занятой установленной SRAM — 0.75. Это не запас
по всем аппаратным ресурсам. Ошибка в соседнем/padding-бите не даёт права
отбрасывать общее событие: нужен совместный закон по физическим позициям,
включая два корпуса. Полётные счётчики объединяют другие объёмы/компоненты;
пересчёт в интенсивность независимых ошибок нашего слова не выполнен.

## Что пока мешает вычислению и что делать

1. **Физический пакет.** Нужны численные спектры/экспозиции/пропуски по орбите,
   отклик одной версии памяти, группы и прямые события при объявленной защите.
   Опубликованная SAC-C геометрия неоднородна (Duzellier, PDF 6); она не равна
   нашим 4 г/см² Al. Нельзя повторно применять защиту или переносить старый GEO.
   Локальная правка: адресно получить уже существующий численный материал
   ICARE/MUSCA/OMERE и установить его область, без нового транспорта/облучений.
2. **Канал и способ управления.** Публикация GPS подтверждает существование
   бортового решения, но короткий RMS не ограничивает миссионную ошибку.
   Нужны пределы ошибки/возраста, интерфейс получения позиции и WATCHDOG;
   значения можно предъявлять как проверяемые требования к реализации.
   Если по тем же сведениям достаточно расписания, результатом станет
   расписание и его цена. Новый навигационный прибор не требуется.
3. **Другая точка, только одна.** Резерв — PROBA-1, 561×681 км, 97.9°:
   PSI описывает публичные SREM-файлы с эфемеридами и качеством. Это снимает
   потенциальный пробел совместной численной орбиты/радиации, но не заменяет
   отклик SRAM и не измеряет задержку бортового канала. Файл ещё не получен;
   две узкие попытки доступа не дали данных, причина/границы — в SOURCES.

**Рекомендация оркестратору:** оставить SAC-C основным до адресного входного
контроля 26.10. Если численный SAC-C пакет не устанавливается, проверить один
файл PROBA-1 с маской качества и принять отдельное решение о замене орбиты;
не ослаблять объём, ε или состав среды. Наличие каталога само по себе не
достаточно для замены. В пределах двух недель можно поставить один срез либо
точный остаток; подтверждённую физическую точку заранее не обещаю.

## Как результат входит в карту

На первом срезе сначала проверяются t1-fixed и t2-fixed, затем OFF для каждого
кода, затем управление положением и эквивалентное расписание. OFF означает
отсутствие отдельных проходов при сохранённых ECC и полных записях приложения.
Ранняя проверка OFF и предела полной цены по общей нагрузке предшествует
широкой обработке архива: [результат #186, PR230][geo] показывает, почему
это может изменить выбор. Его численный предел к LEO не переносится.
Общая историческая таблица остаётся в #186/#196; её числа не становятся LEO
строками. GEO подключается ссылкой #186, известные схемы — поставкой #196.

Новая строка A5 пока **UNKNOWN**: нет Q_upper/lower, подтверждённых периодов,
доли FAST, загрузки/ответа, цены кодека/канала и численного запаса. Нули вместо
этих полей не подставлены. После допуска нужны общий lifetime-бюджет, цена на
всём T и незавершённые операции, раздельные запасы Q/времени/ресурсов. Ориентиры
ε/2 и 20% сохранены. Утверждение о лучшем постоянном требует lower нового
класса F₀; успешная проверка одного периода его не заменяет.

Научный смысл первого результата: существование бортовой позиции подтверждено
лучше, чем её пригодность для гарантии. Выбор разработчика теперь зависит от
проверяемого времени упреждения, качества сведений и непредсказываемой части
среды. Простая карта SAA ещё не даёт выигрыш адаптации; переход к расписанию,
сильному коду или OFF остаётся полноценным результатом выбора.

## Проверка, календарь и передача

`verify.py` проверяет версии исходных файлов, SHA256 трёх PDF, точный перенос
разрешённых полей v4, размещение и явные незаполненные поля. Он не проверяет
физическую модель и не является независимой научной рецензией. PDF 4–6 Reichert,
3/5/6 Ecoffet, 5/6/9 Duzellier просмотрены также как изображения. Пакет проверок
сохранён в [verification.json](verification.json).

Из корня checkout, Python 3.10+, только стандартная библиотека:

```text
python -B experiments/leo-position-control-20261022/verify.py --pdf-dir <cache> --fetch-pdfs
```

Без `--fetch-pdfs` проверяются уже имеющиеся PDF. Имена/URL/хэши —
[sources.json](sources.json). В git PDF не включены. Веб-страницы прочитаны
23.10; они указаны как маршруты к данным, не как побайтово замороженный архив.
Повтор в чистом `git archive HEAD` должен дать тот же `verification.json`.

На [адресные вопросы][theory] получен [ответ #196][reply] / [PR232@58a5242][gate]:
достаточное основание — прежний moment/E-верх на фиксированных при каждом z
обязательных окнах. Добавлен общий календарь LOW/FAST; просто сохранённый
курсор окон не доказывает. J_FAST(z) должен охватывать слоты, обязательные
при всех хороших историях канала. Случайный фактический календарь в моменты
не подставляется. Длительная обнаруженная потеря допускается только с
покрытой переходной историей и ресурсом глобального FAST до T. Это полученный
методический путь, не независимое принятие и не подпись данного физического
входа. 26.10 — точные окна/сервис/среда и адресная подпись;
30.10 — один орбитальный срез и малая окрестность; 06.11 — пример
либо точный недоказанный элемент с рекомендацией и ядро карты. Один слот,
около двух недель; новые исследователи не нужны.
