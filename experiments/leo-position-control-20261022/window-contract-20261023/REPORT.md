## Что установлено

У правила положения теперь есть явное подмножество обязательных FAST-слотов,
общее всем хорошим историям при фиксированном внешнем пути z. Для пребывания
в опасной области [a,b], слота q_j=j*g и freeze q_j−f:

`H=W*g+c`, `L=h+d+f+H`,
`max(0,ceil((a-H)/g)) <= j <= min(ceil(T/g)-1,floor((b+f)/g))`.

Детерминированные внешние E-окна — `[j*g+e,j*g+c]`. Начало, базовый LOW,
переходы, потеря положения и хвост учитываются в
[CONSTRUCTION](CONSTRUCTION.md). Слабое E допускает удаление новых ошибок;
оно не создаёт их и удаляет старые. Совместные сроки службы/трубка остаются
явными предпосылками. Обнаруженная длительная потеря добавляет FAST, но
не даёт бесплатного ресурса: верх цены должен выдержать FAST до T.

Небольшой пример проверяет арифметику, **не представляет SAC-C/KM**:
W=8, g=1000нс, c=400нс, f=100нс, h=1000нс, d=500нс,
опасный интервал [15000,17000]нс, T=30000нс. Получены H=8400нс,
L=10000нс, J_FAST=7..17, всего22 обязательных слота с начальным проходом
и LOW k=3. При потере положения на весь срок исполняются30: подмножество
из22 не является верхом цены. Полные точные значения — [results.json](results.json).

## Ранняя проверка OFF и обязательной цены

Сохранённый исследовательский профиль v4 полностью перезаписывает каждое
из131072 слов раз в **131.07462144с**. Это предпосылка нагрузки, не
наблюдённая периодичность SAC-C. За10 лет предложено315569688607 полезных
чтений и315569688606 полезных записей; учитывается полное исполнение всех
предложенных до T запросов, в том числе завершение после T.
Начальная инициализация отдельно даёт131072 encode и393216 x16-записей.
Эти числа согласованы с принятым `#186/app-only/calendar_audit`; старые
Q, сервисные задержки и предел1.066372× не перенесены.

Для каждого n=39,44 сначала проверяется OFF: окна полезных записей
`[arrival,arrival+3000нс]` допустимы только после нового совместного
временного основания. На них применяется T196(8) с Phi_t, полными
массами/метками нового закона, direct, I0 и общими исключениями.
Достаточный результат — Q_upper≤ε (проектный ориентир≤ε/2), отдельно
временные/ресурсные запасы. Сейчас необходимые массы и сроки UNKNOWN,
поэтому OFF не объявлен ни достаточным, ни исключённым.
Превышение ε верхом само по себе его не исключит.

Полный обязательный вектор операций, включая prefix:

- x16-чтения:1893418131639;
- x16-записи:946709459034;
- decode:631139377213; encode и turnaround:по315569819678;
- запросы/ответы приложения:по631139377213, размеры заголовков неизвестны.

Одинаковые три адреса полного слова дают одинаковые количества шинных
операций для39/44, но не равные задержки/энергию кодека. Для каждого
ресурса цена — скалярное произведение этих количеств с его непересекающимися
стоимостями действий плюс полные расходы управления/проверки инициализации.
Коэффициенты пока параметры; CPU, LUT/BRAM и энергию не суммируем друг с другом.
Начальный префикс и работа после первого превышения не удалены.
Средняя/пиковая шина, задержки, ресурсы и три запаса — пока UNKNOWN.

Если OFF44 получит достаточный сертификат, в **одной** обоснованной
скалярной метрике действует ранний предел T196(9):
`gain <= C_OFF44_upper / C_application39_lower`.
При малом пределе уточнение канала не обоснует крупный выигрыш по полной
цене. Если OFF не получил достаточного верха, следующий шаг — постоянные
периоды/расписание; отсутствие сертификата ещё не lower класса.
Новый профиль редких записей #186/PR235 здесь не заимствован: он отдельно
исследуется #186/#196. Для LEO изменение полезной нагрузки потребовало бы
своего содержательного основания.

## Физический кандидат и решение

Адресный [протокол доступа](ACCESS.md) установил два отдельных остатка.
SAC-C/KM не имеет полученного здесь совместимого численного пакета
с экспозицией/качеством и полным откликом/метками предлагаемого слова
после4г/см². Публичные маршруты единственного резерва PROBA-1 также не
дали файл: PSI недоступен, ESA ODI — ошибка сертификата, ESA SWE — HTTP401.
Проверка содержимого реального PROBA-файла **не выполнена**. Существование
описания формата не выдано за успешно проверенный файл.

Рекомендация: получить один штатный PROBA-файл через существующий доступ,
но до согласованного отклика SRAM не менять статус кандидата на подтверждённый.
Локальное получение данных, t2/OFF/расписание и смена среды сравниваются
в ACCESS; новые орбиты/контакты/транспорт не запускаются. При открытом
физическом входе расчётный срез30.10 остаётся условным; объём одного слота
и ориентир ядра06.11 сохранены.

Практический вывод: положение полезно лишь если новые обязательные окна
меняют допустимость или цену относительно сильного кода/OFF и заранее
вычисленного расписания. Если трубка заранее известна, правило даёт то
же расписание. Число «30с GPS» не устанавливает необходимую частоту
обновлений. Проверяемое требование пока параметрическое:
`доступный горизонт трубки >= h+d+f+W*g+c`. Численный порог и физический
выигрыш назначать сейчас не из чего. Это граница результата, не
доказанная бесполезность адаптации.

## Проверки, повтор и запрос #196

Python3.12+, стандартная библиотека; сеть и PDF для численного повтора
не нужны. Из корня репозитория перейти в этот подкаталог:

```text
cd experiments/leo-position-control-20261022/window-contract-20261023
python -B -m unittest -v test_windows.py
python -B reproduce.py --check
```

На Windows допустим `py -3.12 -B` либо полный путь установленного Python.
`--write` сознательно пересоздаёт только локальный results.json.
Проверяются шесть принятых входов по хэшу с нормализацией CRLF→LF,
неизменные W/T/ε/поля нагрузки, точная арифметика окон и сохранённый выход.
Девять тестов включают малые переборы границ/пересечений,2187 вариантов
задержек команд с тремя вариантами потери, контрпример без freeze,
опоздавший LOW, старт в зоне, конечный pending и сжатый десятилетний счёт.
Они проверяют реализацию; аргумент «для всех историй» изложен отдельно,
независимая научная рецензия ещё требуется.

Адресный запрос #196: проверить формулу J_FAST и все границы при указанных
предпосылках; согласовать внешние E-окна/детерминированный выбор окон с (8),
включая незавершённый хвост и useful-write. Затем назвать минимальный
незакрытый физический/временной член для применения. Это подпись точного
нового входа, не повтор общего допуска PR232. До ответа `method_applicability`
для конкретной новой конструкции остаётся «на проверке».
