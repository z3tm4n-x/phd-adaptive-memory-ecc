## Реализация и область проверки

Принятый источник/FIFO передаёт **все** события. Сборщик50МГц сохраняет
неизменяемый префикс с G, source/processing timestamps, ERR/recovery,
sequence/counts/health. Событие на cut относится к следующему пакету.
ARM определяет пары ERR, NW/NH/NR и not_before; PL проверяет ответ, ждёт
программный срок, доставляет через XPM и запрещает устаревший LOW на том
же быстром фронте. Frozen skips и pending correction прежние. Устаревшее
ещё не переданное решение можно заменить, историю — нельзя.

Ускорение драйвера не меняет правило: base_G берётся из предыдущего
обработанного пакета, start — из первого, count — из разности G; reserved=0.
Нулевые ERR/recovery-поля не читаются. После аппаратного release сразу
запрашивается новый snapshot, без лишнего диагностического ACK. Полные
sequence/end_G читаются и проверяются. Индукция на **фактическом RTL**
доказывает используемые идентичности, неизменяемость банка и release только
после принятия проверенного ответа. Условия: один владелец, no runtime
reset/тихое искажение MMIO, Device/shareable/non-cacheable и упорядоченное
завершение. Fault терминален; вечный FAST не считается обычной priced recovery.

Raw Oracle обрабатывает события абсолютными сроками; C — summary/countdown.
Общие ABI/константы, не функции обновления. driver_reference.c сохраняет
алгоритм a477950 для регрессии, **не является независимым oracle**.
В Unicorn Cortex-A9 ELF исполняет main, драйвер, правило, CRC и DMB; каждый
MMIO проходит в Icarus с настоящим mailbox. Host C не подставляет ответ.
Отдельная полная связка использует native C/DPI, vendor XPM и независимый
ETransaction-checker. Это композиция, не физически тактовая модель hard PS7.

ISA-тест не начисляет время инструкциям/OCM/DMB/GP0/SmartConnect.
SLVERR виден мосту и последующему sticky fault; ARM Data Abort/его обработчик
не моделируются. Qualified startup/OCM/MMU — условие, не boot-продукт.
При ≥2 ERR программа явно проверяет source-span≤PAIR; неограниченная
история не объявляется точным summary. Прежние функциональные проверки
полных таймеров/потери/восстановления сохранены.

## Временной остаток и решение

Сохранённые наблюдения e8b1225; нынешняя исправленная достаточная
композиция **буквального** срока (не срока предвычисления):

`80,500800 +36,500360 +5189,022209… +2B +600,506000 +748,507480 ≤10000 нс`.

B включает **весь** cut-to-cut: polling, чтения, вычисление, записи, CRC,
канал и ACK. Множитель2 оплачивает событие сразу после cut. Цифровой верх
доставки сертификата545,505440нс при allocation600,506;
с10% запасом allocation660,5566<1мкс. Это не перенос времени slow_rule на CPU.

| ARM/RTL тест | Наблюдённый max cut-to-cut | Ещё не оплачено |
|---|---:|---|
| Старый scalar MMIO | 1980нс | CPU/OCM/DMB/GP0/SmartConnect |
| Сокращённый MMIO | **1620нс** | то же; после CDC-поправки до allocation **52,481575нс** |
| Сокращённый, тестовые stalls0…7slow ticks | 3640нс | то же; stalls не являются измерением PS |

В сокращённом нулевом тесте686…849 ISA-инструкций между CLAIM, не тактов A9.
Ни остаток, ни превышение в отдельной трассе не решают универсальное
условие10мкс. [Исторические числа](outputs/timing-residual.json) сохраняют
старые70,731756нс; текущая поправка в [advance-budget](outputs/advance-budget.json).
Непрохождение достаточной композиции не доказывает невозможность исполнителя.

Доступные GCC/QEMU, Unicorn, Icarus/Yosys, Vivado/XPM/PS7 проверены.
[QEMU отличает icount от cycle-accurate эмуляции](https://www.qemu.org/docs/master/system/invocation.html).
[AMD UG585 v1.15 от06.02.2026, CPU→GP](https://docs.amd.com/r/en-US/ug585-zynq-7000-SoC-TRM/Cortex-A9-CPU-via-General-Purpose-Masters)
описывает ограниченную пропускную способность, не верх задержки нашего
пакета. Эти страницы проверены13.10.2026. Произвольный CPI или throughput
не использованы как WCET.

| Вариант | Оценка и решение |
|---|---|
| Локальное ускорение scalar MMIO | Выполнено;360нс выигрыша в тесте. Следующие мелкие правки не дадут отсутствующий platform service upper. |
| Предвычисление /другой транспорт | Summary и отложенный сертификат уже реализованы. Проверен новый достаточный договор. Burst/ACP не назначен без необходимости; scalar service пока UNKNOWN. |
| Договор /рабочая точка | Автор разрешил разделение сроков по #146 без изменения научной точки. Выделен1мс; верх CPU из этого не возникает автоматически. |

**Рекомендация:** quantitative advance-договор выше, без мелкой
оптимизации scalar polling. Для завершения В нужен также обоснованный верх
Cortex-A9/OCM/PS–PL: минимальная частота, cold/cache состояние, арбитраж,
DMB и программный прогресс. После решения по нужному сроку выбирать
транспорт только при фактическом недостатке scalar. Временная модель или
документированные односторонние границы разрешат пробел; физические
измерения сами по себе дадут лишь максимум и поручением запрещены.
Новых закупок/испытаний не предпринято.

| Условие | Основание → проверка | При нарушении |
|---|---|---|
| Префикс, no reset, source-span, один владелец | ABI → raw Oracle, ARM/RTL, collector/ACK induction | Fault; обычная цена не заявляется |
| Упорядоченные XPM, непрерывные часы | Принятые леммы → vendor traces, guard/join | Нет общего срока/сохранности |
