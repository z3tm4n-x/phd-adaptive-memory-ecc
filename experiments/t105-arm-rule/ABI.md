# T105: реализованный пакетный ABI

Little-endian, AAPCS32. Ключевые структуры — batch.h; static asserts
96/72/32 байта. Все времена и поколения — 64 бит, runtime reset запрещён.
Первый тестовый ABI 32 байта из rule.h сохранён для поэлементной проверки.

## История: 96 байт

Десять u64: sequence, base_generation, end_generation, end_tick, start_tick,
first_err_source, last_err_source, first_err_tick, last_err_tick,
last_recovery_tick. Затем event_count:u32, err_count:u32, flags:u32,
reserved=0:u32. Маски flags: started=1, healthy=2, internal_recovery=4,
event_at_end=8, fault=16.

end_tick — предыдущий фронт перед cut в непрерывном 50-МГц домене;
source timestamp — исходный 250-МГц момент. Ошибки до/после cut не смешиваются.
Количество событий равно end_generation−base_generation. Пакет остаётся
неизменяемым до принятия программного ответа, а живой накопитель работает
независимо. Инициализация допустима только до квалифицированного начала.

## Ответ: 32 байта

sequence:u64, generation:u64, not_before:u64, flags:u32, crc32:u32.
Flags: 0 — нет разрешения, 1 — разрешить не раньше срока, 2 — явная ошибка.
CRC32 IEEE reflected покрывает первые 28 байт; Python zlib и C проверяют
сверку с RTL. Проверка RTL — 7 тактов по 32 бит, не 28 тактов по 8 бит.

При нарушении seq/G/CRC новое разрешение не устанавливается, fault sticky.
Корректная ordinary loss/recovery обрабатывается без сброса миссии.
Аппаратный guard снимает старый LOW на фронте публикации изменения G.
Уже frozen skip и выполняемая корректирующая запись не отменяются.

## Карта AXI-Lite: base 0x40000000, 4 КБ

| Смещение | Значение |
|---|---|
| 0x000 R | status, номера битов: snapshot_valid=0, validating=1, decision_valid=2, started=3, fault=4 |
| 0x004 W=1 | CLAIM: создать следующий снимок; только без удерживаемого банка |
| 0x008 W=1 | COMMIT: проверить полностью записанный ответ |
| 0x00c W=1 | программный FAULT, без runtime reset |
| 0x010/014 R | последний sequence, принятый медленной доставкой |
| 0x100…15c R | 24 слова неизменяемого снимка |
| 0x200…21c W | 8 слов shadow-ответа; учитывается каждая WSTRB |

AW/W независимы. B/R удерживаются при backpressure. Неполные, неверно
выравненные или неизвестные команды получают SLVERR; неполный shadow
не публикуется. Все 32 байта должны быть записаны перед COMMIT.
CRC/sequence/G mismatch дополнительно фиксирует fault.
Обычный B-response COMMIT подтверждает проверку, **не применение в 250 МГц**.
Счётчик 0x010 означает приём медленной частью; он также не fast ACK.

driver.c использует Device/shareable/non-cacheable MMIO и DMB SY,
проверяет статус/sequence без сброса накопленной истории. Параметры
памяти обязан установить внешний квалифицированный запуск; он здесь
не реализован. Firmware не содержит скрытого fallback после ошибки.
Сокращённый драйвер читает sequence/end_G/end_tick, err_count/flags;
start_tick — только в первом банке, ERR-поля — только при err_count>0,
recovery_tick — только при соответствующем флаге. Остальное восстанавливается
по отдельно доказанным инвариантам collector: base_G=предыдущее end_G,
count=end_G−base_G, неизменный start, reserved=0. Это не обнаружение
произвольного искажения памяти/шины; оно вне объявленного цифрового договора.

После phase2 status[2:0]=0 разрешает следующий CLAIM: при отсутствии fault,
одном владельце и no runtime reset банк может исчезнуть только после
sequence/G/CRC-проверенного decision_valid&&ready. Это доказывает slow-side
приём, **не fast ACK**. Диагностические 0x010/014 больше не перечитываются;
полный sequence следующего банка всё равно проверяется. Новая CLAIM после
32-го завершения входит в число MMIO-записей даже при остановке теста.

verify_driver проверяет 20 019 пакетов/широкие границы, verify_isa исполняет
весь ELF с RTL mailbox. IRQ/FIQ отключены start.S; caches/MMU/OCM и clocks
должны быть установлены квалифицированным входом. BFM отображает SLVERR
и sticky fault, но не моделирует ARM Data Abort/обработчик исключения.
Это не аналоговая/PS7 временная проверка.

## Доставка интервала

После max(приём, not_before) interval_link передаёт 65 бит G+LOW через
неизменённый стандартный handshake_channel/XPM. Частые CONTROL
по-прежнему выдаёт локальный календарь, не ARM. Нет per-frame beacon.
Пока G не меняется, разрешение можно использовать на следующих freeze.
Новый G немедленно запрещает его; возврат к старому G/сброс запрещены.

Одно ожидающее, ещё не переданное решение может быть замещено более новым
поколением. Принятые в XPM payload удерживаются до handshake.
Полнота истории доказывается отдельно sequence/base/end и обработкой
префикса, а не количеством доставленных давно устаревших разрешений.

Неизвестны WCET CPU/OCM, срок PS7/GP0 и полный цикл B. Буферизация не делает
эти величины нулевыми; пределы/ограничения — TRANSPORT_CONTRACT и REPORT.

Текущее дополнение13.10: ADVANCE_CONTRACT явно заменяет внутреннюю строку
10мкс по решению автора; выбран полный service allocation1мс, не WCET.
Режим C0 задаёт параметры только хешированным образом до qualified start,
без runtime-перенастройки, нового init или сброса миссии.1013 выровненных
адресов вне перечисленных write-команд/банка проверены как SLVERR без
изменения удержанного snapshot/decision/ACK. Поддержка онлайн-конфигурации
не заявляется; новый образ требует нового отдельного квалифицированного опыта.
