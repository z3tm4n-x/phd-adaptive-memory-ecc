Issue #110; зависимый draft PR #111 к `t104-new-rtl-executor`.
Инженерные входы: `36f0dab3cfb1e051b9480d02c5aae303e943ecfe`.
Принятые T95/А и пакет инженера сохранены.

Результат — условное научное дополнение с доказательствами, двумя адресными
подстановками и областью допустимого трафика, не реализация RTL/В/Г.

Календарь: группы 8, c164, g192, ka83, gate256 тактов.
Виртуальные начала и явный член незавершённого E заменяют clean-U.
Реальная занятость 92/148 тактов отделена от резерва 104/164 и периода Wg.
Цена включает послеотказные истории, фоновые/ложные ERR, плохие окна,
возвращения, X и края срока. Потеря монитора сохраняет тот же общий риск;
малую цену при неограниченной потере не обещаем.

Чтение приложения — атомарное 32 data без inline repair. При условном
backpressure≤100 нс достаточная общая для метода/постоянного соперника область:
совместная счётная огибающая CPU/X с 1≤b≤1,4027920469,
ρ≤588229,4118 запросов/с и неравенством задержки (6).
X: работа≤209 нс+10⁻⁴t. Это проектная область, не подстановка выдуманного
полезного потока; старые 4%, b8/2М запросов/с не объявлены допустимыми.
Физические full38/ERR/E-aperture, монитор, I/O/clock/CDC/WCET неизвестны.

## Повтор

Python≥3.10, стандартная библиотека, offline:

```sh
python -B experiments/t110-err-write-service/verify.py
```

По умолчанию нет записи файлов. Штатный пакет инженера повторяется первым:
28+15+49+71 проверка, 20 blob и оба его JSON. Затем **111 адресных проверок**
T110 и побайтовое совпадение новых `report.json`, `handoff.json`.
Числа — точные рациональные границы, включая конечные хвостовые оценки
и соседние периоды. Малые контрпримеры/фазы не заменяют аналитическое доказательство.

`--write` предназначен только для осознанной генерации двух новых JSON T110
после изменения формул; принятые источники не записываются никаким режимом.
Нет случайных прогонов, новой сетки T58, общего оптимизатора или кампании.

Файлы: `inputs.json` — два фиксированных расчётных назначения;
`pinned_sources.json` — 12 дополнительных проверок неизменности;
`calculate.py` — точные формулы; `verify.py` — граничные проверки;
`report.json` — полный расчёт; `handoff.json` и
[ENGINEER_HANDOFF.md](ENGINEER_HANDOFF.md) — новый контракт.
Научный SHA публикуется в описании/комментарии PR, без самоссылки внутри commit.
Независимую адресную рецензию назначает оркестратор; собственные проверки
не объявляются её заменой. Принятие результата и слияние — за Иваном.
