**Предлагается 0,25 МиБ при ε=10⁻³.** Реализуемый период 51,380224 мс равен четырём периодам непрерывного обхода. Его верх Q за десять лет равен 0,0008538619. При одном классе ГСО любой допустимый постоянный режим требует **не менее 5,0916%** чистого времени шины. Для кандидата достаточно **6,2112%** в модели защитных операций. За весь срок это соответственно ≥16 068 003 с и ≤19 600 775 с. Уже необходимая нижняя цена выше ориентира 5%. Выбор объёма для Ц3 и контраста LEO принадлежит Ивану. **0,125 МиБ** при основном допуске имеет кандидат k=18 с верхом 1,4026% шины. В **0,5 МиБ** требуются как минимум 20,382%, сертифицирован непрерывный обход. Для 0,25 и 0,5 МиБ необходимое число чтений выше максимума соответственно в 1,998 и 7,993 раза или более, чем исключается весь объявленный постоянный класс.

## Границы Q и периодов

Верх строится по (11) THEORY с новыми B, S₁ и S₂ из [общего класса](CLASS.md). При W полезных 32-разрядных словах положим K=39·38W/(2D²), d_E=124ξ₊+3J в наносекундах, Pₖ⁺=196kWξ₊ наносекунд плюс J. После перевода в секунды верх равен min(1,δ₀+d+K[(Pₖ⁺+d_E)S₂+2B d_E S₁]). Здесь δ₀=6·10⁻⁶, d ограничивает ожидаемое за весь банк и срок число родителей, каждый из которых поражает не менее двух разрядов хотя бы одного слова. Для основной таблицы d=0 условно. Кандидат 0,25 МиБ сохраняет допуск при сумме дополнительных вероятностных вкладов до 0,00014613817, в том числе при обеих прежних опорах d=10⁻⁵ и 10⁻⁴ по отдельности. Полная вероятность для физической памяти зависит от закона меток и исполнения. [Математическое основание](../regime-map-methodology-20261019/predictability-volume-20261028/THEORY.md) · [Временной сервис](../regime-map-methodology-20261019/predictability-volume-20261028/RESOURCE.md) · [Прямой вклад](../t413-cy62167-placement-d2/README.md).

Для необходимой цены взяты допустимые часы ξ₊, нулевой джиттер, полный исходный одиночный закон внутри класса верхних ограничений и профиль высокого старта длительности F/(B−b). Первый отрезок в одну секунду отброшен, он длиннее первоначального прохода у всех трёх объёмов. Остаток плато разбит на равные части L≤120 с. При любом физическом периоде P≥P₀ и любой фазе на часть приходится не больше M=L/P₀+2 апертур слова. В (13)–(15) использованы свободное время [L−Md_E]₊, направленные нижние границы exp(−uL)≥1−uL, 1−exp(−Z)≥Z/(1+Z) и вычет δ₀. Превышение допуска даёт обязательное число чтений (1−δ₀)W[T/(P₀+J)−2]₊. Средняя необходимая цена охватывает весь класс постоянных периодов, в том числе фазы вне сетки кандидатов. Она не равна цене предполагаемого оптимума.

На реализуемой сетке k=1,2,… для 0,25 МиБ при 10⁻³ исключены все k≥5, включая периоды за пределами конечного меню. Порог исключения произвольного физического периода не больше 61,137628 мс. Для 0,5 МиБ при 10⁻³ все k≥2 исключены, общий порог не больше 30,545579 мс; между Pmin и этим порогом вывод о произвольном исполнении открытый. Для 0,125 МиБ при 10⁻³ у k=19 интервал Q составляет 0,0009964568…0,001012831, все k≥20 исключены. Для 0,125 МиБ при 10⁻⁴ у k=2 интервал 0,0000999030…0,000111986, все k≥3 исключены. Границы включают неопределённость сертификата, поэтому для этих двух соседних ступеней окончательного статуса нет.

## Цена и ресурс

Для каждого объёма календарь заново построен принятой функцией предрасчёта ресурса. Три чтения x16 на кодовое слово занимают 48 номинальных нс шины и 68 нс последовательного обслуживания, дополнительная запись ремонта — 56 нс. Учитываются часы, джиттер, ремонт по числу инверсий, продолжение после неисправимой ошибки, край срока и гарантированный запас по исполнению. Инициализация до t=0, приложение и управление имеют отдельные статьи цены. В основной строке последовательное обслуживание защиты составляет ≥7,2354% для класса, ≤8,7623% для кандидата. Приложение добавляет на шине от 14 989,40 до 15 305,29 с за T, инициализация — ≤0,003703 с. Верх известных операций защиты вместе с приложением и инициализацией равен 19 616 079,29 с. Неизвестная добавочная работа управления C_bus и C_serial входит в соответствующие полные цены сверх известных статей. Затраты CPU и энергии также остаются отдельными параметрами.

В любом окне 1 мс совместные верхние оценки составляют 57,934624% шины и 67,936577% последовательного обслуживания при лимите 80%. Для дополнительной последовательной работы остаётся не менее 12,063423 процентного пункта вместе с условиями прежнего слота и атомарности. Верх ответа приложения 2,533018 мкс при сроке 3 мкс. Ни один из этих показателей не заменяет измерения физического времени выполнения. [Ресурс и точные данные по каждой строке](six.json).

## Воспроизведение

База main `e5055f5e9928ca09320e454f3dcddfbe1631f58f`. Нужна вторая рабочая копия на SHA PR419 `c944c91a2c20a207516824333e02711aaf34898f` и внешние кэши, описанные в [PR419](https://github.com/z3tm4n-x/phd-adaptive-memory-ecc/pull/419). При наличии объектов обеих веток можно создать копию командой `git worktree add --detach ../pr419 c944c91a2c20a207516824333e02711aaf34898f`. Параметр `--previous` обозначает корень именно этой рабочей копии. Кэш пятиминутных GOES должен содержать выданные PR419 дневные свёртки. Кэш минутного расчёта создаётся отдельно по списку и контрольным суммам T67. Команды из каталога опыта для Python 3.12 с NumPy, SciPy и h5py приведены ниже.

```text

python coverage.py --previous <pr419> --sepem-cache <t141> --windows <windows.npz> --goes-cache <goes5> --check
python cadence.py --previous <pr419> --minutes <minutes> --goes-cache <goes5> --sepem-cache <t141> --check
python growth_check.py --previous <pr419> --minutes <minutes> --goes-cache <goes5> --sepem-cache <t141> --check
python fixed_six.py --previous <pr419> --check
python verify.py
```

Сохраняются расчётный статус класса, независимая приёмка, ограничения физической скорости внутри бина, экспозиция пропусков GOES, размещение и пространственные метки. Результат по постоянным периодам и решение о выборе объёма предшествуют Ц3.
