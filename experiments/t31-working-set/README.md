### Особенности полного повторения

1. В GOES-16 `verify_prereg` проверяет, что `870a3c5d…` является предком HEAD.
   Адресный перенос файлов в T0 не создаёт такой истории. Полный исторический
   повтор запускается в отдельном checkout тега, без отключения защиты:

   ```bash
   git fetch origin tag v1/research/internal-count-goes16-validation-01
   git worktree add --detach ../t31-goes16-replay refs/tags/v1/research/internal-count-goes16-validation-01
   ```

   Далее — его `REPRODUCE.md` с зафиксированной средой и внешними входами.
   Этот научный повтор в T0 не запускался.
2. Исторический COSRAD `verify_package.py` возвращает ошибку двух лишних файлов
   `delivery_b/`: это позднейшая утверждённая поправка, не повреждение переноса.
   Все 34 файла исходного манифеста проверены по размеру и SHA-256;
   поправка и манифест также сверены с `5e75ab99…`. Проверка рабочего набора
   явно допускает ровно эти два дополнения. Старый скрипт и manifest не изменены.
3. Версии библиотек исторических кампаний перечислены в их REPRODUCE/provenance;
   установленная среда T0 им не тождественна. Новый численный результат на другой
   среде не заявляется. Установка зависимостей и аппаратные проверки не выполнялись.

  проверку пиков, задержек, начального состояния и аппаратных ресурсов.

## Решения автора для R0

| Что определить | Почему требуется решение до расчёта |
|---|---|
| Горизонт 5 или 10 лет; основной ε и уровни чувствительности | Задают исследовательское требование, не извлекаются из старой недельной кампании |
| Орбита, 1 мм Al, тип интенсивностей, неопределённость и временной канал | Пока нет новой поставки COSRAD и полного контракта среды |
| Оплачивать весь резервированный слот или фактические обращения; определение периода | Меняет стоимость, допустимые расписания и смысл 125,82912 с |
| Окно измерения пика и арбитраж | При плотном проходе интерфейс занят 100% внутри прохода; без окна 25% не проверяется |
| Поток запросов приложения: burst/огибающая, чтения/записи, смысл предельной задержки | Средняя загрузка 50% сама по себе не ограничивает максимальную задержку 3 мкс |
| Неизменяемый буфер либо протокол согласования записи приложения с pending correction | Редкие записи сами по себе конфликт не исключают |
| Чистое начало как модельное условие либо явная процедура подготовки | Старый условный сертификат исполнителя и чистый старт RES имеют разные области |
| Статус 300 нс и безотказность ECC/контроллера | Проектный бюджет слота не является измеренным WCET; физический перенос открыт |

Рекомендация для решения PI: сначала согласовать ограниченную модельную версию
R0 с явно объявленными началом, записями и ресурсными определениями. Альтернатива —
сразу включить изменяемую память и физическую подготовку; это требует отдельного
инженерного задания. Ни один вариант этой поставкой не принят автоматически.
