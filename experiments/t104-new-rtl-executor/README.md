# T104 — этап Б T96: временная реализация и новый RTL

Задача [#104](https://github.com/z3tm4n-x/phd-adaptive-memory-ecc/issues/104),
пункты карты R4/R8. Ветка `t104-new-rtl-executor` от main
`5b463280be672d1c0fcc839b95c786d7c624b8be`; отдельная поставка после принятого А.

Первый шаг — проверка временной реализации **до основного RTL**:
совместное U≤99999/1100000000000 с, неделимый запрос приложения≤45 нс,
запас 10%, исходные календарь/LOW/окна. Наивные 48+48 нс не подходят.
Проверяются полный pin timing, подфазы, ранний приём команды, CDC,
джиттер, накладные расходы и достаточное ограничение конечной очереди.
Неизвестные величины не заменяются нулями.

Принятые входы: А на `96e1cc58ffe91ea5ef6ac3960fb4da03423b56d1`,
T95 на `8ecc8fb24213e03110789646725481cd34d09ab9`, CONTRACT/INTERFACE T90.
Повтор при старте 05.10.2026: **49/49 А, 71/71 T95**, без перезаписи;
поставка А совпадает с принятой версией.

```sh
python -B experiments/t96-hybrid-rule-implementation/run.py
python -B experiments/t95-method-regime-map/verify.py
```

После совместимой временной реализации — RTL с нуля и свойства по #104.
При несовместимости — точный мешающий параметр и два варианта решения автору;
принятые параметры, научные файлы и эталон А самостоятельно не меняются.
Функциональные записи остаются вне Q(T). В/Г не выполняются;
старые RTL/AC701 — только идеи и тесты. PR сливает автор.
