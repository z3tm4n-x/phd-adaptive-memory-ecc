# T104 — этап Б T96: временная реализация и новый RTL

Задача [#104](https://github.com/z3tm4n-x/phd-adaptive-memory-ecc/issues/104),
пункты карты R4/R8. Ветка `t104-new-rtl-executor` от main
`5b463280be672d1c0fcc839b95c786d7c624b8be`; отдельная поставка после принятого А.

**Итог первого шага: совместимое исполнение не установлено; основной RTL
ожидает решения по времени приложения.** Паспорт допускает read access=45 нс
на выводах. В полном запросе≤45 нс отсутствует бюджет пути к памяти,
обратного пути и захвата. Для фиксированного числа подфаз при исходном
допуске часов необходимый worst-case интервал уже ≥45,000900009 нс,
ещё без дополнительных задержек. Это исключение рассматриваемого способа
исполнения, а не всех архитектур или принятой условной теоремы.

| Требование | Выбранный для проверки способ | Граница времени | Основание / остаток |
|---|---|---|---|
| Исходные s/f/d | Счётчик 4ξ; метки LOW/hold без округления | Точные кратные 4ξ | А/T95; физическая привязка и джиттер неизвестны |
| Совместное U≤90,908181818 нс | Два отдельных цикла, пробная подфаза ¼ξ | 90,500905 нс до прочих расходов; остаётся 0,407276818 нс | Оптимистическая проверка, полный pin timing не закрыт |
| Неделимый запрос≤45 нс | Один цикл на той же подфазе | 45,2504525 нс >45 нс | Несовместимо уже без дополнительных расходов |
| Чтение→запись одного alias | Захват DQ/ERR → OE↑ → освобождение DQ → обратная запись | HZ≤18 нс; setup≥25 нс; WE pulse≥35 нс | Паспорт с.10/14; задержки конкретного FPGA/платы неизвестны |
| Раннее получение команды | Неактивный shadow до a−1; not-before=a | Первое решение после a — a+3, границы LOW прежние | Проекция семантики проверена; CDC/физический apply ещё не реализованы |
| Конечная очередь | 16 мест суммарно от первого VALID; дополнительный счётный договор | Достаточно 12 при исходном сервисе и N(u)≤8+2·10⁶u | Требование к потоку, не подтверждённая нагрузка; нужны также исходные work-envelope |

Полные условия, точная арифметика, ограничения циклограммы и два варианта
решения — [TIMING.md](TIMING.md). Неизвестные физические upper остаются `null`.

Принятые входы: А на `96e1cc58ffe91ea5ef6ac3960fb4da03423b56d1`,
T95 на `8ecc8fb24213e03110789646725481cd34d09ab9`, CONTRACT/INTERFACE T90.
Повтор 05.10.2026: **15/15 проверок первого шага Б, 49/49 А, 71/71 T95**;
принятые файлы и JSON не перезаписываются. 14 исходных blob закреплены.
Паспорт Rev.*F повторно прочитан и визуально проверен; SHA-256 совпал
с уже сохранённым источником проекта. Новые квалификационные данные не искались.

```sh
python -B experiments/t104-new-rtl-executor/run.py
```

Python≥3.10, стандартная библиотека; сеть и HDL-инструменты не нужны.
Команда повторяет оба принятых пакета и сверяет собственный JSON. `--write`
обновляет только этот JSON, после него выполнен обычный запуск.

**Решение автору:** (1) сохранить сервис при предъявленном достаточном
договоре другого совместимого исполнения; (2) разрешить согласованный
пересчёт сервиса под полный путь CY62167-45. Рекомендуется (2): имеющийся
паспорт не оставляет положительного бюджета к лимиту приложения 45 нс.
Пересчёт пока не выполнялся. Нельзя исправить это уменьшением D*.

Среда: Python 3.12.14, x86-64; инвентаризация А сохранена. Плата/FPGA,
vendor STA и квалифицированные часы не выбраны; HDL-симулятора в PATH нет.
Локальные pyslang/YoWASP из А не подменяют pin timing; основной RTL,
синтез и RTL-формальные свойства на этом шаге не выполнялись.
Функциональные записи остаются вне Q(T); В/Г не начаты. PR сливает автор.
