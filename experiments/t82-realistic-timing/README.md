# T82 — временной запас и реалистичный канал

Рабочая поставка Issue #82; база `d2916599ca8456211da61bf58a4907a3a0738cec`.
Принятые пакеты и теория не изменяются. Это инженерная проверка, не
физическая квалификация и не самостоятельная научная рецензия.

До расчёта закреплены [METHOD.md](METHOD.md) и [config.json](config.json).
Первый этап: четыре принятых входа T73/T72, две защиты, запасы 10% и 5%,
существующие исполнители и не более двух профилей монитора (SREM, REM).
Новые доказательство, direct и архитектурные входы принимаются только
точными SHA через оркестратора. Отсутствие этих входов не останавливает
временную проверку старого T73 и документальный разбор канала.

## Результат независимого первого этапа

Расчёт выполнен: [REPORT.md](REPORT.md), документальные профили —
[CHANNEL.md](CHANNEL.md). Черновой [PR #85](https://github.com/z3tm4n-x/phd-adaptive-memory-ecc/pull/85)
открыт в первый день. Полное Issue #82 не завершено: новая сетка/кривые
зависят от согласованного #80, совместная архитектура/direct — от #81.

Одна команда из корня репозитория (Python 3.12+, matplotlib; без сети):

```bash
python -X utf8 -B experiments/t82-realistic-timing/run.py
```

Команда повторяет 21 существующий тест T73/синхронизации и 10 новых тестов,
включая календарь/маски/FIFO, четыре исходных набора, направленные числа,
независимый Decimal-90 и соседние недопустимые кванты. GOES/RTL не запускаются.
Допускается `--out experiments/t82-realistic-timing/recheck`, без записи
в старые пакеты. matplotlib нужен только для PNG/SVG; решения рациональны.

| Выход в `outputs/` | Смысл |
|---|---|
| `replay.csv`, `expanded_inputs.json` | 128 строк: 4 набора × 2 запаса × 2 архитектурных статуса × 4 стадии × 2 защиты; внешний риск отсутствует |
| `timing_margins.csv` | 384 проверки: срок минимум, upper/номинальная основа, абсолютный/относительный запас, допустимый overhead |
| `directed_bounds.csv` | Направленные границы значений формул внутренних вариантов, не доверительные интервалы физического риска |
| `fixed_comparator.csv`, `resource_boundaries.csv` | Полный диапазон постоянного сертификата M/M+1; g/g−1 для ресурса и запаса задержки |
| `ERR_only_old_fallback.csv` | Принятый fallback всегда S; не новый адаптивный выход по ERR |
| `channel_timing.csv`, `count_hypotheses.csv` | Старый LOW против документированных времён; отдельная непроверенная гипотеза 4 отсчёта/с/см² |
| `pending_curves.csv` | Новые ERR-only/monitor-only/combined кривые явно отсутствуют, не заполнены нулями |
| `timing_replay.{png,svg}`, `channel_window_obstruction.{png,svg}` | Только диагностика старого сертификата; не оптимизированные кривые #80 |
| `independent_checks.json`, `tests.log`, `protocol.json` | 16 точек Decimal-90, выполненные тесты, версии и хеши |

Для строк с отказом условия значение формулы не становится гарантией.
Поле `physical_qualification` везде false; `conditional_scalar_pass`
означает лишь совместность объявленных условий, включая будущий upper U.
Нет верхней FIFO-границы — поле задержки пустое, не фиктивное 10⁹ с.
Прежняя стадия g=130 при 10% сохранена: она проходит ≤3 мкс, но не запас
этого срока; окончательная внутренняя стадия использует g=131.

Открытые зависимости: согласованный SHA #80 с формулами/сеткой и SHA #81
с direct/архитектурой. Не подставлять вместо них догадки; не уменьшать D*.
