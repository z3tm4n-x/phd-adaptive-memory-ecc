## 2. Программное состояние и события

- 64-битные absolute ticks и slot index j; k_a/его обратный moduloW, mode;
  начальные W mandatory, j%k_a==0 далее. Пропуск тоже увеличивает j.
- `short_until`, `long_until`, `last_new_ERR`, `forced_until`, health;
  идентификатор единого миссионного бюджета не перезапускается.
- Глобальный lock всех alias, pending corrected/new image и transaction ID;
  признак «ERR этой транзакции уже учтён»; счёт логических новых ERR.
- FIFO: payload/byte enable/internal-word, first-VALID timestamp,
  occupancy с in-flight/удерживаемым ACK; backpressure-watchdog.
- Неизменяемое committed decision, только будущие pending decisions;
  ошибки входов/численного допуска → FAST, не самовольный новый k_a.

На новом флаге t: short=max(short,t+w); при t-last<=w либо в одноступенчатом
сопернике long=max(long,t+h); last=t. На точной границе FAST сохраняется.
LOW только t>всех трёх сроков. Потеря прежде новых решений; восстановление
продлевает forced до t+h+tau. Ранее принятые skips и память pending не отменять.
Новый ERR не равен каждому чтению высокого pin-уровня: ровно один флаг
на незавершённый epoch полного внутреннего слова. MCU разных слов может
дать несколько флагов, и это учитывается в теореме/цене.
Один родитель внутри E-окна также может быть раскрыт в двух разных завершённых
epoch: E не обещает чистого release. Это не повтор уровня в одной pending-
транзакции; добавочная интенсивность флагов <=nu/W отдельно оплачена в цене.

`rule.py` — эталон этой семантики, не драйвер тайминга и не готовое RTL.
Контроллер не хранит истинную nu/остаток/каталожную фазу. Таблица допустимых
численных конфигураций проверяется offline; online — счётчики, сравнения,
max, индекс/адрес, FIFO и атомарные признаки.

## 3. Обязанности исполнительного RTL/микропрограммы

Контрольный E как T104/T110: R<=92.500920нс, E<=148.501480нс, reserve104/164,
снимок60, ERR/решение64, repaired write end132, release148 тактов.
Сохранить условную физическую E-обязанность под облучением; её pin-WCET
не квалифицирует. После чистого чтения может остаться новое попадание.

**Новый application write:** first alias read+write E-sequence независимо
от ERR, с requested/merged data; второй alias — отдельный68-cycle write.
Один coherent full38 ERR до первой модификации. Общий lock/дедуп до конца.
Цена<=217.002160нс, резерв240 с10%; gate320. Новая data-select/merge и учёт
ERR должны совместно уложиться в прежние3нс logic и dispatch — это надо
подтвердить, а не добавить после расчёта. Raw137.001360нс write32 без
преднаблюдения в эту гарантию не входит. Inline-repair read32/unaligned
two-word запросы не допущены; для них нужен отдельный расчёт.

Grant приложения только frame_start+1312ticks. Кадр1568ticks, хвост256;
остатки: placement14.9688нс,10% margin0.795224нс. Однословность текущего
active window нужна также доказательству нижнего канала — это не только
условие гонок. Адрес выбран до родителя, а не адаптирован к будущему попаданию.

Доставка истинного ERR **или своевременного loss** в правило<=1.2мкс,
включая latch→counter→decision/validation/публикацию. Скрытые miss/дедуп-сбои
входят в одну δ_E=1e-6 за10лет. Признанные outages имеют отдельные ценовые
верх1e-4T и1000восстановлений; неизвестная реальная доступность остаётся null.
Восстановление не возобновляет старый LOW без h+tau здоровой истории.

## 4. Приложение, пик, очередь и цена

Предложения CPU/X должны иметь **совместный** envelope N(I)<=bΣ+ρΣ|I|.
Отдельные burst=1 у CPU и X не доказывают совместный bΣ=1.
Общая с постоянным соперником область (одни условия для сравнения):

- 1<=bΣ<=1.3839685175;
- ρΣ*1.700017мкс<=1;
- `0.760353512607 + 217.002160ns/1ms * (bΣ+ρΣ*1.003ms) <= 0.8`;
- полный ответ<=3мкс с10% запасом, CDC<=16.500160/40.500400нс,
  backpressure<=100нс; X_work(I)<=209нс+1e-4|I|;
- запрос целиком помещается в атомарный профиль, входной FIFO пуст при старте.

При bΣ=1 достаточен ρΣ<=181157.4160/s. Во всей этой общей области достаточно
двух мест, включая in-flight и held reply. Это верхняя область **всей шины**,
не попытка оплатить защитный peak редкостью ERR. Распознавание/телеметрия/X
не должны украсть незаложенные такты у контроля. Полезное программное время
не считается процентом памяти; максимум блокирования grant определяется
полным атомарным блоком, а не45нс одного фронта.

Если средние числа предложений приложения равны r_w/r_r в секунду, добавить:
защитный overhead <=92.500920нс*r_w;
полная шина <=217.002160нс*r_w+185.001840нс*r_r.
Для тихих возвратов использовать расширенные на3мкс компоненты, не только
предложения внутри их границ. При неизвестном потоке не подставлять0 или4%.
Табличные числа — intercept этих формул. Если добавочная цена уничтожает
выигрыш/1%, фиксируется отказ; D*/ε/80%/10% не меняются.

## 5. Адресная проверка через оркестратора

Повторить одну команду из README на опубликованном SHA; подтвердить:

1. Предсказуемое исключение только одного активного слова и lower phi=a-1/W;
   контроль/прикладные окна никогда не перекрываются, в том числе при all-ERR.
2. E→second-write последовательность и тот же full38 ERR перед обновлением;
   новый образ нельзя затереть старым pending. Все тайминги с margin/CDC/alias.
3. Новое произведение Poisson-клеток, joint affine certificate, старое начало
   и E-cross с beta0; начало/потери без нового ε. 68строк,36 отказов сохранены.
4. Числа двухступенчатого и одноступенчатого правила; сильный constant-E;
   нулевая нагрузка принадлежит envelope и делает необходимый свидетель допустимым.
5. Positive main conditional rows, secondary rejection, обе точные T113записи;
   ни одна не квалифицирует будущий full38 рост. Unknownполя не заполнены числами.

После проверки — одна независимая научная рецензия по решению автора.
Продолжения из приложения Е не запускаются этой поставкой. Принятые файлы,
паспорт, исходные сетки, main и Issues не изменять/не закрывать.
