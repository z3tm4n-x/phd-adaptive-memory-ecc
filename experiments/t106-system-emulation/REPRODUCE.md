# Повтор текущего пакета Г: сценарии1/3/4 и ускорение

Переносимый повтор ниже теперь включает22 unit tests,8 новых полных
сжатых трасс, независимый расчёт стоимости, сравнение буквальных хвостов
FAST/LOW и проверку6065 строк восстановленного профиля T67. Старые
холодные выходы сохранены. Нужен только Python≥3.11; NumPy/NetCDF/Vivado
не нужны для проверки поставленных данных.

Свежий повтор новых ARM ELF/vendor-RTL прогонов:

```sh
python3 experiments/t106-system-emulation/reproduce.py --execute-accel
```

Те же WSL/GCC/Vivado/Unicorn, что описаны ниже. Выполняются короткие
базовый/ускоренный опыты, буквальный/ускоренный LOW-хвост после полного NR,
сценарии1/3 в обоих режимах. По одному запуску~18–29с хоста; это не ARM-время.
Новый параметр `--execute-accel` не заменяет `--execute` для первого cold-start
и `--execute-empty` для компонентных свидетелей. Их можно сочетать.
Большие сырые файлы остаются в `.build/`; новые сжатые trace~6,7МБ доступны
в Git. Воспроизводимые хеши — outputs/accel-summary.json; host_elapsed/build
в JSON не обязаны совпасть, но при повторе trace обязаны совпасть побайтно.

Опциональное повторное извлечение выбранного T67 (не нужно для replay):

```sh
python3 -m pip install --only-binary=:all: --target experiments/t106-system-emulation/.tools/netcdf netCDF4==1.7.4 cftime==1.6.6.1 certifi==2026.7.22
python3 experiments/t106-system-emulation/extract_profile.py --download
```

Требуется NumPy2.3.5 в исходном Python; reader загружается из task-local
папки, системная среда не изменяется. Использованы netCDF4-python1.7.4,
netCDF-C4.9.3. Скрипт берёт URL/SHA из принятого source_manifest, скачивает
пять файлов в `.build/t67-source`, вызывает прежние SGPS/Response и готовый
transport-cache, но не запускает RADAR. Исходные NetCDF в Git не добавлены.
Ряд6065 интервалов и audits опубликованы, нормировка R0-A пока НЕ применена.

## Сохранённый первый запуск и компонентные свидетели

Из корня checkout, Python≥3.11, только стандартная библиотека:

```sh
python3 experiments/t106-system-emulation/reproduce.py
```

Проверяет закреплённые хеши,14 unit tests, обе опубликованные полные
сжатые трассы (~2,4МБ вместе), пять отрицательных мутаций и раздельную цену.
Дополнительно пересчитывает новые пустые переходы, абсолютные дедлайны,
векторы и журналы полного RTL-календаря. Это **независимая обработка
записанной трассы**, не повтор ARM/RTL.
Распаковка получается автоматически; отдельного Windows-пути для SR нет.

Новый actual-ISA/vendor-RTL запуск обоих режимов плюс тот же checker:

```sh
python3 experiments/t106-system-emulation/reproduce.py --execute --bootstrap
```

Linux/WSL, GCC, Vivado2025.2 с Zynq7000 нужны заранее. Wrapper по умолчанию
`/home/z3tm4n/bin/vivado-wsl`; другой путь задаётся `VIVADO`.
`--bootstrap` скачивает только три закреплённых wheels из принятого
analysis-tools.json, проверяет SHA256, ставит в локальный `.tools/analysis`.
После подготовки флаг не нужен. Вместо установки можно задать
`T106_ANALYSIS=/absolute/path/to/existing/pinned/analysis` — именно так
первый запуск переиспользовал ранее установленные пакеты В.
Ни sudo, ни подключение платы, ни изменение accepted outputs не нужны.

Среда первого запуска: Ubuntu26.04/WSL2, Python3.14.4, GCC15.2,
Vivado2025.2 build6299465, Unicorn2.1.4, pyelftools0.33. Используются
принятые ELF, новой пересборки ARM в Г пока нет. CP15/GIC/table модель
переиспользована явно из В; она не тактовая модель hard PS7.
Actual-запуск занимал~28с хоста на режим, память xsim peak~346МБ,
Vivado peak~1650МБ. Дополнительно checker обрабатывает~180тыс строк на
режим. `.build/` содержит большие сырые trace/vendor logs и generated IP,
в Git их нет; сжатые trace и run.json поставлены в outputs.

Каждый режим начинает отдельную миссию из одного и того же clean state;
runtime reset не выполняется. Входы генерируются из config и сверяются
между режимами по хешам. Общие начальные данные/инъекции не означают
общие наблюдения: каждое ERR получено собственным посещением памяти.

При новом запуске поля host_elapsed/build/environment могут различаться.
Детерминированные traces/check должны совпасть. Профиль ARM-доставки
синтетический; время хоста, инструкции, HDL-время и неизвестное время
платы не взаимозаменяемы. **Q(T) за срок этой командой не доказывается.**

## Новый запуск компонентов ускорения15.10

```sh
python3 experiments/t106-system-emulation/reproduce.py --execute-empty
```

Нужны Linux/WSL, GCC, Icarus Verilog12.0 и те же закреплённые Unicorn/
pyelftools в `T106_ANALYSIS` или `.tools/analysis`. Этот флаг не требует
Vivado и не заменяет `--execute`: он запускает **компоненты**, не весь top.
Флаги можно сочетать; `--execute --execute-empty` повторит оба вида.
Полный W524288 буквально тактируется в двух frame_engine (FAST/LOW)
около79с хоста. Затем631209 пустых пакетов выполняются исходным C и
сравниваются со свёрнутыми переходами;41 вектор исполнен функциями
принятого firmware ELF. Суммарно эта часть занимала~3,7с хоста.
Версии нового прогона: Python3.14.4, GCC15.2.0, Icarus/vvp12.0.
Исходные ELF/C/RTL только читаются; shared library/executable — в `.build`.

Полные компактные журналы `empty-calendar-{3,4,19}.txt`, двоичные ABI-векторы
в hex и все исходные хеши поставлены в Git. Независимому повтору не нужен
локальный кэш инженера. Счётчик ISA относится только к вызванным функциям,
не к полному driver/MMIO. Полное время ARM и новый сквозной сервис неизвестны.
