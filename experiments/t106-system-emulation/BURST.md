# Случай2: источник и нормировка до сравнительного исполнения

15.10.2026. Это цифровой сценарий исполнения E/r4, **не новый физический
пересчёт CY62167**. Прежний извлечённый T67/G16/E ряд6065 минут остаётся
неизменным (SHA в outputs/t67-profile.json). Его исходные16777216бит и
10ммAl не выдаются за полную память38бит/3г·см⁻². RADAR/T141 не применяются.

Рассмотрены три пути: прямая подстановка старых амплитуд (другая
нормировка, отвергнута); новая спектрально-транспортная калибровка
(вне Г, отвергнута); использование **только безразмерной временной
формы** внутри уже принятой R0-A огибающей (выбрано). Это проектный
расчётный вход для проверки исполнения, не измеренная интенсивность.

Весь закреплённый интервал06.06.2024 02:55—10.06.2024 08:00 UTC
сохраняется без сжатия/перестановки. Для старых значений f_i задаём
g_i=f_i/max(f), s_i=0,244528·g_i, ν_i=0,000154704+s_i, с⁻¹ на массив.
Коэффициенты — прежние R0-A из T135§1; множитель38/32 **не применяется**:
амплитуда уже на полный массив. Между минутными узлами — линейное
продолжение; последний60-секундный интервал постоянный. Это явно
выбранная реконструкция формы средних, не восстановление внутриминутных
всплесков. Она не вводит искусственных скачков, нарушающих H_l.

До генерации/исполнения проверяются пик≤0,244682704/с, ∫s≤28310,473728,
максимальный относительный положительный наклон ν'/max(ν,0,001)≤0,048/с.
Начальный пик и спады разрешены принятым договором. Эти три проверки не
сертифицируют все физические/lifetime-предпосылки. Если H_l не проходит,
форму не сглаживать молча: вернуть конкретный остаток нормировки.

Инжектор — NHPP thinning от постоянного верхнего темпа; одна инверсия
на родителя, независимые равномерные word/bit marks на всех W×38.
Это singleton-подслучай, а не реализация всех MCU/прямых путей R0-A.
Новая серия не используется для вывода Q(T). Seed10620261014; Python
random.Random/MT19937, алгоритм в burst_inputs.py. Время родителя
округляется вверх до разрешённого отрицательного fast-фронта (≤4нс);
контроллеру не передаются ν, UTC, seed или будущие события.
Один фиксированный общий список на adaptive/FAST; собственные ERR разные.
Начало чистое, данные как в случае5, приложений/ложных ERR/loss в2 нет.

Проверка пяти сценариев не требует положительного выигрыша. Полное
сравнение2 ещё **не выполнено**. До него потребуется оценить время и
объём полного журнала, сохранив все непустые проверки и возможность
независимого повтора. Не урезать6065 минут либо W по результатам.
