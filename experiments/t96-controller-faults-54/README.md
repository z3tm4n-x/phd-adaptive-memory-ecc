# №96. Что покрывают локальные проверки контроллера по ERR

**Одиночный сбой может отменить обязательную запись даже в версии с проверками.** На последнем адресе контроллер принял ERR=1 и правильные данные. Через 5 нс инверсия триггера `hit` сняла запрос записи. Защита сохранила ближайший частый обход, но запись завершилась на 1400 нс позже обязательного срока. Второй путь к опасному исходу — повреждение истории нулевых отчётов. Оно породило допустимый по коду шаг 4 при обоснованном шаге 2. Для переноса гарантии на ПЛИС требуется верх суммарной частоты таких исходов вместе с остальными непокрытыми путями. ### Первый пропущенный ремонт

Нулём времени служит первое внешнее чтение адреса 0 в раунде 1280 после штатного reset. Такт 10 нс, полный обход $L=2800$ нс. Четыре слова по 32+6 занимают восемь адресов ×16. Адреса 3 и 7 читают половины одного слова. Состояние памяти в этом опыте содержит один исправимый дефект проверочной позиции 37. Все разрешения завершения, отчёта и установки исправны. Единственное повреждение **контроллера** — инверсия `hit` с 1 в 0. [Оба входа и моменты инъекций](config.json)

| Время от начала раунда 1280 | Штатное обслуживание | Наблюдение при `CHECK_LOCAL=1` |
|---|---|---|
| +2101 и +2160 нс | Ошибка в слове 3 после первого чтения его младшей половины. Начало чтения адреса 7 | В памяти установлена одна ошибка. Адрес 7 выбран, OE# активен |
| +2220 и +2225 нс | Защёлкиваются ERR=1 и DQ=0xA5BF | Оба значения захвачены правильно. Спустя 5 нс повреждён `hit` |
| +2260 нс | Начало выдачи 0xA5BF для записи | Выбор SRAM снят. Опубликован полный по признаку отчёт с количеством 0 |
| +2270…+2320 нс | Активный WE# и его подъём на конце записи по адресу 7. Нормальное освобождение в +2360 | Импульса WE# нет. На сроке +2320 прежняя ошибка всё ещё в слове |
| +2500, +2700 и +2800 нс | Частый шаг 1 и старт раунда 1281 | Отдельный признак `any_err` запретил замедление. Адрес 0 прочитан в +2800 |
| +3720 нс | В исправном опыте слово уже чистое | Первая фактическая исправляющая запись теперь по адресу 3, DQ=0x3413. Ошибка устранена |

До первого пропущенного ремонта двух ошибочных разрядов не возникло. Доказательная предпосылка нарушена уже на сроке обслуживания. Ошибку позднее устранил следующий проход. В исходной версии без проверок тот же дефект контроллера разрешил также редкий шаг. Следующее чтение произошло на +5600 нс, первая запись — на +6520. [Сигналы и итоги всех сценариев](results.json)

На xc7z020clg484-1 при ограничении 10 нс по отчётам синтеза №465 исходный вариант занимает **158 Slice LUT / 93 FF**, вариант с проверками — **182 / 94**. HDL-инъекция в функциональный регистр, в частности в неиспользуемый при выключенных проверках бит чётности, сама по себе не свидетельствует о наличии отдельного физического триггера этого имени. ### Какой вклад допустим на десять лет

$Q_{\rm нак}(T)$ — вероятность первого появления двух ошибочных позиций в одном слове. Общая квота всех исключений исполнения $\delta=6\cdot10^{-6}$ уже входит в выделенные на накопление $10^{-3}$. Пусть $B_{\rm проч}$ ограничивает вероятность хотя бы одного прочего нарушения (чистое начало, независимые от контроллера нарушения часов и передачи, оговорённые исключения обслуживания). Пусть $B_{\rm общ}$ отдельно ограничивает общие причины, одновременно нарушающие несколько путей. Для учёта непересекающихся причин можно заранее отнести каждую общую причину только к одной группе. Если её уже включили в $B_{\rm проч}$, повторное отдельное слагаемое за неё не берут.

Остаток для опасных исходов самого контроллера равен $a=6\cdot10^{-6}-B_{\rm проч}-B_{\rm общ}$. При $a\ge0$ достаточно $\sum_j \mathbb E N_{j,\rm опасн}(T)\le a$, или для средней суммарной частоты $\bar\nu_{\rm опасн}\le a/315\,576\,000$ с⁻¹. Это верх по ожидаемому числу событий и неравенству объединения, независимость и пуассоновский закон для отказов ПЛИС не требуются. При $a=0$ эта проверка требует нулевого остаточного вклада. При $a<0$ уже предъявленные верхние оценки исчерпывают квоту. Это заключение о достаточности имеющихся границ. [Закреплённая длительность и определение события](../../theory/t196-native-err-20261110.md) · [Проверка арифметики](check.py)

| Доля прочих и общих причин за срок | Остаток контроллеру | Достаточный уровень средней суммарной частоты |
|---|---:|---:|
| Обе нулевые только для иллюстрации максимально возможного допуска | $6\cdot10^{-6}$ | $1/52\,596\,000\,000\,000$ с⁻¹ ≈ $1,901285\cdot10^{-14}$ с⁻¹, или 0,0684463 на миллиард часов |
| Иллюстрация, по $10^{-6}$ каждой группе | $4\cdot10^{-6}$ | $1/78\,894\,000\,000\,000$ с⁻¹ ≈ $1,267523\cdot10^{-14}$ с⁻¹, или 0,0456308 на миллиард часов |
| Физическое изделие в главном примере | **Не установлен** | Верх на прочие нарушения, общие причины и суммарную частоту опасных исходов контроллера отсутствует |

В сумму входят регистры решения, захвата ERR/DQ, фазы, адреса и разрешений, конфигурационная память ПЛИС, логика и маршрутизация стробов и управляющие пути. Для заданной среды требуются верхние меры появления нарушений на соответствующих ресурсах и условная вероятность опасного исхода при их возникновении, включая длительность неисправности, восстановление и непокрытые фазы. Можно вместо детализации предъявить общий физически обоснованный верх. У общего сбоя тактирования либо нескольких ресурсов должен быть единый учёт. Для других фаз, многих одновременных повреждений, общей причины и физического соответствия RTL триггерам частота здесь неизвестна. На стенде показано наступление исключения при определённом повреждении. Сроковая гарантия для ПЛИС остаётся условной.

**Передача для общей рецензии.** Синтез №465 определяет цену двух вариантов. Принятая 5.2 проверяет обслуживание при ошибках памяти и исправном контроллере. Настоящая проверка определяет границу этой связи при сбоях регистров. Допустимая формулировка положения 4 — локальные проверки удерживают частый шаг при указанных повреждениях, с измеренной прибавкой ресурсов и без отдельного доступа к защищаемой памяти. Подтвердить полное покрытие контроллера ими нельзя. Для переноса в главный пример первым по значимости нужен физический верх на опасный пропуск ремонта и искажение истории/фазы вместе с остальными исполнительскими причинами. [Поставка 5.2 и решение о принятии](https://github.com/z3tm4n-x/phd-adaptive-memory-ecc/pull/503#issuecomment-6856411811) · [Исходный синтез](../native-example-20261111/synth.tcl)

### Повтор

Из корня репозитория. Для новых и девяти известных случаев нужен Icarus Verilog/vvp 12 и Python со стандартной библиотекой. Основной расчёт выполнен под Ubuntu с Python 3.14.4, дополнительный разбор выходов — также под Windows с Python 3.13.5. Время полного нового прогона около 10 с при шести параллельных процессах на данной машине.

```sh
python3 -B experiments/t96-controller-faults-54/run.py --work /tmp/t96-faults-54 --jobs 6 --check
python3 -B experiments/t96-controller-faults-54/check.py /tmp/t96-faults-54
python3 -B experiments/native-example-20261111/hardware.py inject
```

Скрипт `check.py` самостоятельно восстанавливает чтения, адресованные концы WE# и занятость слотов по изменениям выходов. Проверка отвергает намеренно подставленное утверждение, что поздний ремонт успел к сроку. Это инженерная перекрёстная проверка общих первичных сигналов. Каждый повтор сохраняет необработанные журналы в `--work`. Точные входы заданы в [конфигурации](config.json). Ведомость [results.json](results.json) включает хеш строк сигнала каждого опыта и совпадает побайтно при повторе. SHA-256 ведомости `ded5f273e176ac575e73efa7336caf3d1c645393fb551b52e28154ecb2385aa2`. База `67d35ff60a8804de5ae6edd27cbc818e3d2b880c`, регистрация `02ddce4d0820a4c6a80fb5204366882769123c0b`, исходный RTL blob `27f651fcea5b8ef677ccbad13fcfbb9f502c4296`.

При первом запуске Icarus 12 прервал часть опытов при выборе объекта инъекции по динамической строке. В стенде изменено только представление имени на строку фиксированной ширины, затем весь зарегистрированный набор выполнен заново. Прерванные запуски исключены из ведомости.
