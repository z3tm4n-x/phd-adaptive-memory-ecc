# #206 — ядро карты и методика выбора

22.10.2026. План закрепляется до новых расчётов этой задачи. Статус:
предложение исполнителя, не научная приёмка. Организационная база main
`4131b908259130bad269c2116b5b0b7811b40502`; действующее задание — [#206][issue].

## Цель и ближайшее решение

Выбрать достаточный режим защиты заданного полезного объёма при общем
событии, сроке, допуске и полной цене. Сначала постоянный режим каждого
кода, затем адаптация и дополнительные сведения. Если входы не замкнуты,
результат — конкретное недостающее основание и рекомендуемое изменение,
а не искусственный победитель. Новая теория adaptive-t2, RTL, транспорт
и физическая кампания не входят.

Событие A_t(T): хотя бы в одном полном кодовом слове хотя бы в один момент
[0,T] число ошибочных разрядов превысило t. Это событие паспорта; оно
не подменяется ошибкой только на чтении, первой зарегистрированной аварией
или вероятностью в конце срока. Смена t меняет корректирующую способность,
но сохраняет смысл системного события и полезные данные.

## Алгоритм выбора

1. Закрепить полезные данные, A_t(T), T, ε, начальное состояние и обязательства
   приложения. Для сравнения использовать один класс среды/родителей на физических
   позициях, а не одинаковую array-rate при разном числе проверочных битов.
2. Проверить память/ревизию, полный код, адресное размещение, марки родителей,
   прямые группы >t, весь энергетический отклик, геометрию/защиту, совместность
   среды и срок. Незамкнутый физический вход допускает только условную строку.
3. Выделить lifetime-бюджет: Q_total_upper ≤ δ_env + δ_init + δ_exec +
   Q_model_upper + прочие статьи. Не складывать direct второй раз, если он
   уже внутри Q_model. Для нулей нужно основание/явное условное определение.
   Нет бюджета одной обязательной статьи — итоговая достаточность UNKNOWN.
4. Для каждого кода сформировать объявленный постоянный класс: сервис E/U,
   допустимые периоды/фазы/такты и приложение. Получить sufficient-кандидата
   и отдельно применимый class lower. Граница достаточного теста не оптимум.
5. Только после этого подключить адаптацию по собственным исправлениям, простые
   схемы и внешний канал в принятых областях. Для n39 нового эталона необходима
   подпись #196; fixed-t2 не разрешает автоматически adaptive-t2. Не переносить
   TS₂/F² на другой функционал. Известные схемы импортируются по #186/#196 к03.11.
6. Для каждого допустимого кандидата учесть полную цену до T: приложение,
   кодирование/декодирование, наблюдение, управление, память, очереди, остатки,
   работу после A и начатые операции. Отдельно верх полных начатых работ и
   точную занятость, обрезанную T. Общие и устранимые затраты явно разделить.
7. Выдать один из трёх статусов с областью: **достаточное решение** при
   применимом upper≤ε и выполненных обязательных ограничениях; **доказанное
   исключение** только при применимом lower>ε или доказанной несовместимости;
   **пока неизвестно** во всех остальных случаях. Отказ одного кандидата не
   исключает класс, а физическая условность хранится отдельно от этих статусов.
8. Сравнить по выбранной координате при ограничениях остальных либо выдать
   Pareto-набор. CPU, LUT/BRAM и джоули не складывать без заданных весов.
   Доказанное преимущество над лучшим постоянным требует upper цены кандидата
   ниже lower цены всего соответствующего постоянного класса. Иначе — только
   сравнение предъявленных вариантов или UNKNOWN порядка.
9. При неопределённой цене вывести пороги коэффициентов. Для линейной цены
   C_i=a_i+b_i x и C_j=a_j+b_j x граница — решение
   (b_i−b_j)x=a_j−a_i; отдельно обработать равные коэффициенты, знак и область
   допустимых x. Для интервальных цен сравнивать upper с lower, а не два upper.
10. При затруднении сравнить локальное исправление, другую архитектуру и другую
    рабочую точку. После двух безрезультатных попыток перейти уровнем выше.
    Ослабление объёма/T/ε предложить автору явно, не применять автоматически.

Запасы раздельны: ΔQ=ε−Q_upper, m_Q=1−Q_upper/ε;
m_time=1−L_upper/L_limit; m_resource,j=1−R_upper,j/R_limit,j.
Неизвестный numerator/limit даёт null, не 0 и не положительный запас.
Проектный ориентир основного примера: m_Q≥0.5, m_time,m_resource≥0.2.
При caps 3 мкс и 0.8 шины это 2.4 мкс и 0.64; обязательные caps сохраняются.

внешние (39,32)/(44,32), 3×x16 без межсловной упаковки, 10 лет, ε=0.001,
