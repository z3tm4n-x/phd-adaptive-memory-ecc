**Неустранённое расхождение.** У REDW2020 в нейтронной строке EV30
14,8 МэВ стоит1843, у Cecchetto задан default1731; численное сечение
2,99·10⁻¹⁴ см²/бит совпадает. Совпадение числа не доказывает общность серии
и не разрешает считать1731 опечаткой. Визуально сверены Table6.3/6.6.
Нужна явная связь run/device ID с полной маркировкой; сейчас ни источник
не исправлен, ни таблица MBU не перенесена в1843.

В §6.2.1 Cecchetto поясняет, что SEU-счётчик суммирует все изменённые биты,
а MBU регистрируются в16-битном слове. Поэтому даже после уточнения date code
битовое сечение нельзя молча заменить интенсивностью независимых родителей.
Для трёх x16 адресов внешнего full44 ещё нужны межадресные связи, временная
идентификация одного родителя, четыре неиспользуемых бита и выбранный диапазон.
Отсутствие таких полей в рассмотренных таблицах не является нулевой групповой
частотой. Найденные MBU другой/неразрешённой серии также не доказывают
конкретную групповую частоту1843.

## 2. Точный недостающий вход

Проверенные первоисточники не дают одновременно следующую цепочку:

1. Полная маркировка/идентификатор образца → CNA LEP → KVI HI → HEP Fig.5
   → нейтронные run IDs, с объяснением1843/1731 и без подстановки1525.
2. Численные energy/LET/angle/voltage/temperature, стэк и lid-state для тех же
   образцов, события и флюенс; перенос на закрытый корпус, если он выбран.
   Точка95%-интервала и неопределённость флюенса не дают единую огибающую
   всего диапазона и всех режимов с требуемым lifetime-покрытием.
3. Полный отклик с LEP/HEP/прямой ионизацией и согласованным исключением
   двойного счёта; метки на полном44-битном слове и межсловные события.
4. Совместная среда после единственного применения Al4 г/см² и обоснованные
   B, M1, M2, M3 за10 лет; отдельные неоплаченные δ_env/δ_init/исполнения.
   Прежний GE30/T150 S2 и 90%-покрытие не закрывают эти поля.

Это точный перечень отсутствующих оснований **в проверенном наборе**,
не утверждение об отсутствии данных у авторов. Следующий внешний вход —
уже имеющиеся протоколы/таблицы этих серий и подтверждение идентификации.
Запросы авторам/изготовителю не отправлялись. Новая испытательная или
транспортная кампания не предлагается как автоматическое продолжение.

## 3. Граница, которая действительно меняет решение

Используется только принятое [основание #196, формула(1)](https://github.com/z3tm4n-x/phd-adaptive-memory-ecc/blob/f5cc22211d33cec4ddd4f2144c9a77c5314fb5f2/theory/t196-write-only-apertures-20261022.md)
и готовый [результат #186](https://github.com/z3tm4n-x/phd-adaptive-memory-ecc/blob/f5cc22211d33cec4ddd4f2144c9a77c5314fb5f2/experiments/t186-method-comparison/app-only/outputs/result.json).
Окна P=131074621440 нс, D=3000 нс, W131072, clean, причинное E и независимые
singleton NHPP на всех44 позициях должны сохраняться. Если иной физический
закон не удовлетворяет этой области, приведённые пределы неприменимы.

Пусть **независимо от расчёта карты** обеспечены совместные верхние границы
`B_phys <= c*B_ref`, `Mj_phys <= c^j*Mj_ref`, j=1,2,3.
Это один достаточный срез многомерного входа; c не измерен и не назначен EV30.
Единственная временная кривая референсу не приписывается. Сечение на одной
энергии не является таким сертификатом.
Моменты должны относиться к исходному NHPP либо к доказанному покрывающему
процессу; нельзя получать их условливанием на отсутствие плохих событий
или на реализованные start/release. Сохраняется область исходного доказательства.

Все члены принятой moment/E-оценки имеют степень3: M3, B*M2, B²*M1.
Обозначим R готовой величиной `U_ref - Delta_ref`, Delta_ref=6·10⁻⁶.
Дополнительный бюджет beta покрывает за **весь T** любые ещё не оплаченные
отличия среды/начала/исполнения и исключённые события. Если группы удаляются
через beta, требуется вероятность всех исключённых групп, не только уже
неисправимых групп. Зависимость исключений не позволяет считать их нулями;
один и тот же риск не оплачивается повторно.

Тогда достаточный порог на **вход** получается прямой инверсией:

    c^3 <= (alpha*epsilon - Delta_ref - beta)/(U_ref - Delta_ref).

Применение требует также доказать физический общий бюджет не выше
Delta_ref+beta. Delta_ref из v4 сам по себе не является измерением устройства.
alpha=1 — допустимое требование; alpha=1/2 — проектный вероятностный запас.
Три среза beta заданы планом до расчёта. Нижние десятичные границы безопасно
округлены вниз; соседняя верхняя с шагом10⁻⁹ строго пересекает границу
сертификата. Это таблица порогов параметра, не новая таблица вариантов защиты.

| Дополнительный beta за10 лет | c для требования epsilon | c для цели epsilon/2 |
|---:|---:|---:|
| 0, идеализированный срез | ≤5,376305931 | ≤4,258573642 |
| 10⁻⁴ | ≤5,189605578 | ≤3,949304191 |
| 2,5·10⁻⁴ | ≤4,881419788 | ≤3,366292020 |

**Как меняется выбор.** Если, например, c≤3,949304191, beta≤10⁻⁴ и все
предпосылки отдельно подтверждены, OFF-кандидат закрывает проектную
вероятностную цель; необходимость дополнительного scrub по этой цели
не установлена. Остались сервис, цена и административный допуск класса.
При c=4 в том же срезе сертификат hard-требования ещё доступен, а
сертификат половинного бюджета уже не получается. Это повод явно показать
недостающий проектный запас, а не объявить код невозможным.
За hard-порогом статус **UNKNOWN**: достаточная оценка не исключает схему.
Нижняя оценка класса здесь не построена.

Для CNA1843 c, beta и применимость singleton/E остаются неизвестными.
Неизвестный физический множитель не компенсирован запасом; новый physical Q
не вычислялся. Инверсия формирует проверяемое требование к данным вместо
одного остатка epsilon-U, но не заменяет сами данные.

## 4. Цена и практичная альтернатива

Счётчики полного приложения, prefix/post-A/pending импортируются из #186;
новый календарь, шина и ответ здесь не рассчитываются. Для опубликованного
dense-ROM кодека 23040 байт один лишь ROM требует capacity≥28800 байт при
20%-резерве. Полное условие: `23040 + M_other <= 0.8*M_cap`, где M_other
содержит регистры, буферы и управление. Неизвестный M_other не занулён.
Непрохождение ограничивает эту архитектуру кодека, не семейство t2.

Для неперекрывающихся энергетических затрат сохраняется отдельное условие
`T*P_idle + sum(N_i*e_i) + E_other <= alpha_E*E_cap`.
Цена одного действия j ограничена остатком, делённым на его N_j;
точные готовые счётчики и формула выведены в `thresholds.json`.
E_cap, P_idle, e_i и остальные затраты неизвестны. Энергия не суммируется
с CPU/LUT/BRAM, а ресурсный/временной/вероятностный запас проверяется отдельно.
Только доказанная несовместимость фактических ограничений допускает исключение;
невыполнение достаточного upper не является таким доказательством.

Рекомендация оркестратору: сохранить EV30/CNA1843 как кандидат и завершить
уже назначенный простой сервис #186/#196 на проверенных AC-основаниях.
При отсутствии перечисленных протоколов предъявлять его как пример выбора
при **явно условном законе среды**, отдельно от физического mission-Q.
Это практичный проверяемый результат без новой кампании; замену им главного
подтверждённого физического примера можно только предложить автору, не объявить.
Ни уменьшение объёма/срока, ни ослабление epsilon не устраняет конфликт
происхождения данных. Автоматически выбирать1525/GE30 вместо1843 нельзя.

Сначала полные восстановления приложения, затем дополнительный контроль
и сведения — порядок методики сохранён. Численная/теоретическая работа
известных схем к27.10/03.11, рабочий срез30.10 и ядро06.11 не изменены.
Полная #206 не завершена; принятие этого среза и независимая рецензия отдельно.
