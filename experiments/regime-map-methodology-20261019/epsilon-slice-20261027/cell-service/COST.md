## Основной поток, ошибочный C и дополнительные E

Для каждой координаты x∈{bus,core}:

```
V_x = U0_x + Cb_x*δ_C,   Cb_x=M_b*(r_x+d_x)/T
C_A_x <= V_x + Az_x*z + Ag_x*G + (Ch_x-Cb_x)*δ_escape + c_x
δ_C <=5e-5, δ0=6e-6, N_h=1610097765253120.
```

U0 содержит обучение, базовые/редкие клетки, обычные loss/false,
остаток слабого E, repair, startup/края, q₀M_b после разрыва сопряжения
и δ₀N_h. Cbδ_C оплачивает полную E-работу на ошибке значения C при
исправном исполнении; риск Q не уменьшается. G охватывает дополнительные
E на всём G₀, включая неверный C и post-A. На нарушенном исполнении
действует прежний принудительный hard-cap, не M_b.

Ранее ошибку C оплачивали коэффициентом C_h; теперь условие соответствия
CONTRACT даёт C_b. Если оно не обеспечено для части ошибок, C4 возвращает
дорогой член δ_escape. При δ_escape=δ_C получается прежняя цена, а не
бесплатное исключение. Для математического селектора без порчи epoch/
календаря δ_escape=0 тождественно. Аппаратный ноль этим не установлен.

Приложение:315569688607 full39 reads, полезных записей0. Общая инициализация
W encode+3W write до t=0 оплачивается отдельно с амортизацией на T.
App ECC уже включён один раз. Прикладной read не помогает C и не исправляет
сохранённые ошибки. Полезные payload, заголовки, диспетчеризация и буферы
сохраняются отдельными общими коэффициентами.

## Полный счёт обработки без новой модели транспорта

Сохраняются32-byte record, cut4000ns, весь пакет≤3900ns, прежние
131136bytes транспортного/loss состояния. Обработка включает capture,
source-health/prefix, decode/map, dedup, increment, причины GAP/RESTORE/FALSE,
закрытие прохода и клетки, кольцо6 сумм, решение/install, gate/таймеры.
Online exp/log/обращение статистической границы не нужны: порог4 заранее задан.
Отсутствие таких операций — свойство алгоритма, не нулевая цена остальных.

На G₀, включая B_C и A, число закрытий прохода≤1+Nn_b. На плохом исполнении
дополнительная обработка, не ограниченная этими вызовами, имеет отдельный
член δ₀·C_other_controller_hard. Он входит c_x и не присваивается нулю.
Число command-dispatch оплачено M_b+δ₀N_h; проверка потенциального слота
и подготовка реально исполняемой команды — разные операции. Если реализация
их объединяет, единичные цены должны исключать повторный счёт.

Для ordinary raw records используем тот же родительский/послеаварийный
свидетель, что и для repair:

```
raw0 = (H0 + δ_C*M_b + E[N_false] + N_loss + N_restore)/T
       + δ0*source_edge_rate
raw_rate <= min(source_edge_rate, raw0 + G/T + v).
```

До разрыва один родитель даёт≤2 ERR; после него каждый основной E может
породить запись. H0 уже оплачивает q₀M_b; δ_C оплачивает весь M_b. G здесь
добавляет возможную запись от дополнительного E, отдельно от его SRAM-цены.
False и распознанные loss/restore оплачены отдельно; v — дополнительные
raw/veto, не повторно ordinary ERR. Пропущенные/потерянные записи не становятся
бесплатными: верх считает их создание/обработку; повторы/причины одного edge
не начисляются как независимые родители. Контроллер не наблюдает этот
родительский разбор — это только свидетель верхней цены.

При ε=.01 условные средние верхние rates (не измерение):

| Работа | Rate за весь T, /s | Коэффициент цены |
|---|---:|---|
| cut+ready, включая пустые | 250002.500026 | совокупный c_cut ns в данной координате |
| Проверка потенциального control-slot | 5102091.937452 | c_gate ns; физическая реализация может не обращаться к общей SRAM |
| Подготовка основной команды | M_b/T+δ₀N_h/T | c_dispatch ns, точный rate в JSON |
| raw record bundle | ≤1629.436897+G/T+v, с source cap | c_record ns: все непересекающиеся шаги записи |
| Закрытие прохода/его префикса на G₀ | ≤.098894400 | c_pass ns |
| Каждое из cell-close/choice, ring-update, cell-prefix | ≤.001621220 | отдельные единичные цены |
| Остальная работа на плохом исполнении | δ₀·hard-work | неизвестный all-history предел |

Здесь source_edge_rate≤250002500.026/s. Малое число outage episodes не
уменьшает этот сырой домен. Квота raw/veto, если она нужна для выигрыша,
предъявляется как условие, а не выводится из1001 losses/1000 restores.

Полный c_x в долях T:

```
c_x = sum(rate_i * cost_i_x_ns)/1e9
      + (G/T+v)*cost_record_x_ns/1e9
      + (G/T)*cost_extra_dispatch_x_ns/1e9
      + δ0*C_other_controller_hard_x + idle_controller_x.
```

Таблица rates уже содержит raw0; добавляется только его G/T+v. Word decode,
read/write beats и turnaround входят r/d и не начисляются повторно в c_x.
Source-record decode — другая операция. Общий codec/app нельзя повторно
добавлять к защите ради сравнения. Совпавшие причины guard образуют G один раз.

CPU использует собственные cost_i_CPU_ns и предел/idle. Энергия —
ΣE[N_i]e_i_J+T·idle_W с отдельной стоимостью плохого исполнения. Все чтения,
repair/extra E, app/init, record/cuts/gates входят соответствующим счётом;
неизвестные CPU/энергия не заменяются временем общей SRAM. Без этих
коэффициентов нет численного20%-утверждения для CPU или энергии и нет
единого взвешенного «общего коэффициента».

Возможная packed policy раскладка — прежние64bytes локальной привязки C
+6×8bytes клеточных сумм +8 flags/ring +8 rolling sum +8 cell index
+8 period/cursor =144bytes, сверх131136bytes. Это достаточный проектный
layout, не измеренная RAM. Максимальная сумма6 клеток при .001 требует30bits;
64bits сохраняют запас. Code/stack/codec/workspace/LUT/BRAM остаются параметрами.

## Потери, invalid, v и число затронутых запросов

Прежние D_loss≤31557.6s, N_loss≤1001, E[N_false]≤315.576 за T уже вошли
в E10. Их нельзя снова начислить в z. Restore оплачивается как сообщение
и обработка состояния; он не стирает потерянные6-cell окна и не требует
сам по себе прежнего длинного FAST.

Для дополнительных распознанных интервалов недоступности можно использовать
консервативный свидетель

```
z <= min(1, (D_extra/H_lower + 7*N_extra_episodes + N_late)/N).
```

N_late — дополнительные опоздавшие запросы. D_extra и episodes считаются
по объединению ещё не оплаченных причин. Семь краёв покрывают6-cell историю
и короткий scan/source хвост при фиксированных общих границах. Дополнительный
E или raw/veto можно внести как эпизод только вместе с длительностью его
неразрешённого состояния; неизвестное ожидание восстановления нельзя заменить
нулевой длительностью. Пересечение/повторы могут завышать этот sufficient
верх, поэтому его превышение не доказывает фактическую дороговизну.

Если source/processed/health вообще не связан с агрегатором, все запросы
invalid и z=1. Это конкретный отказ20%-условия, а не «редкая потеря».
Если нет покрытия работы при неверном epoch/очереди, остаётся δ_escape.

## Численная область20% при ε=.01

Для обоих классов F и S получаются следующие достаточные условия.
Обозначим g_E=G/T в extra E/s, c_x — **всю** добавочную обработку в мкс/с:

```
bus:  267.960735*z + .10500104*g_E + 534363.906022*δ_escape + c_bus
      <=5.875573 мкс/с
core: 378.460018*z + .12450124*g_E + 633602.952037*δ_escape + c_core
      <=15.481007 мкс/с.
```

Коэффициенты округлены вверх, правые части вниз. Нельзя израсходовать каждый
предел независимо: все добавки делят один остаток своей координаты.

| Одна ось, остальные добавки формально0 | Bus: допустимый предел | Core: допустимый предел |
|---|---:|---:|
| Дополнительная доля invalid z | .02192699 | .04090526 |
| Extra E/s | 55.95728 |124.34419 |
| δ_escape |1.0995453e-5 |2.4433293e-5 |
| Средние ns на каждый cut+ready | .02350205 | .06192340 |
| Средние ns на каждый потенциальный gate | .001151600 | .003034246 |
| Средние ns на raw record при v=G=0 |3.605891 |9.500832 |

Это сечения достаточной области, **не выбранные физические значения** и
не совместный бюджет. Например, по16ns общей SRAM на каждый cut потребуют
около4000.04мкс/с вместо всего5.875573мкс/с. Значит этот способ обработки
не проходит; само наличие cuts не доказывает обязательных16ns общей SRAM.
Обработка в локальной памяти/логике имеет свои ненулевые CPU/энергию и
ресурсы; её размещение/WCET нельзя вывести из среднего лимита.

Из полного сырого домена v или отсутствующего префикса20% не следуют.
Например, в упрощённом sufficient счёте мгновенных veto с затрагиванием≤7
запросов и без других добавок достаточно v≤5.0783532e-6/s по шине.
Это не назначенная квота: при длительном UNKNOWN нужен ещё D_extra,
а реальные raw/veto могут иметь перекрытие и иную подтверждённую цену.

При .1/.001 уже V не помещается в20%-остаток. При .0001 нового адаптивного
Q нет, fixed допустим. Для30% все три sufficient остатка отрицательны.
Ни один из этих отказов не является доказательством невозможности А.
Для решения достаточно границ полных классов; точный оптимум здесь не нужен.
