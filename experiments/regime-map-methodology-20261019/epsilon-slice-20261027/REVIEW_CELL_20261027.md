## Что установлено

1. **Ошибка значения C не означает произвольную частоту работы.** На каждой клетке устанавливается ровно один из двух заранее заданных календарей; поздний результат и дальнейшие сообщения его не меняют. Индукция по клеткам даёт M_b для основной работы до T, включая последнюю неполную клетку и работу после ошибки памяти. Контрпример 94 вместо61 прохода показывает необходимость однократного выбора. Поэтому только ценовой коэффициент при прежней δ_C можно заменить с N_h на M_b. Вероятностная квота, Q(T), настройки и цена нарушений исполнения δ₀N_h сохранены.
2. **Алгоритмический перенос E4/C2 дан.** Блок кратен прежней frame; первый проход начинается во втором блоке клетки, все укороченные интервалы имеют не меньше двух блоков. При фиксированном ξ якоря назначены общей эпохой; release и будущий ERR не сдвигают границы. App-grant и порядок слов сохранены. Готовность включает install до fence. Это конструктивная совместимость при прежних сервисных условиях, не измерение исполнения. Диспетчер «следующий старт после завершения обработки ERR» сюда не входит.
3. **События и цена разделены правильно.** Произвольный scalar C/invalid выбирает календарь; порча эпохи, очереди или таймера не объявляется той же дешёвой ошибкой. Для непокрытой части остаётся δ_escape. G охватывает дополнительные E также при неверном C и после ошибки памяти. В выбранном селекторе сообщения не создают E; подключённый старый OUR/FAST не получает G=0. Полная обработка, приложение, инициализация и неизвестные цены сохранены.
4. **Дополнительная непригодность:** оценка z через D_extra/H⁻+7N_extra+N_late применима, когда D_extra покрывает всю длительность непригодности данных, включая ожидание восстановления и хвост регистрации/обработки. Для одного такого интервала число затронутых клеток не больше D/H⁻+2; объединение запросов по шести прошлым клеткам добавляет не больше пяти, откуда +7. Поздние запросы оплачены отдельно. Нельзя подставлять лишь длительность физической потери, оставляя хвост вне D_extra. Привязка этого D_extra к конкретному каналу остаётся условием применения, а не установленной величиной.

Нижние цены относятся ко всему объявленному классу, но не являются вычисленными оптимумами. Для30% эти достаточные сравнения не проходят во всех трёх обязательных точках. Обязательная сетка автора проверена; повторной кампании ради формального исполнения этого требования не нужно.

При .01 все дополнительные составляющие совместно должны выполнить:

```
шина: 267.960735*z + .10500104*(G/T)
      + 534363.906022*δ_escape + c_bus <= 5.875573 мкс/с;
последовательное обслуживание: 378.460018*z + .12450124*(G/T)
      + 633602.952037*δ_escape + c_core <= 15.481007 мкс/с.
```

Здесь G/T — дополнительных E в секунду; c — вся оставшаяся обработка в данной координате. **Core в этих таблицах — сериализованное обслуживание памяти с декодированием, а не процессорное время.** Для CPU и энергии остаются собственные ненулевые коэффициенты.

## Следствие для направления А

Новый математический переход и его условное соответствие сервису закрыты. Остаток — принадлежность выбранного способа получения/обработки наблюдений найденной области цены, полнота префикса и названные условия исполнения. Это уже не задача получить ещё одну общую теорему или повторить ε-сетку.

Узкое место обусловлено выбранным обслуживанием: около250 тыс. cut/ready и5,1 млн потенциальных gate в секунду. Даже один16-нс доступ к защищаемой SRAM на каждый cut занимает около4000мкс/с при остатке всего5,88мкс/с. Значит такой способ обработки не подтверждает20%; наличие cut само по себе не требует обращения к этой SRAM. Локальная память/логика могут иначе распределять затраты, но их CPU/энергетическая цена не равна нулю и имеющаяся архитектура должна это обосновывать.

**Решение до30.10:** один совместный итог #186/#196 по уже принятой архитектуре и доступным материалам: какие затраты обработки и условия наблюдения обоснованы, какие остаются параметрами, входит ли их совместная область в20%-условие. Не требовать новой аппаратуры, измерений WCET или транспорта. Если для полноценного примера нужны такие новые работы, сохранить условную гарантию и найденную область полезности, рекомендовать завершение А в этом объёме без продления. Не объявлять это доказательством бесполезности собственной обратной связи. Научный центр и календарь диссертации от результата этой ветви не зависят.
