# Уточнение цены счёта без уменьшения δ_C

27.10.2026, #196, PR283. **При произвольном C/invalid основная работа
принятого правила остаётся ограничена двумя календарями.**
[Доказательство C1–C5](../../../../theory/t196-count-error-price-20261027.md),
[обе таблицы](TABLE.md), [график](cost-bounds.svg), [точные дроби](result.json).

На правильном исполнении значение счётчика выбирает один календарь
клетки; поздний результат не запускает второй. Поэтому основных чтений
не больше M_b даже при скрытой ошибке счёта и после ошибки памяти.
Полная E-цена этой работы оплачивается δ_C M_b, а нарушение исполнения —
по-прежнему δ₀ N_h. Квота δ_C=5e−5 не уменьшалась; Q(T), все периоды,
история и статистические бюджеты PR281 сохранены.

F — весь постоянный класс, S — весь детерминированный класс расписаний.
Их необходимые цены не являются найденными оптимумами.
Отрицательные остатки означают отказ данного достаточного сравнения,
не запрет адаптации. Для30% остатки отрицательны во всех обязательных точках.

При .01 два20%-сравнения дают одну и ту же достаточную область:
все дополнительные расходы должны одновременно удовлетворять

- шина: 0.000267960735 z +(105.00104 нс/T)G +c_bus ≤5.875573·10⁻⁶;
- core: 0.000378460018 z +(124.50124 нс/T)G +c_core ≤15.481007·10⁻⁶.

Слева коэффициенты округлены вверх, справа остатки вниз.
G — ожидаемое число дополнительных чтений на хорошем исполнении,
**включая неверный C и A**; они оплачены полным E. z — дополнительная
непригодность групп; c — вся ещё неучтённая обработка в данной координате.
Ни один параметр не объявлен нулём. CPU, энергия, память и пиковые сроки
требуют собственных коэффициентов; это не измеренный аппаратный выигрыш.

**Граница применимости.** Если ошибка агрегатора способна испортить эпоху,
таймер или добавить основной проход вне прежнего договора исполнения,
этот путь не покрыт дешёвым членом. C4 сохраняет
(C_h−C_b)δ_escape; при δ_escape=δ_C получается прежняя цена.
Для математического правила δ_escape=0 следует из однократного выбора.
Для реализации нужен адресный переход #186, а не переименование нарушения.
Контрпример в проверке: объединение двух календарей .01 даёт94 прохода
вместо допустимых61.
