## Обязательная работа и дополнительные действия

SOURCE: принятый `theory/hybrid-p-r-20261026.md` §6 не переносит старые
hold-таймеры автоматически. Новый клеточный кандидат — новое правило
при прежнем сервисе, а не запуск старого T119 с прежней FAST-маской.
PR275 с сохранённым guard остаётся неизменным.

| Работа | Основание | Проверка / последствие нарушения |
|---|---|---|
| Startup, первый двухблочный интервал/проход каждой клетки | План PR281 | Нельзя снять его, сохранив новое основание остатка |
| Выбранный по прошлому календарь клетки, база при invalid/late | План PR281 | Основные посещения не отменяются после guard, A или обычной потери |
| Pending, completion, release, health и закрытый source/processed prefix | SERVICE, PR272 | Без покрытия invalid либо отдельное служебное исключение; не C=0 |
| Дополнительный E на использованном окне | Принятая локальная конструкция C | Invalid соответствующего наблюдения; E и обработка оплачиваются |
| Legacy hold90/180/NR | Прежний T119, не автоматическая обязанность PR281 | При сохранении явно назвать таймеры и срок expiry; цена включается |
| Raw/cause сообщения, cuts, счётчики, таймеры | Существующий интерфейс | Ненулевая работа, неизвестные CPU/шина/энергия остаются коэффициентами |
| Плохая история и работа после A | Общий договор цены | All-history caps и принудительный release нужны независимо от Q |

Нужные обязательные операции образуют `N_main`. Дополнительные guard-
чтения `G_good` — **объединение** причин loss/false/restore/hold/veto,
не сумма повторно посчитанных совпадений. Прежние квоты не задают
положительный нижний G и не доказывают G=0.

```
S <= min(N_h, E[N_main,good] + E[G_good] + (delta0+delta_C)*N_h)
H <= min(S, 2*F_parent + U_joint*N_h)
C_bus <= (48.50048*S + 56.50056*H)/(T*1e9) + u_A
C_core <= (68.50068*S + 56.00056*H)/(T*1e9) + v_A
N_h = 1610097765253120
```

`delta0=6e-6`; δ_C — прежнее **требование**, не измеренное число.
Нижние цены одного чтения — 47.49952/67.49932ns. Один родитель при weak E
может оплатить два repair. Bad-history term не является новой тратой ε.
Приложение/init показываются отдельно; неизвестные u_A/v_A, CPU/энергия,
idle и пиковая занятость не обращаются в ноль.

## Квоты и область уведомлений

Сохраняются false mean≤1e-6/s, total outage≤31557.6s,
episodes≤1001, restores≤1000. Если клеточный контракт требует только
invalid→база, стоимость базы уже входит N_main; действия интерфейса
и потерянная информативность остаются. Сам факт потери не предписывает
старую длинную FAST-полосу, но выбранное исполнение обязано описать guard.

Если оставлен прежний hold-контроллер, требуется назначить h/w/τ/NR,
expiry/fresh и применимость `hold-price(3)/(4)`. Тогда sufficient upper
добавляет B_ERR+B_R+B_O+S_v*v*T; это не обязательный низ нового правила.
При отсутствии такого договора остаётся полный hard cap и параметр G.

Прежний `v` — частота дополнительных raw source/veto notifications;
ordinary ERR не начисляются в него повторно:

```
0 <= v <= 1e9/(4*xi_minus) + 2/T ~= 250002500.025 /s.
```

Квота episodes/restores не ограничивает v. Он влияет на обработку,
guard и invalid предыдущих шести клеток. Положительную экономию при
ограниченном v/G/неизвестной цене нужно обозначать условием с численным
порогом, а не утверждением для всей области канала.
