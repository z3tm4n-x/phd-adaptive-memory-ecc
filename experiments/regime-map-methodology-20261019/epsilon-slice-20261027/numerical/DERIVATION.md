# Перенос формул, один кандидат серии и цена

27.10.2026, инженерный вывод для согласования #196. SOURCE — принятые
hybrid-p-r(9)–(14), A1–A11, PR272 и SERVICE; отдельные следствия ниже
не получают самостоятельной научной приёмки. Все исходники закреплены
в manifest.json. Входы input-1e-{1,2,3,4}.json отличаются только ε.

## Почему формулы применяются к разным ε

У S₂=∫p²+(2p_max+R)F_r, физического возраста метки, экспозиции A5,
пикового хвоста BP_obs и допустимости семейства подъёмов нет параметра ε.
Меняются только проверяемые неравенства и выделенные бюджеты.
Для постоянного кандидата проверяется δ₀+hS₂/W≤ε при каждом k.
Для серии — Q_b+δ₀+δ_C+Σα_j+Σζ_j+Σβ_j≤ε и b_j≤β_j.
Статистический тест использует точные направленные exp/ln, а не старые
константы .63/9.22. ΣC не объявляется Poisson; p из C не вычитается.
Масса F_r ограничивает интенсивность, не число реализованных родителей.

В нижней лемме отдельно пересчитывается Hε=−log(1−ε−δ_exec).
Для .1 это больше .105, поэтому подстановка H≈ε не используется.
Верх через union/факториальный момент является неравенством при .1,
а не приближением малой вероятности. Во всех строках проверены
0<ε+δ_exec<1, L>0, D<T, положительность корня/цен и тот же свидетель r_τ.
OFF исключён положительным необходимым числом посещений всего класса,
не отказом какого-либо достаточного теста.

## Соперники и границы оптимумов

Постоянный кандидат: startup, затем полные проходы через k·Wg ticks,
фазы batch8 прежние. Ненужный статистический drain/канал ему не назначен.
В A6 достаточно h=((k+1)Wgξ⁺+2J)/1e9; это консервативный полный возраст
с учётом предыдущей апертуры и остатка. Максимальный k найден по A7–A8,
следующий целый не проходит **этот сертификат**, не доказано недопустим.
Полный ε после δ₀ доступен сопернику; α/ζ/δ_C ему не начисляются.

Нижняя цена расписаний буквально пересчитана по принятому PR272:
x_* — корень f(x)=[L−d_Ex]_+²/(x+1)=Hε/(κW),
N_E≥Wx_*(T−D)/(L+d_E); затем два краевых вычета и множитель1−δ_exec.
Ни периодичность, ни сетка адаптации этому классу не навязываются.

Дополнительное следствие для постоянного класса: на плато после startup
каждое слово имеет не больше L/P+2 апертур при любой фазе. Поэтому из
необходимого x_* следует P≤L/(x_*−2), если x_*>2. При ξ⁺ и нулевом
джиттере это необходимый верх периода; для цены сохранён запас J.
Низ ожидаемых чтений ≥(1−δ₀)W[T/(P_limit+J)−2]_+.
Берётся максимум этого и общего календарного низа. Начало плато R/g
проверено позже startup, старый недопустимый B-свидетель PR250 не используется.
Это локальное следствие направлено #196, не утверждение об оптимальном k.

Для сильного расписания представлен интервал оптимума [L_S,U_F]:
необходимый низ всего класса и достаточный верх его постоянного члена.
Непостоянный минимизатор по p не найден. Это честная граница сильного
класса, а не его ограничение постоянными/порогами гибрида. Поиск более
сильного непостоянного кандидата остаётся отдельным конкретным остатком.
Строки оконного PR260/261 в эту панель не переносились.

## Повторяемое причинное семейство

Настройка зарегистрирована в SETTINGS.md до вычисления. Для каждого ε
один раз выбираются k_b,M,q,N,k_e,η,u,K,C_max и все α/ζ/β.
M=ceil(R/(g a_b⁻)) даёт примерно5379с обучения одной попытки.
N выбирается только как параметр решения из конечной доказанной области,
максимизируя **потенциальное** число снятых проходов, не прогноз успеха.
Значения p,R,g,F_r и цена операций при этом не меняются.

Epoch j занимает M k_b+k_e блоков на любой ветви. На валидной своевременной
истории при C≤C_max действует одно удлинение; иначе этот интервал заполняет
база. Все эпохи кратны k_b, поэтому после них сохранена исходная фаза.
Затем база идёт до T. N, α_j, ζ_j и β_j назначены до наблюдений;
invalid и позднее решение не возвращают квоты. Новый тест получает лишь
свой заранее оплаченный индекс. После E остаются новые ошибки; clean
возникает только в условном начальном состоянии, не после restore.

**Переход относительного времени, на подтверждение #196.** Начала эпох
заранее заданы в общей шкале ticks и одинаковы при success/fallback.
Для каждого фиксированного допустимого clock и r их физическое начало σ
фиксировано; A4–A5 применяются к [σ+Ma⁻,σ+Ma⁺]. В разностях времён σ
сокращается. Численный тест использует p≥b и эти разности, поэтому ему
не требуется новый датчик точного физического σ или сброс ошибки часов.
Все последующие начала/апертуры и префиксы должны оставаться предсказуемыми.
Это явный перенос общего A1–A5, не удаление assert старого checker.

Полнота использованного C/закрытого префикса, health, собственная epoch,
отсутствие дополнительных E на использованном окне, завершённый основной
проход и pending=false — прежние условия. Loss до решения оставляет
липкий invalid. Срок финального gate/install не доказывается длиной
обучения; после fresh последнего основного E прежний запас1270.8848нс
имеет смысл только без более позднего guard-E. WCET неизвестен.
δ_C≤5e-5 — единое lifetime-требование для **всей серии**, не на каждую
попытку и не измеренная вероятность. Прежняя δ₀=6e-6 не уменьшена.

## Цена до T, включая плохие истории

Число начатых чтений определяется аналитически по8 фазам; физические
границы используют ξ/J. Startup и последний неполный проход оплачены.
После скрытого A счёт и плановая работа продолжаются. App/init отделены.

Для постоянного класса all-history cap есть число его назначенных стартов,
а не поток адаптивных guard. Это прежний договор cost_result(...adaptive=False)
из PR250/common comparison.py: Hard=support.upper. Тогда

```
N_F = N_fixed_upper
H_F ≤ min(N_F, 2F_parent + U_F*N_F)
C_F,bus ≤ (48.50048 N_F + 56.50056 H_F)/(T*1e9) + u_F
C_F,core ≤ (68.50068 N_F + 56.00056 H_F)/(T*1e9) + v_F.
```

Один родитель может дать два repair при weak E. На плохих историях
оплачен полный поток данного режима, а не остановка. Если физический
исполнитель способен выходить за назначенные старты, приведённый договор
не выполнен; дополнительный консервативный член δ₀ N_h для этой возможности
явно указан в JSON. Не присваиваем такую возможность или её отсутствие
по результатам Python-тестов.

Для адаптации N_h=1610097765253120 — прежний cap всех потенциальных слотов.
Пусть Z — число успешных попыток на good execution (0≤Z≤N), G — число
добавочных guard-чтений на good execution. Для каждого фиксированного
допустимого r/канала без усреднения по средам:

```
S ≤ min(N_h, N_base⁺ − W(m−1) E[Z] + E[G] + (δ₀+δ_C)N_h)
H ≤ min(S, 2F_parent + U_joint N_h)
C_A,bus ≤ (48.50048 S + 56.50056 H)/(T*1e9) + u_A
C_A,core ≤ (68.50068 S + 56.00056 H)/(T*1e9) + v_A.
```

G включает loss/false/restore/удержания/veto/другие проверки без двойного
счёта совпавших причин. G=0 на графике — только обозначенная компонента
формулы; общий hard cap рядом, физический ноль не назначен.
Ни один исход не останавливает оплату. До bad history один родитель
оплачивает≤2 repair; после него используется hard-поток. F_parent=bT+F_s
является верхом среднего числа родителей, не их реализованной квотой.

Необходимая цена **этого семейства** получается даже при успехе всех N
попыток и нулевой дополнительной работе: снять можно не больше
D=NW(m−1) основных чтений. Следовательно
L_A=(1−δ₀−δ_C)[N_base⁻−D−2]_+ R⁻/T.
Это низ среднего по каждому фиксированному r/каналу при сохранении
обязательных посещений на good execution; не средняя цена выбранной
спокойной траектории и не нижняя цена всех адаптивных правил.

## Два сравнения и неизвестные добавки

Для постоянного и календарного оптимума отдельно известны
L_F≤C_F*≤U_F и L_S≤C_S*≤U_F (общий допустимый член).
Доказанная положительная экономия потребовала бы U_A<.8L_F или .8L_S
для20%, соответственно .7 для30%. Эти неравенства не получены.

С другой стороны, при u_A≥0 и заданной добавке u_F:
s_A/F*≤1−L_A/(U_F+u_F), s_A/S*≤1−L_A/(U_F+u_F).
Одинаковый потолок здесь имеет две отдельные причины: допустимый
постоянный кандидат принадлежит обоим классам. Это не равенство оптимумов.
Условия на u_F, достаточные для отсутствия преимущества данного семейства,
и необходимые для возможности20% сохранены в JSON. По CPU/энергии
без единичных цен такие численные отношения не определяются.

Полный вектор не заканчивается на SRAM: N(M−q) закрытий C/добавлений,
N оплаченных запросов, cuts/ready и raw/cause handlers за весь T,
calendar gates/timers, app/init. Нет online exp/ln/inversion, пороги
подготовлены до запуска. CPU=ΣE[N_i]c_i/(T·1e9)+idle_CPU;
energy=ΣE[N_i]e_i+T·idle_W. c_i,e_i,idle,stack/code/LUT/BRAM,
u_A/u_F/v_A/v_F и дополнительные veto — UNKNOWN, не нули.
Прежние transport/loss131136bytes и32bytes/record сохраняются.
