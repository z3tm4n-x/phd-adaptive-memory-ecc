# Сколько раз меняется период обхода за десятилетие SEPEM

## Условия до подстановки

Пункт 1 [№547](https://github.com/z3tm4n-x/phd-adaptive-memory-ecc/issues/547), база `23648c549b02a544f0e352729ba5edb2951891ef`. Берём одну принятую строку SEPEM 16.12.1996–16.12.2006 для проектных 256 КиБ, пары адресов $(w,w+65\,536)$, восемь периодов от $L=45{,}8752$ мс до $128L$, штатные отчёты и регистровое управление при $I=X=0$. Смесь выбирает одно слово с вероятностью 4/5 и два соседних с вероятностью 1/5. Общий допуск на накопление за десять лет равен 0,001. Соперник — принятый постоянный кандидат 86,429 мс для того же полного класса ГСО. [Архивный договор №535](../t534-archive-comparison/PROTOCOL.md) · [Классовые границы №528](../t525-two-phases/result.json).

Сменой считаем установку команды с периодом, отличным от предыдущего, на интервале $[0,T)$. Назначение частой ступени при пуске учитываем отдельно. Повтор команды текущего уровня имеет нулевой вклад. Одно непосредственное снижение с редкой ступени до $L$ даёт одну смену независимо от расстояния между ступенями. Сверяем момент решения в [архивном исполнителе](../t186-volume-archive/replay.py) с [календарём установки](../t534-native256-fpga/rtl/scan_engine.sv). Проверяем правый край до использования счётчика возвратов. Для повышения берём действительные пороги и возможный незавершённый подъём к концу срока.

Заранее различаем границы на пути, границы среднего в 128 сохранённых реализациях, статистическую неопределённость этого среднего и аналитический верх по классу профилей. По опубликованным возвратам ограничиваем все смены сверху и снизу. Отдельно выписываем календарное время на $L$, секунды занятости защитного порта и пик с длительностью окна. Достаточные границы по исходной ведомости завершают эту проверку. [Архивная ведомость](../t534-archive-comparison/sepem-256.json).
