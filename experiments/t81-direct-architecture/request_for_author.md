Для каждой архитектуры требуется верх среднего числа родителей,
повреждающих ≥2 позиции хотя бы одного полного слова за 10 лет:
D*≤5·10⁻⁵; отдельно ≤10⁻⁴. В `outputs/handoff.json` это **целевые**
условные диапазоны; доказанная физическая верхняя граница — null.

Минимальные поля существующих run/segment: устройство/партия/режим,
питание/температура/доза, вид и энергия иона, LET **на чувствительном слое**,

на **полное** событие и отдельное покрытие q/F, не только число ноль.

## 2. Количественные требования

В прежней normal-as-isotropic области веса для защит 2,5/3:
C=29,4471268934 /23,5336096946 см⁻². Для D≤5e−5 нужна uniform upper
σ≤**1,69795852·10⁻⁶ /2,12461990·10⁻⁶ см²/массив**; для 1e−4 вдвое больше.
Это условные требуемые границы, не измеренная оценка check/ECC-on.
Защита 3 снижает этот расчётный интегральный отклик относительно 2,5.

Новый независимый заранее заданный нулевой **whole-array** опыт при LET≥57,
если он действительно ограничивает всю эту область: на point95 и θ_F=0,3
Fnew≥**2520448,812 /2014297,960 см⁻²** для 5e−5;
для 1e−4 — **1260224,406 /1007148,980 см⁻²**. Одинаковая арифметика двух
архитектур допустима только для соответствующего полного испытываемого
массива, не одного чипа, умноженного на три. Data32-экспозиция здесь
не засчитана. Выбор удобного нуля/остановка по данным требует отдельного
покрытия; 95% не квалифицирует Θ с миссионной ошибкой ≪10⁻³.

Это условный масштаб запроса, **не готовый флюенс реальной кампании**.
Недостающие коэффициенты для физического требования:

1. C_(ρ,j): совместно покрытый флюенс за 10 лет после обеих защит по
   LET/углам/азимутам либо эквивалентные обоснованные веса. Из одного
   скалярного LET-экспорта их восстановить нельзя.
2. Область Ω: для сопоставления со скалярным маршрутом 0≤ϑ≤60°,
   **все азимуты** относительно рядов/столбцов. Нужно основание отсечения
   60° либо верх остатка 60–90° и обратной стороны/других направлений,
   если они достигают чувствительной области. Опубликованные суммарные
   SEU при 45/60° не дают SMU-меток. Если имеются event-логи именно этих
   измерений, нужны они с азимутами и экспозициями, не новая широкая
   литературная кампания.
3. Для LET≥57: область ионов/пробега, верх **между** угловыми/азимутными
   точками и выше максимального LET опыта. Монотонность переносит верх
   вниз, но не доказывает плато вверх. Без оболочек даже бесконечный
   флюенс в одной точке не подтверждает весь интеграл.
4. R: верх непокрытых вкладов — L<27, GCR>126, SEP за 32,6, прочие
   частицы/энергии, углы и скрытые/пропущенные метки вне определения
   теста. Это не нули. Достаточно общего квалифицированного R,
   не обязательно новой детальной физической модели.
5. q_j, g_j, E_old,j: полнота, геометрическая нормировка площади,
   пригодная старая эффективная экспозиция; бюджеты b_j и α_j.

Точная формула в `METHOD.md` и `allocation_fluence`:

`Fnew,j ≥ [−lnα_j · C_(ρ,j)/b_j − E_old,j]_+ / [(1−θ_F,j) q_j g_j]`,
`Σb_j≤D₀−R`, `Σα_j≤α_Θ`.

При R≥D₀ увеличение только доступной экспозиции не закрывает этот
сертификат; при неизвестном R физический запрос F остаётся неизвестным.
`angular_requirements.csv` даёт коэффициенты иллюстративного деления
0–30/30–45/45–60° и двух архитектур: α_j=0,05/6, b_j=(D₀−R)/3.
При R=0, q=g=1, θ_F=0,3 коэффициент F/C_j равен 410356,4351 /205178,2176
для 5e−5/1e−4. Это **не утверждение**, что R=0, q=g=1, азимутная симметрия
или такая угловая сетка квалифицированы; верх требуется на весь страт.

## 3. Канал и обслуживание: только остаточные вопросы

Для #80/#82: actualW/aliases, полнота ERR для всех 38, задержки/пропуски,
повторное чтение (не новый родитель), эффект записи/fence, попадания
latch→write и подготовка без pending. Штатное исправление всего внутреннего
слова и отсутствие read-writeback известны; это не сертификат clean-U
в радиационном окне. Для внешнего 39 нужны совместный ERR/DQ и состояние
скрытой ECC. WCET/календарь закрывает #82; T81 новых времён не назначает.

## Два варианта для решения автора

1. Передать имеющиеся приборные/run данные или квалифицированный
   black-box full-word upper с областью/совместным покрытием. Подставить
   их в готовые формулы; нужный функционал иногда можно закрыть без
   восстановления всей топологии. Новые испытания, если понадобятся,
   требуют отдельного решения автора, не запускаются в T81.
2. До появления оснований сохранить обе архитектуры как условные
   кандидаты. #80/#82 проверяют D* параметрически при ≤5e−5/≤1e−4
   и показывают зависимость от большего D*. Это поддерживает построение
   метода, не объявляя заданную Θ физически подтверждённой.

Рекомендация: сначала запросить остаточные full-word/угловые основания;
не выбирать архитектуру по одному нулю data32 и не наращивать экспозицию
для нуля, полученного при неполной регистрации.
